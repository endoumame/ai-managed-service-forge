# 新機能パッケージ製品アイデア レポート
日時: 2026-04-01
ターゲットドメイン: 経理・請求書処理

## 選定アイデア: InvoiceForge

### エレベーターピッチ
InvoiceForgeは、受領した請求書をAIが読み取り、ハーネスが品質を保証し、決定論的コードが正確に仕訳する「請求書処理の完成品」を提供するAIマネージドサービスである。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は「受領→抽出→照合→仕訳→承認」という明確なライフサイクルを持ち、ハーネスによる各ステージの品質ゲートが最も自然に設計できるドメインである。AIが「抽出完了」と自己申告しても、貸借不一致や金額異常をハーネスが検出して差し戻す構造は、ドリフト問題への直接的な解決策を体現している。また、ユーザーの仕訳修正がそのまま学習データとなるため、自己改善ループが極めて自然に実現できる。コモディティ性も最高レベルで、全企業に共通する業務でありながら競争優位に直結しないため、マネージドサービスとしての経済合理性が高い。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before/afterの各ステージ）による品質ゲートが機能し、信頼度スコア閾値チェック・貸借一致検証・金額異常検知が自動実行されること
- 終了条件の外部管理により、AIの自己申告に依存しないパイプライン制御が実現できること
- ナレッジストアへの修正履歴蓄積→改善提案生成→人間承認のループが動作すること
- 3件の請求書（通常/複数明細/高額）に対して仕訳が正確に生成され、貸借が一致すること
- 高額請求書に対してヒューマン・イン・ザ・ループが発動すること

### プロトタイプの起動方法
```bash
cd prototype
pnpm install
npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude APIとの実統合: モックエージェントを実際のClaude API呼び出しに置き換え、OCR結果やPDFからの非定型請求書解析を実現する
2. 永続化層の構築: インメモリストアをデータベース（Cloudflare D1等）に移行し、ナレッジの蓄積と改善提案の履歴管理を実運用レベルにする
3. Webダッシュボード構築: Vue.jsフロントエンドで、請求書一覧・仕訳結果・レビューキュー・ナレッジ管理画面を提供する

### 学んだこと / 気づき
- ハーネス層のライフサイクルフックは「AIを信頼しない」設計の核心であり、プロトタイプレベルでも品質保証の効果が明確に見える
- 決定論的コード（税計算・貸借バランス）とAI推論（勘定科目推定）の責務分離は、コード設計としても非常にクリーンになる
- ナレッジ改善ループは、初期データが少なくても修正回数の閾値（3回）で提案が生成されるため、導入初期から価値を発揮できる設計にできた
- 厳格なリンタールール環境下でもクリーンなコードを維持するには、関数のstatement数制限（10）への意識的な分割設計が必要
