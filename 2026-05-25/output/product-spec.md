# InvoiceForge 設計書

## エレベーターピッチ
請求書を投入するだけで会計ソフトにインポート可能な仕訳データが出力される、AI マネージドサービス型の請求書の自動仕訳システム。

## ターゲットユーザー
- ペインポイント — 毎月大量の請求書を手作業で仕訳入力しており、月末の経理業務が逼迫。入力ミスによる修正コストも大きい。
- 現在の解決方法 — 経理担当者が 1 枚ずつ請求書を確認し、会計ソフトに手入力。または Excel 管理からの転記。
- 提供する価値 — 請求書投入→自動仕訳→人間承認→記帳完了のワンストップ処理。仕訳作業時間 80%削減、入力ミスゼロ。

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック
  - `before:extract` — 請求書テキストの前処理（正規化、ノイズ除去）
  - `after:extract` — 抽出結果の完全性チェック（必須項目の欠損検知）
  - `before:classify` — 勘定科目候補の事前フィルタ（ナレッジベースから過去パターン取得）
  - `after:classify` — 仕訳結果の妥当性検証（金額突合、勘定科目バリデーション）
- 終了条件管理
  - チェックリスト形式で以下を外部管理:
    1. 全必須項目が抽出されたか
    2. 金額の整合性（小計＋税＝合計）が確認されたか
    3. 勘定科目がナレッジベースまたは標準科目に存在するか
    4. 仕訳の貸借が一致するか
- 品質チェック機構
  - 税額の決定論的な再計算
  - 過去の同一取引先との金額乖離チェック（異常値検知）
  - 勘定科目の出現頻度に基づく信頼度スコア
- サブエージェント構成
  - ExtractorAgent: 請求書からの項目抽出
  - ClassifierAgent: 勘定科目の分類提案

### AIエージェント層
- 担当タスク（推論アップサイドが大きい部分）
  - 非定型請求書からの項目抽出（取引先名、品目、金額、日付、適格番号）
  - 品目内容に基づく勘定科目の推定
  - 曖昧な記載の解釈（「一式」「他」等の補完）
- 使用するツール/API
  - Anthropic Claude API（テキスト理解・分類）
  - ナレッジストア検索（過去パターン参照）
- ヒューマン・イン・ザ・ループのトリガー条件
  - 勘定科目の信頼度スコアが閾値（80%）未満
  - 過去に見たことのない取引先
  - 金額が過去平均から 2σ以上乖離
  - 必須項目の抽出に失敗

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）
  - 消費税額計算（税率 10%/8%、端数処理）
  - 仕訳フォーマット変換（勘定科目コード→会計ソフト形式）
  - 金額の整合性チェック（小計＋税＝合計）
  - 仕訳の貸借バランス検証
  - 重複した請求書の検知（請求書番号＋日付＋金額の一致）
  - 適格請求書における発行事業者の番号のフォーマット検証

### ナレッジ自動改善ループ
1. **インプット（ユーザー行動/フィードバック）**: 人間が承認した仕訳データ（特に AI 提案を修正した場合の修正内容）
2. **矛盾検知メカニズム**: 同一取引先に対して異なる勘定科目が割り当てられた場合に矛盾を検知し、改善提案を生成
3. **承認フロー**: 改善提案を人間に提示し、承認された場合のみナレッジベースを更新
4. **反映タイミング**: 承認直後にナレッジベースを更新し、次回の同一の取引先の処理から即座に反映

## MVP（プロトタイプ）スコープ
実装する機能（3 つ以内に絞ること）は以下の通りです。
1. **請求書テキストからの項目抽出**: テキスト形式の請求書から取引先名・品目・金額・日付を抽出
2. **自動仕訳生成と検証**: 抽出データから仕訳を生成し、決定論的チェック（金額突合・貸借バランス）で検証
3. **ナレッジベースの学習と改善提案**: 処理結果の蓄積と、矛盾検知時の改善提案

実装しない機能（将来版）は以下の通りです。
- OCR/画像認識（テキスト入力のみ対応）
- 会計ソフトとの API 連携
- 複数通貨対応
- Web ダッシュボード（CLI のみ）
- バッチ処理（1 件ずつの対話的処理）
- 適格な請求書番号の国税庁 API 照合
