# 新機能パッケージ製品アイデア レポート
日時: 2026-05-25
ターゲットドメイン — 経理・請求書処理。

## 選定アイデア: InvoiceForge — 請求書の自動仕訳マネージドサービス

### エレベーターピッチ
請求書を投入するだけで会計ソフトにインポート可能な仕訳データが出力される、AI マネージドサービス型の請求書の自動仕訳システム。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
InvoiceForge は、AI マネージドサービスの「三位一体アーキテクチャ」が最も自然に活きるユースケースです。請求書からの項目抽出は AI の推論アップサイドが大きく（非定型フォーマットへの対応）、一方で税額計算や金額突合は決定論的コードで確実に処理すべき領域であり、この分離が明確です。ハーネスは「AI の読み取った金額が本当に正しいか」を決定論的に検証する品質チェック機構として不可欠であり、ハーネスなしでは AI のドリフト（誤読の累積）を検知できません。さらに、処理するたびに「取引先→勘定科目」のマッピングが蓄積され、ナレッジの自動改善ループが自然に形成される点も、マネージドサービスとしての持続的な価値向上に直結します。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before/after extract, before/after classify）による段階的な品質チェックが機能すること
- 終了条件チェックリスト（4 項目）による外部管理で、AI の「自己完了宣言」を防止できること
- ナレッジの自動学習（1 件目で記録した「クラウドネット→通信費」が 3 件目で自動適用され、信頼度 85%→95%に向上）
- 決定論的コードによる税額再計算・貸借バランスチェックが仕訳の正確性を保証すること
- ヒューマン・イン・ザ・ループの接点（信頼度 80%未満でエスカレーション）が設計通りに動作すること

### プロトタイプの起動方法
```bash
cd 2026-05-25/prototype
npm install
# モックモード（AI APIなし）
npm run demo:no-ai
# Claude API使用
export ANTHROPIC_API_KEY="your-api-key"
npm run demo
```

### 次のステップ（マネージドサービス化に向けて）
1. OCR/画像認識の統合（PDF・画像形式の請求書に対応し、テキスト入力の前段として OCR パイプラインを構築）
2. 会計ソフト API 連携（freee/マネーフォワード/弥生への仕訳データ直接インポート機能の実装）
3. Web ダッシュボード開発（ヒューマン・イン・ザ・ループの承認 UI、ナレッジ改善提案の管理画面、処理履歴の可視化）

### 学んだこと / 気づき
- ハーネスの「Before/After フック」パターンは、AI の出力を決定論的に検証する仕組みとして非常に有効。特に金額系のバリデーションは「AI に任せてはいけない」典型例
- ナレッジの自動改善ループは、わずか 3 件の処理でも効果を実感できた。マネージドサービスとして多数の顧客を束ねることで、ネットワーク効果による精度向上が期待できる
- 終了条件の外部管理（チェックリスト形式）は、ドリフト対策として必須。AI が「完了」と言っても、4 項目すべてがクリアされるまでハーネスが処理を完了させない設計が重要
- フォーマッターとリンターの厳格なルール（no-magic-numbers, require-await, max-statements 等）は、プロダクションコードの品質を高める。一方、プロトタイプの迅速な開発との間にトレードオフがある
