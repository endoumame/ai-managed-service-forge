# アイデア発散: 経理・請求書処理ドメイン

日時: 2026-04-09。

---

## アイデア 1: InvoicePilot -- 請求書受領から仕訳起票までの完全自動化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
受領した請求書（PDF/画像/メール添付）を投入するだけで、会計ソフトにインポート可能な仕訳データが出てくること。経理担当者は「確認・承認」だけで月次処理が完了する状態。

### ハーネス設計のキモ
- ライフサイクルフック: 項目抽出後に必ず「金額整合性チェック」を実行（合計 = 明細合計 + 税額）
- 終了条件: 全必須項目（取引先名、日付、金額、税額、明細）の抽出完了 + 仕訳科目の確定 + 金額整合性 OK
- 品質チェック: 抽出結果と原本画像の突合表示によるヒューマンレビュー画面

### AIが担う部分（推論のアップサイドが大きく、ミスのダウンサイドが小さい部分）
- 請求書からの項目抽出（取引先名、日付、金額、明細テキスト）
- 取引先名の名寄せ（表記揺れの吸収:「株式会社 ABC」「(株)ABC」「ABC Corp.」）
- 勘定科目の推定（過去の仕訳パターンからの推論）

### 決定論的コードが担う部分
- 消費税額の計算・検証（税率テーブルに基づく確定的計算）
- 仕訳フォーマットの生成（会計ソフト別の CSV/API 形式変換）
- 金額整合性チェック（合計金額 = Σ明細金額 + 消費税額）
- 重複請求書の検知（請求書番号 + 取引先 + 金額の完全一致チェック）

### ナレッジ/データの自動改善ループ
- ユーザーが修正した勘定科目を記憶し、同一取引先・同一内容の次回推定に反映
- 新規取引先のフォーマットパターンを蓄積し、2 回目以降の抽出精度を向上
- 承認済み仕訳の蓄積により、季節性パターン（年次費用、四半期契約等）を学習

### 内製との差別化ポイント
- OCR + NLU + 仕訳推定のパイプラインを自社で構築・運用するコストは高い（モデル更新追従含む）
- 請求書フォーマットは取引先ごとに異なり、パターン数が膨大。マネージドサービスは複数顧客のパターンを集約できる
- 税制改正（インボイス制度等）への対応を一元的に反映できる

## アイデア 2: PayWatch -- 支払期日管理と資金繰り予測サービス

### ユーザーが本当に欲しいもの（業務の完成品）
請求書の支払期日を自動管理し、「今月の支払予定」「来月の資金不足リスク」がダッシュボード上で一目瞭然となること。支払漏れゼロと資金ショート回避が同時に達成される状態。

### ハーネス設計のキモ
- ライフサイクルフック: 支払の期日抽出後に「カレンダー登録」と「資金繰り再計算」を自動実行
- 終了条件: 全請求書の支払期日の登録完了 + 資金繰り表の更新完了 + アラート設定完了
- 品質チェック: 支払期日の妥当性検証（過去の支払サイクルとの整合性チェック）

### AIが担う部分
- 請求書本文からの支払条件の読み取り（「月末締め翌月末払い」等の自然言語解釈）
- 異常な支払条件の検知（通常と異なる条件の警告）
- 資金繰りの傾向分析とリスクコメント生成

### 決定論的コードが担う部分
- 支払期日の計算（営業日カレンダーに基づく確定計算）
- 資金繰り表の更新（入金予定 - 出金予定の確定的計算）
- アラート判定（残高が閾値を下回る日の特定）

### ナレッジ/データの自動改善ループ
- 取引先ごとの支払条件パターンを蓄積（初回抽出 → 承認 → 次回自動適用）
- 実績データから季節性パターンを学習（賞与月、決算月の支出増加等）
- 支払遅延の発生パターンを記録し、リスク予測の精度を向上

### 内製との差別化ポイント
- 支払条件の自然言語解釈は多様なパターンがあり、ルールベースでは対応困難
- 資金繰り予測の精度は学習データ量に依存し、マネージドサービスは匿名化された業界データで精度向上可能
- 営業日カレンダーや税制の変更を一元管理できる

## アイデア 3: MatchKeeper -- 請求書と発注書の自動照合サービス

### ユーザーが本当に欲しいもの（業務の完成品）
受領した請求書が、事前に承認した発注書（PO）と一致しているかを自動で照合し、差異がある場合だけ人間に判断を求めること。「照合 OK」の請求書は自動で支払処理に回せる状態。

### ハーネス設計のキモ
- ライフサイクルフック: 照合実行後に「差異レポート生成」→「承認フロー起動」を連鎖実行
- 終了条件: 全請求書の照合完了（完全一致/差異あり/発注書なしの 3 分類が確定）
- 品質チェック: 差異の種類と金額を可視化し、閾値超過時は自動エスカレーション

### AIが担う部分
- 請求書と発注書の明細テキストのマッチング（品名の表記揺れ吸収）
- 部分納品・分割請求の対応関係の推定
- 差異の原因推定（単価変更、数量変更、追加作業等のカテゴリ分類）

### 決定論的コードが担う部分
- 金額の完全一致判定（数値比較）
- 許容差異の閾値判定（±X%以内なら自動承認等）
- 照合結果のステータス管理（完全一致/差異あり/未照合）
- 発注残の計算（発注金額 - 既請求金額）

### ナレッジ/データの自動改善ループ
- 承認された差異パターンを蓄積（「この取引先は毎回送料を別請求する」等）
- 品名の表記揺れマッピングを学習（「コンサル費」=「コンサルティング料」等）
- 差異解決の判断基準を蓄積し、自動承認の精度を向上

### 内製との差別化ポイント
- 明細テキストのファジーマッチングは取引先ごとの慣習に依存し、ルールの網羅が困難
- 複数顧客の照合パターンを集約することで、業界共通の表記揺れ辞書を構築可能
- 分割請求や部分納品の対応は複雑で、内製では対応コストが高い

## アイデア 4: TaxGuard -- インボイス制度対応の適格請求書の検証サービス

### ユーザーが本当に欲しいもの（業務の完成品）
受領した請求書がインボイス制度（適格請求書等の保存方式）の要件を満たしているかを自動判定し、不備がある場合は取引先への差し戻し文面まで生成されること。税務調査で指摘されるリスクがゼロになる状態。

### ハーネス設計のキモ
- ライフサイクルフック: 検証実行後に「不備項目リスト生成」→「差し戻しメール文面生成」を連鎖
- 終了条件: 全請求書の検証完了（適格/不備あり/免税事業者の分類確定）
- 品質チェック: 登録番号の国税庁 DB との照合（外部 API 検証）

### AIが担う部分
- 請求書面からの登録番号・税率区分の抽出
- 不備内容に応じた差し戻しメール文面の生成（丁寧かつ正確な日本語）
- 経過措置（80%控除→50%控除）の適用判断支援

### 決定論的コードが担う部分
- 適格請求書の必須記載事項チェック（登録番号、税率ごとの区分記載、税額計算の端数処理方法）
- 登録番号の形式検証（T + 13 桁数字）
- 消費税額の再計算と照合（税率×課税標準額）
- 経過措置の控除率計算

### ナレッジ/データの自動改善ループ
- 取引先ごとの請求書品質スコアを蓄積（繰り返し不備がある取引先を可視化）
- 差し戻し後の修正パターンを学習（同じ不備の再発防止テンプレートを改善）
- 税制改正情報を自動取り込み、チェックルールを更新

### 内製との差別化ポイント
- インボイス制度は経過措置を含む複雑なルールがあり、内製ではメンテナンスコストが高い
- 税制改正への追従を一元的に行えるのはマネージドサービスの強み
- 国税庁 DB との照合 API の運用保守を個社で持つ必要がない

## アイデア 5: BookBot -- 経費精算から仕訳・月次レポートまでの統合処理サービス

### ユーザーが本当に欲しいもの（業務の完成品）
従業員が提出した領収書・経費申請を投入するだけで、承認フロー → 仕訳起票 → 月次経費レポート生成までが一気通貫で完了すること。経理担当者は月末に「確認ボタン」を押すだけで月次締めが終わる状態。

### ハーネス設計のキモ
- ライフサイクルフック: 経費申請受付 → 領収書 OCR → ポリシーチェック → 承認ルーティング → 仕訳生成 → レポート集計の各ステップにフックを配置
- 終了条件: 全申請の処理完了 + 仕訳の整合性確認 + 月次レポートの数値一致
- 品質チェック: 経費ポリシー違反の検知（上限超過、カテゴリ不適切等）、部門別集計の前月比の異常検知
- サブエージェント構成: OCR エージェント、ポリシーチェックエージェント、レポート生成エージェント

### AIが担う部分
- 領収書からの項目抽出（店名、日付、金額、品目）
- 経費カテゴリの自動分類（交通費、交際費、消耗品費等）
- 月次レポートのサマリーコメント生成（前月比の変動要因分析）
- 不正経費の異常検知（パターンから逸脱する申請の検出）

### 決定論的コードが担う部分
- 経費ポリシーの適用（上限金額、承認権限ルール）
- 仕訳の生成（勘定科目 × 部門 × プロジェクトのマッピング）
- 集計処理（部門別、カテゴリ別、プロジェクト別の確定的集計）
- レポートフォーマットの生成（Excel/PDF 出力）

### ナレッジ/データの自動改善ループ
- 承認/差し戻しパターンから経費ポリシーの暗黙ルールを学習
- 店名→カテゴリのマッピングを蓄積（「スターバックス」→「会議費」等）
- 部門ごとの経費傾向を学習し、異常検知の閾値を自動調整

### 内製との差別化ポイント
- OCR + カテゴリ分類 + 異常検知 + レポート生成の 4 つの AI 機能を個別に構築するコストは膨大
- 経費ポリシーは企業ごとに異なるが、基本構造は共通。テンプレート + カスタマイズで対応可能
- 月次処理の「締め」は時間的制約が厳しく、自動化の価値が特に高い
