# 新機能パッケージ製品アイデア レポート
日時: 2026-04-09
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoicePilot

### エレベーターピッチ
請求書を投入するだけで、AI が項目を抽出し、ハーネスが品質を保証し、決定論的コードが正確な仕訳データを生成する -- 経理担当者は「確認・承認」だけで月次処理が完了する AI マネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は全企業が行うコモディティ業務であり、内製する経済合理性が低い領域です。同時に、AI の抽出ミスが即座に会計上の問題になるため、ハーネスによる外部検証なしには成立しません。金額整合性チェック（合計 = 明細合計 + 税額）や終了条件の外部管理（5 項目のチェックリスト）など、ハーネスの価値を最も具体的に示せるドメインとして選定しました。また、取引先マスタや勘定科目推定の学習データが自然に蓄積されるため、ナレッジ自動改善ループの実装が直感的であることも重要な選定理由です。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（beforeExtract / afterExtract / afterClassify / afterJournalEntry）を実装した。各フェーズで AI の出力を検証し、品質基準を満たさない場合はパイプラインを停止する
- 終了条件の外部管理: 5 項目のチェックリスト（必須項目抽出、金額整合性、勘定科目確定、仕訳生成、借方貸方一致）をハーネスが評価し、AI の自己申告に依存しない完了判定
- ヒューマン・イン・ザ・ループ: 勘定科目の推定信頼度が 80%未満の場合、ユーザーへ確認を求め、その修正をナレッジに反映する改善ループ
- 決定論的コードによる金額検証: 消費税計算や借方・貸方の一致確認をルールベースで実行し、AI の推論に依存しない正確性を保証
- ナレッジの自動改善: 処理した取引先の勘定科目マッピングを蓄積し、次回の推定に反映する学習ループ

### プロトタイプの起動方法
```bash
cd 2026-04-09/prototype
pnpm install
pnpm demo
```

### 次のステップ（マネージドサービス化に向けて）
1. OCR 統合: PDF/画像からのテキスト抽出を AI エージェント層に追加し、実際の請求書画像を処理できるようにする
2. 会計ソフト連携: 仕訳データを弥生会計、freee、マネーフォワード等の API/CSV フォーマットでエクスポートする機能の実装
3. Web ダッシュボード: 請求書のアップロード、仕訳の承認、ナレッジの管理をブラウザから行える UI の構築

### 学んだこと / 気づき
- ハーネスの「AI を信頼せずに検証する」設計思想は、請求書処理のように金額の正確性が求められるドメインで特に強力である。金額整合性チェックは決定論的に実装でき、AI の抽出ミスを即座に検知できる
- ヒューマン・イン・ザ・ループの設計では「いつ人間に聞くか」の閾値設計が重要。信頼度 80%未満で確認を求める設計により、高信頼度の処理は自動化しつつ、不確実なケースは人間の判断を仰ぐバランスが実現できた
- ナレッジ改善ループには「承認されたデータのみ反映」というガードレールが必要である。AI による無制限の更新を許すと、誤った学習の蓄積につながるリスクを伴う
