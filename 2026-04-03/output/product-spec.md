# ReconcileBot 設計書

## エレベーターピッチ
銀行入金データと売掛金台帳を自動マッチングし、「消込済み・候補付き・要調査」の 3 段階に分類した状態で経理担当者に提示する、入金消込マネージドサービス。

## ターゲットユーザー
- ペルソナ — 中小企業（従業員 50〜500 名）の経理担当者・経理マネージャー
- ペインポイント
  - 毎月末に 1〜2 日かけて手作業で入金消込を実施している
  - 振込名義と取引先名が一致しない（略称・カナ揺れ）ケースの特定に時間がかかる
  - 合算入金（複数請求書を 1 回で振り込み）の分解が最も困難
  - 消込漏れが翌月以降に発覚し、手戻りが発生する
- 現在の解決方法
  - Excel で目視照合
  - 会計ソフトの簡易マッチング機能（完全一致のみ）
  - 経験豊富な担当者の記憶に依存
- 提供する価値
  - 月末の消込作業を数時間→数分に短縮
  - 消込漏れゼロ（全入金が必ず処理される保証）
  - 担当者の記憶に依存しない、組織としてのナレッジ蓄積

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック
  - `beforeMatch`: AI マッチング実行前に、金額完全一致の決定論的マッチングを先に実行（AI の負荷軽減＆確実性確保）
  - `afterMatch`: AI マッチング結果に対して二重マッチング検出・金額整合性チェックを実行
  - `beforeFinalize`: 全入金が処理済みか（確定/候補/要調査のいずれかに分類されているか）を検証
- 終了条件管理
  - [ ] 全入金データが処理済み（未分類の入金がゼロ）
  - [ ] 自動確定分の消込金額合計が入金合計と一致
  - [ ] 二重マッチングなし（1 入金 → 1 以上の売掛金、ただし同一売掛金が複数入金に紐付かない）
  - [ ] 候補提示分に対して AI の信頼度スコアが付与されている
- 品質チェック機構
  - 金額整合性の数学的検証（消込金額の合計 = 入金金額）
  - 二重マッチング検出（同一売掛金が複数の入金に割り当てられていないか）
  - 消込率の異常検知（前月比で 10% 以上低下していないか）
- サブエージェント構成
  - `FuzzyMatchAgent`: 振込名義と取引先名の曖昧マッチング担当
  - `CombinationAgent`: 合算入金の組み合わせ探索担当

### AIエージェント層
- 担当タスク（推論アップサイドが大きい部分）
  - 振込名義と取引先名の曖昧マッチング（カナ揺れ・略称対応）
  - 合算入金の組み合わせ推定（複数請求書の金額合計が入金額に一致する組み合わせの探索）
  - 不明入金に対する取引先候補の推定（過去パターンからの推論）
- 使用するツール/API
  - Claude API（claude-sonnet-4-20250514）: 自然言語理解による名義マッチング
  - ナレッジストア参照: 過去の名義→取引先マッピング辞書
- ヒューマン・イン・ザ・ループのトリガー条件
  - AI の信頼度スコアが 0.8 未満のマッチング候補
  - 新規取引先（過去に消込実績がない）からの入金
  - ナレッジ辞書への新規ルール追加提案時

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）
  - 金額完全一致マッチング（ハッシュマップによる O(1)検索）
  - 消費税込み/税抜き変換による再マッチング試行
  - 消込仕訳の生成（借方: 普通預金 / 貸方: 売掛金）
  - 未消込売掛金のエージング計算（30 日/60 日/90 日超過）
  - 振込の手数料差額の自動調整（差額が一般的な振込手数料の範囲内なら自動消込）

### ナレッジ自動改善ループ
1. インプット（ユーザー行動/フィードバック）
   - 人間が手動で消し込んだ「振込名義→取引先」ペア
   - 人間が AI 候補を承認/却下した結果
   - 人間が修正した消込仕訳
2. 矛盾検知メカニズム
   - 同一振込名義に対して異なる取引先が割り当てられた場合にアラート
   - 過去のルールと矛盾する新しい消込パターンの検出
3. 承認フロー
   - 同一パターンが 3 回以上発生 →「確定ルール昇格」を経理担当者に提案
   - 担当者が承認 → 決定論的ルールに追加（以降 AI を介さず自動消込）
4. 反映タイミング
   - 辞書エントリ追加: 即座（次回マッチングから反映）
   - 確定ルール昇格: 承認後即座

## MVP（プロトタイプ）スコープ

以下の機能を実装します。
1. 3 段階マッチングパイプライン — 決定論的な完全一致 → AI 曖昧マッチング → 要調査分類
2. ハーネスによる品質保証 — 終了条件チェック・二重マッチング検出・金額の整合性検証
3. ナレッジ辞書の蓄積と改善提案 — 消込結果からの学習と確定ルール昇格提案

以下の機能は将来版で実装します。
- 会計ソフト連携（freee / マネーフォワード / 弥生 API）
- 銀行 API 連携（入金データの自動取得）
- Web UI ダッシュボード
- マルチテナント対応
- 合算入金の組み合わせ探索（プロトタイプでは 1:1 マッチングに限定）
