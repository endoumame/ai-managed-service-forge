# 新機能パッケージ製品アイデア レポート
日時: 2026-04-03
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: ReconcileBot — 入金消込自動マッチングサービス

### エレベーターピッチ
銀行入金データと売掛金台帳を自動マッチングし、「消込済み・候補付き・要調査」の 3 段階に分類した状態で経理担当者に提示する、入金消込マネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
入金消込はハーネスの価値が最も明確に現れる領域です。金額の整合性チェックは「だいたい合ってる」では許されず、1 円の誤差も許容できない会計処理において、決定論的コードによる外部検証が不可欠です。AI エージェントが「全部消し込みました」と自己申告しても、ハーネスが「まだ未処理の入金が 2 件ある」と差し戻す仕組みが、ドリフト問題への直接的な対策になっています。さらに、振込名義→取引先マッピング辞書という形でナレッジが自然に蓄積され、3 回以上使われたパターンを確定ルールに昇格させることで「使うほど賢くなる」自己改善ループが実現できます。この改善ループは単一企業では限界がありますが、マネージドサービスとして業界横断でナレッジを共有することで、内製では到達できない精度に到達できます。

### プロトタイプで実証できたこと
- 3 層アーキテクチャ（ハーネス/AI エージェント/決定論的コード）の明確な分離と連携
- ハーネスのライフサイクルフック（beforeMatch/afterMatch/beforeFinalize）による外部品質保証
- 終了条件チェックリストによるドリフト対策（AI の自己申告に頼らない完了判定）
- 決定論的コードによる金額完全一致マッチングと振込の手数料差額の検出
- ナレッジ辞書の蓄積と確定ルール昇格提案の仕組み
- 6 件の入金データに対して消込率 100%（5 件完全一致 + 1 件手数料差額）を達成

### プロトタイプの起動方法
```bash
cd 2026-04-03/prototype
npm install
npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API 統合 — モックの類似度計算を claude-sonnet-4-20250514 に置き換え、カナ→漢字変換や略称認識の精度を向上させる
2. 会計ソフト連携: freee / マネーフォワード / 弥生の API と接続し、入金データ・売掛金データの自動取得と消込結果の自動反映を実現する
3. Web UI ダッシュボード: 経理担当者が候補の承認/却下をブラウザ上で行えるインターフェースを構築し、ヒューマン・イン・ザ・ループの体験を向上させる

### 学んだこと / 気づき
- 振込の手数料差額マッチング（¥329,670 + ¥330 = ¥330,000）は決定論的コードで簡潔に実装でき、AI に任せるよりも確実。「AI が得意なこと」と「ルールで確実に処理すべきこと」の線引きが重要
- ハーネスの終了条件チェックリストは 4 項目（全入金処理済み/金額整合性/二重マッチなし/信頼度スコア付与）で十分にドリフト対策として機能する
- ナレッジ辞書の「確定ルール昇格」は、AI のコスト削減とレイテンシ改善の両方に効く。頻出パターンを AI 推論から決定論的ルールに昇格させることで、サービスのコスト構造が改善される
- 厳格なリンター環境下でもクリーンなコードを維持することで、プロトタイプの品質が本番コードと同等になり、そのまま発展させやすい
