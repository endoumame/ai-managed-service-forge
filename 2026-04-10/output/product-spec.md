# InvoiceGuard 設計書

## エレベーターピッチ

InvoiceGuard は、受領した請求書を AI が自動仕訳し、ハーネスが金額・税率・異常値を決定論的に検証します。人間の承認を経て確定する「請求書処理の完成品」を提供する AI マネージドサービスです。

## ターゲットユーザー

- ペルソナは中小企業（従業員 50〜500 名）の経理担当者（1〜3 名体制）である
- ペインポイントは以下のとおりである
  - 月間 50〜300 枚の請求書を手作業で仕訳入力している
  - インボイス制度対応で確認項目が増え、処理時間が 1.5 倍に
  - 仕訳ミスが月次決算時に発覚し、手戻りが発生
  - 異常な請求（二重請求、金額変動）を見落とすリスク
- 現在の解決方法は以下のとおりである
  - 手作業で Excel に入力→会計ソフトへ転記
  - または会計ソフトの OCR 機能（精度が低く結局手修正）
- 提供する価値は以下のとおりである
  - 請求書の処理時間を 80%削減（月 20 時間→4 時間）
  - 仕訳精度 99%以上（ハーネスの品質チェックにより保証）
  - 異常請求の 100%検知（決定論的チェック + AI 異常スコア）

## システムアーキテクチャ

### ハーネス層

- ライフサイクルフックは以下のとおりである
  - `before-extract` では請求書データの形式チェック（必須フィールドの存在確認）を行う
  - `after-extract` では抽出データの整合性チェック（金額と税額の関係、日付の妥当性）を行う
  - `before-classify` では過去の仕訳ルールの読み込みを行う
  - `after-classify` では仕訳結果のバランスチェック（借方合計 = 貸方合計）を行う
  - `before-complete` では全請求書の処理状況を確認する

- 終了条件管理はチェックリスト方式で、以下の項目を確認する
  - [ ] 全請求書が「処理済み」または「要確認」ステータス
  - [ ] 未分類の請求書がゼロ
  - [ ] バランスチェック（借方 = 貸方）が全仕訳で合格
  - [ ] 異常スコアが閾値超えの請求書がすべてレビュー済み
  - [ ] インボイス番号のバリデーション完了

- 品質チェック機構は以下のとおりである
  - 税率計算の逆算検証（税込額 ÷ (1 + 税率) = 税抜額の一致確認）
  - 同一取引先の過去 6 か月平均との乖離率チェック（±30%超で警告）
  - 重複請求チェック（同一取引先 × 同一金額 × 近接日付）

- サブエージェント構成は以下のとおりである
  - データ抽出エージェント（請求書→構造化データ）
  - 仕訳分類エージェント（構造化データ→仕訳）
  - 異常検知エージェント（全仕訳→異常スコア）

### AIエージェント層

- 担当タスク（推論アップサイドが大きい部分）は以下のとおりである
  - 請求書テキストからの構造化データ抽出（取引先名、金額、品目、日付の認識）
  - 過去の仕訳パターンに基づく勘定科目の推定
  - 取引の異常度スコアリング（通常パターンからの逸脱度）
  - 摘要文の自動生成

- 使用するツール/API は以下のとおりである
  - Anthropic Claude API（テキスト理解・分類）
  - ※プロトタイプでは OCR は省略し、構造化 JSON を入力とする

- ヒューマン・イン・ザ・ループのトリガー条件は以下のとおりである
  - 異常スコアが閾値（0.7）を超えた取引
  - AI の確信度が閾値（0.8）を下回った仕訳提案
  - 新規取引先（過去データなし）の初回仕訳
  - 金額が一定額（100 万円）を超える取引

### 決定論的コード層

- 担当処理は以下のとおりである
  - 消費税計算（標準税率 10%、軽減税率 8%の判定と計算）
  - インボイス番号バリデーション（T + 13 桁数字のフォーマットチェック）
  - 借方・貸方のバランスチェック
  - 仕訳番号の採番（連番管理）
  - 日付フォーマットの正規化（和暦→西暦変換含む）
  - 重複チェック（完全一致 + ファジーマッチ）

### ナレッジ自動改善ループ

1. インプット（ユーザー行動/フィードバック）は以下のとおりである
   - 仕訳提案に対する承認（そのまま採用）
   - 仕訳提案に対する修正（勘定科目の変更、金額の訂正）
   - 異常フラグに対する判断（「正常」確認 or「異常」確認）

2. **矛盾検知メカニズム**:
   - 同一取引先 × 同一パターンで異なる勘定科目が使われた場合に矛盾を検知
   - 修正率が閾値（20%）を超えたルールを「要見直し」としてフラグ

3. **承認フロー**:
   - 改善提案をバッチで生成（週次）
   - 「取引先 A の消耗品費→事務用品費へ変更を提案」といった形で具体的に提示
   - 人間の承認後にルールを更新

4. **反映タイミング**:
   - 承認済みルールは即座に反映
   - 統計モデル（異常スコア等）は週次バッチで再計算

## MVP（プロトタイプ）スコープ

実装する機能は以下の 3 つに絞ります。
1. **請求書データからの自動仕訳提案**（AI 推論 + 決定論的バリデーション）
2. **異常検知 & ヒューマン承認フロー**（CLI ベースの対話的承認）
3. **ナレッジ自動改善提案**（承認/修正の蓄積→ルール改善提案）

以下の機能は将来版とし、今回は実装しません。
- OCR による請求書画像/PDF の読み取り（プロトタイプでは JSON 入力）
- 会計ソフト連携（freee, マネーフォワード等への API 出力）
- マルチテナント対応
- Web ダッシュボード
- 電子帳簿の保存法に対応するタイムスタンプ管理
