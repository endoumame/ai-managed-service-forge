# 新機能パッケージ製品アイデア レポート
日時: 2026-04-10
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceGuard — 請求書の自動仕訳・異常検知サービス

### エレベーターピッチ
InvoiceGuard は、受領した請求書を AI が自動仕訳し、ハーネスが金額・税率・異常値を決定論的に検証します。人間の承認を経て確定する「請求書処理の完成品」を提供する AI マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は金額の正確性が絶対要件であり、AI の自己申告を信じてはいけない領域です。ハーネスなしでは「税額が正しいか」「仕訳がバランスしているか」を 100%保証できず、サービスとして成立しません。さらに、仕訳の承認や修正がそのままフィードバックループとなり、ナレッジの自動改善が業務フローへ自然に組み込まれます。終了条件の外部管理（「全請求書が処理済みか」をデータで検証）がなければ、AI が未処理の請求書を残すドリフト問題が発生します。そのため、ハーネスの存在が不可欠です。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before-extract / after-extract / after-classify）による入出力の品質保証
- 終了条件チェックリスト（5 項目）による AI 自己申告に頼らない完了判定
- ナレッジの自動改善提案（ABC コンサルティングの仕訳修正→ルール更新提案を自動生成）
- 異常検知（金額乖離 100%、重複請求疑い）による要レビューフラグ付け
- ヒューマン・イン・ザ・ループ（承認/修正のシミュレーション→フィードバック記録）

### プロトタイプの起動方法
```bash
cd 2026-04-10/prototype
npm install
npm run demo
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API との統合（モックモードから実際の LLM 推論への切り替え）と、OCR/PDF パーサーの組み込みによる実請求書対応
2. Web ダッシュボードの構築（承認フロー、改善提案の管理 UI、処理状況のリアルタイム表示）
3. 会計ソフト連携（freee / マネーフォワード / 弥生）の API コネクタ開発とマルチテナント対応

### 学んだこと / 気づき
- 決定論的コード層の分離は想像以上に重要。税率計算やバランスチェックを AI に任せると、99%正しくても 1%のミスが致命的になる。ルールベースで 100%保証できる処理は必ず分離すべき
- ナレッジの自動改善ループは「承認/修正」という既存の業務アクションに乗せることで、追加コスト無しで実現できる。ユーザーに「AI のためにフィードバックしてください」と頼むのではなく、通常業務の一部として組み込む設計が鍵
- 異常検知のスコアリングは閾値設計が重要。厳しすぎるとレビュー疲れが起き、緩すぎると見逃しが発生する。初期値を設定し、実運用データで調整する仕組みが必要
