# 新機能パッケージ製品アイデア レポート
日時: 2026-04-17
ターゲットドメイン: 法務レビュー（契約書）

## 選定アイデア: ContractGuard - 契約書リスクスコアリング＆条項チェッカー

### エレベーターピッチ
ContractGuard は、契約書をアップロードするだけでリスク箇所の特定・スコアリング・修正提案を自動生成する AI マネージドサービスです。法務担当者が最終判断に集中できる「契約書レビュー完了レポート」を提供します。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
契約書レビューは、AI の「問題ありません」という自己申告を絶対に信用できない領域です。ハーネスによる終了条件管理（全必須条項が検査済みか、全リスク箇所にスコアが付いているか）が不可欠です。加えて品質チェック（AI の引用が原文に実在するか）もなければ、プロダクトとして成立しません。また、AI が担うべき部分（条項の意味理解・文脈分析）と決定論的コードが担うべき部分（必須条項の存在チェック・リスクスコア計算）の境界が明確です。三位一体アーキテクチャの価値を最もわかりやすく示すことができます。さらに、契約書レビューは企業横断でチェックロジックを共通化でき、マネージドサービスとしての経済合理性が高い領域です。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフックによる品質保証パイプライン（入力検証→AI 分析→決定論的チェックの 3 ステップ逐次実行）
- AI スコアと決定論的ルールベーススコアの乖離検出（損害賠償: AI=3 vs ルール=1 の乖離を自動警告）
- 終了条件の外部管理（AI ではなくハーネスが「全条件充足か」を判定）
- 必須条項の決定論的チェック（6 カテゴリの必須条項存在チェック、不可抗力条項の欠如を検出）
- ナレッジ改善ループの基盤（フィードバック蓄積→改善提案生成→承認フローの一連の流れ）

### プロトタイプの起動方法
```bash
cd 2026-04-17/prototype
npm install
MOCK_AI=true npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. PDF/OCR に対応し、契約書の PDF アップロードからテキスト抽出までのパイプラインを実装する。
2. Web ダッシュボードを構築し、レビュー結果の可視化とヒューマン・イン・ザ・ループの承認 UI を提供する。
3. マルチテナントに対応し、企業ごとのナレッジベース分離とクロステナント学習の匿名化基盤を構築する。

### 学んだこと / 気づき
- ハーネスの品質チェック（引用検証・スコア乖離検出）は、AI の出力品質を劇的に向上させる。モックモードでも乖離検出が機能し、ハーネスの価値を実証できた。
- 終了条件の外部管理は「AI に何をさせないか」を明確にする設計パターンとして有効。AI の自己過信を構造的に防げる。
- ナレッジ改善ループは最低 3 件のフィードバックが必要（閾値設計）で、初期段階では「改善提案なし」が正しい挙動。過学習防止のガードレールとして機能する。
