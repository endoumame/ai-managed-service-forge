# InvoiceForge 設計書

## エレベーターピッチ

請求書 PDF をアップロードするだけで、AI が情報を抽出し、ハーネスが正確性を保証します。人間は「確認して承認する」だけで仕訳が完了する、請求書の自動仕訳サービスです。

## ターゲットユーザー

- ペインポイント: 月に数十〜数百枚の請求書を手作業で仕訳している。フォーマットがバラバラで、転記ミスが頻発。月末に経理担当者が残業して対応している。
- 現在の解決方法: Excel 手入力、または OCR ツール＋手動補正。既存 OCR ツールは読み取り精度が不十分で、結局人間が全件チェックしている。
- 提供する価値: 仕訳作業時間を 90%削減。ハーネスによる品質保証で「AI が間違えても気づける」安心感を提供。時間とともに精度が向上する自己改善ループ。

## システムアーキテクチャ

### ハーネス層

- ライフサイクルフック:
  - `before-extract`: 入力 PDF のバリデーション（ページ数、ファイルサイズ、破損チェック）
  - `after-extract`: 抽出結果の構造検証（必須フィールドの存在確認、金額フォーマット検証）
  - `before-journalize`: 勘定科目マスタとの照合、税計算の検証
  - `after-journalize`: 仕訳バランスチェック（借方＝貸方）
- 終了条件管理:
  - チェックリスト形式で外部管理（AI に自己申告させない）
  - 必須条件: ① 全必須フィールド抽出済み ② 金額フォーマット正規化済み ③ 勘定科目マッピング済み ④ 税計算検証済み ⑤ 仕訳バランス OK
- 品質チェック機構:
  - 抽出金額の桁数・範囲チェック（統計的な異常の検知）
  - 過去の同一取引先における仕訳との一貫性チェック
  - 信頼度スコアが閾値未満の場合、自動的にヒューマンレビューへエスカレーション
- サブエージェント構成:
  - 抽出エージェント（PDF→構造化データ）
  - 仕訳エージェント（構造化データ→仕訳候補）
  - 各エージェントは独立して動作し、ハーネスが結果を統合

### AIエージェント層

- 担当タスク（推論アップサイドが大きい部分）:
  - 非定型 PDF/画像からの請求情報抽出（取引先名、金額、日付、品目、請求番号）
  - 過去の仕訳パターンに基づく勘定科目の推定
  - 異常検知（重複請求、金額の急激な変動、未知の取引先）
- 使用するツール/API:
  - Claude API（claude-sonnet-4-20250514）: PDF 解析、自然言語理解
  - ナレッジストア参照: 過去の仕訳パターン検索
- ヒューマン・イン・ザ・ループのトリガー条件:
  - 信頼度スコア < 0.8 の抽出結果
  - 初めての取引先からの請求書
  - 過去パターンと大きく異なる金額（標準偏差 2σ超）
  - ナレッジベースの改善提案（新ルール追加時）

### 決定論的コード層

- 担当処理（ルールベースで確実に実行する部分）:
  - 消費税計算（税率テーブル × 税抜金額）
  - 勘定科目マスタとの完全一致マッチング
  - 仕訳帳フォーマットへの変換（借方/貸方の生成）
  - 重複チェック（請求番号 + 取引先 + 金額 + 日付の組み合わせ）
  - 仕訳バランス検証（借方合計 = 貸方合計）
  - 日付フォーマットの正規化

### ナレッジ自動改善ループ

1. **インプット（ユーザー行動/フィードバック）**:
   - 人間が仕訳を修正した場合の修正内容（修正前→修正後）
   - 承認/却下のアクションログ
   - 新しい取引先情報の登録

2. **矛盾検知メカニズム**:
   - 同一取引先に対して異なる勘定科目が割り当てられた場合を検知
   - 既存ルールと修正内容の矛盾を自動検出
   - 修正頻度が高い取引先・科目パターンを「要改善」としてフラグ

3. **承認フロー**:
   - 改善提案をキューに追加（自動適用はしない）
   - 人間が「承認」した場合のみナレッジベースに反映
   - 承認率をメトリクスとして追跡

4. **反映タイミング**:
   - 承認後、即座にナレッジベースへ反映
   - 次回以降の同一パターン処理から適用

## MVP（プロトタイプ）スコープ

以下の 3 機能に絞って実装します。

1. **請求書データ抽出＋ハーネスバリデーション**: サンプル請求書 JSON から AI が情報を抽出し、ハーネスが外部バリデーション（必須フィールド、金額フォーマット、税計算）を実行
2. **自動仕訳生成＋終了条件チェック**: 抽出データから仕訳を生成し、チェックリスト形式の終了条件をハーネスが管理（借方=貸方バランス検証含む）
3. **ナレッジ改善提案＋承認フロー**: 仕訳修正時に改善提案を生成し、人間の承認を経てナレッジベースに反映するループ
