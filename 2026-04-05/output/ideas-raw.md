# アイデア発散: 経理・請求書処理ドメイン

日時: 2026-04-05。

## アイデア 1: InvoiceForge — 請求書の自動仕訳マネージドサービス

### ユーザーが本当に欲しいもの（業務の完成品）
受信した請求書 PDF をアップロードするだけで、正しい勘定科目で仕訳され、承認待ちキューに入り、承認後に会計ソフトへ自動連携される状態。経理担当者は「確認して承認する」だけで仕訳業務が完了する。

### ハーネス設計のキモ
- Before-Tool フック — AI 抽出結果を決定論的ルール（税率計算、勘定科目マスタ照合）でバリデーション
- 終了条件 —「全必須フィールド抽出済み」「仕訳ルール照合済み」「金額突合 OK」の 3 条件をチェックリストで管理
- 品質チェック — 抽出された金額と元 PDF の金額画像を OCR 二重チェック

### AIが担う部分
- 非定型 PDF/画像からの請求情報抽出（自然言語理解・パターン認識）
- 過去の仕訳パターンからの勘定科目推定
- 異常な請求（重複、金額急増など）の検知

### 決定論的コードが担う部分
- 消費税計算（税率×金額）
- 勘定科目マスタとのマッチング
- 仕訳帳フォーマットへの変換
- 重複チェック（請求番号の一意性検証）

### ナレッジ/データの自動改善ループ
- 人間が仕訳を修正した場合、修正パターンをナレッジベースに蓄積
- 同一取引先の過去仕訳パターンを学習し、次回以降の精度を向上
- 定期的に「修正が多い取引先」レポートを生成し、ルールの見直しを提案

### 内製との差別化ポイント
- モデル進化への追従（新しい PDF フォーマット、新しい税制への対応）を継続的にサービス側が行う
- 多企業のパターンを集約した汎用仕訳ルールの恩恵（個社では蓄積できないデータ量）
- ハーネス基盤の保守・改善コストを顧客が負担しなくてよい

## アイデア 2: PayGuard — 支払い異常検知＆承認フロー自動化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
全ての支払いが適切に承認され、不正・誤りが事前に検知された状態。経理部長が「今月の支払いに問題はない」と自信を持って言える状態。

### ハーネス設計のキモ
- ライフサイクルフック — 支払い登録→異常スコアリング→承認ルーティング→実行確認の 4 段階管理
- 終了条件 — 全支払いの異常スコア算出完了 ＋ 閾値超え案件の人間レビュー完了
- 品質チェック — 過去 3 ヶ月の支払いパターンとの統計的比較

### AIが担う部分
- 支払いパターンの異常検知（金額・頻度・取引先の異常）
- 請求書と発注書の自然言語レベルでの内容照合
- 不正リスクの文脈的判断（取引先と金額の通常性を評価）

### 決定論的コードが担う部分
- 承認権限マトリクスに基づくルーティング
- 金額閾値による自動承認/手動承認の振り分け
- 支払い実行のスケジューリング

### ナレッジ/データの自動改善ループ
- 「異常と判定したが正常だった」ケースをフィードバックし、偽陽性率を低減
- 新しい不正パターンが発覚した場合のルール追加
- 取引先ごとの「正常な支払いパターン」プロファイルの自動更新

### 内製との差別化ポイント
- 多企業の不正パターンデータを匿名化して集約した検知モデル
- 法改正・コンプライアンス要件の変更への継続的対応
- 異常検知モデルの精度向上を顧客側で行う必要がない

## アイデア 3: BookKeepSync — 経費精算→仕訳→会計ソフト連携パイプラインサービス

### ユーザーが本当に欲しいもの（業務の完成品）
従業員が経費精算を提出すると、レシート画像から情報が抽出され、正しく仕訳されます。承認後は会計ソフトへ自動連携される状態です。月末の「経費精算の山」がなくなります。

### ハーネス設計のキモ
- Before-Tool フック — レシート OCR 結果を金額フォーマット正規化で検証
- 終了条件 —「全レシート処理済み」「会計ソフト連携成功」をパイプラインで管理
- 品質チェック — 連携先会計ソフトのインポート結果を API 経由で確認

### AIが担う部分
- レシート画像からの情報抽出（店名、金額、日付、品目）
- 経費カテゴリの自動分類
- ポリシー違反の検知（上限超過、私的利用の疑い）

### 決定論的コードが担う部分
- 経費ポリシールールエンジン（上限額チェック、対象外品目チェック）
- 会計ソフト API へのデータ変換・送信
- 為替レート計算（海外出張経費）

### ナレッジ/データの自動改善ループ
- カテゴリ分類の修正履歴から分類精度を向上
- 新しい店舗名→カテゴリのマッピングを蓄積
- ポリシー違反パターンの学習

### 内製との差別化ポイント
- 多様な会計ソフトとのコネクタ保守を個社で行う必要がない
- レシートフォーマットの変化への継続的対応
- 複数企業の経費パターンから学習した高精度分類

## アイデア 4: ContractBilling — 契約書ベース請求スケジュール自動管理サービス

### ユーザーが本当に欲しいもの（業務の完成品）
契約書に記載された支払条件（月額、年額、マイルストーン払い等）から自動で請求スケジュールが生成され、請求漏れ・タイミングずれがゼロになる状態。

### ハーネス設計のキモ
- ライフサイクルフック — 契約書アップロード→条件抽出→スケジュール生成→人間確認→請求実行
- 終了条件 — 全契約の請求条件を抽出完了 ＋ スケジュール確認完了
- 品質チェック — 抽出された金額・日付の元契約書との突合

### AIが担う部分
- 契約書からの支払条件抽出（自然言語理解）
- 曖昧な条件の解釈（「月末締め翌月末払い」等のパターン認識）
- 契約更新・変更時の差分検出

### 決定論的コードが担う部分
- 請求スケジュールのカレンダー生成
- 請求書テンプレートへの差し込み
- リマインダー通知の送信

### ナレッジ/データの自動改善ループ
- 契約書のフォーマットパターンを蓄積し、抽出精度を向上
- 「修正された請求条件」をフィードバックして解釈ルールを改善
- 業界別の支払慣行パターンの学習

### 内製との差別化ポイント
- 多種多様な契約書フォーマットへの対応を個社で維持する必要がない
- 法改正（インボイス制度等）への継続的対応
- 業界横断の契約パターン知識

## アイデア 5: ReconcileBot — 銀行明細×請求書を自動で消込するサービス

### ユーザーが本当に欲しいもの（業務の完成品）
銀行口座の入出金明細と請求書/売掛金・買掛金が自動で突合・消込され、不一致のみ人間がレビューすればよい状態。月次決算の消込作業が数時間から数分に短縮される。

### ハーネス設計のキモ
- Before-Tool フック — AI 照合結果を金額完全一致チェックで検証
- 終了条件 —「全明細の照合完了」「不一致案件の人間レビュー完了」「消込と仕訳の生成完了」
- 品質チェック — 消込後の残高と銀行残高の突合
- サブエージェント — 明細ごとに独立した照合エージェントを並列実行

### AIが担う部分
- 銀行明細の摘要欄と請求書の取引先名・内容のファジーマッチング
- 分割払い・まとめ払いの推定（1 対多、多対 1 の照合）
- 不一致原因の推定（「手数料差引」「為替差」等）

### 決定論的コードが担う部分
- 金額完全一致の突合（ルールベース）
- 消込仕訳の自動生成
- 残高検証
- 期日管理（入金予定日との照合）

### ナレッジ/データの自動改善ループ
- 人間が手動で照合したパターンを学習し、次回以降の自動照合率を向上
- 取引先ごとの「振込名義パターン」を蓄積（例:「(カ)ABC」→「ABC 株式会社」）
- 照合ルールの精度メトリクスを継続的に追跡

### 内製との差別化ポイント
- 複数銀行のフォーマット差異への対応を個社で維持する必要がない
- 多企業の照合パターンから学習したファジーマッチングの高精度
- 消込ロジックの改善を継続的にサービス側が行う
