# 新機能パッケージ製品アイデア レポート
日時: 2026-04-05
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceForge — 請求書の自動仕訳マネージドサービス

### エレベーターピッチ
請求書 PDF をアップロードするだけで、AI が情報を抽出し、ハーネスが正確性を保証します。人間は「確認して承認する」だけで仕訳が完了する、請求書の自動仕訳マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は AI の出力を「信頼しない」アーキテクチャが最も自然に要求されるドメインです。金額の 1 円のズレも許されない経理業務では、AI の自己申告（「正しく読み取れました」）を信じることはできません。ハーネスによる外部バリデーション（金額突合、税計算検証、仕訳バランスチェック）が不可欠であり、まさに「ハーネスなしでは成立しない」ユースケースです。

さらに、仕訳のルールベース処理（消費税計算、勘定科目マスタ照合）と AI の推論（非定型データからの抽出、勘定科目推定）の分離が自然です。「AI エージェント + ハーネス + 決定論的コード」の三位一体モデルの実証に最適でした。

自己改善ループも「人間が仕訳を修正 → ナレッジベースに蓄積 → 次回精度向上」という形で自然に組み込めるため、AI マネージドサービスとしての継続的価値を示しやすい。

### プロトタイプで実証できたこと
- ハーネスによる AI 出力の外部バリデーション: 必須フィールドチェック、金額整合性、税計算検証、仕訳バランスチェックを決定論的コードで実装
- 終了条件の外部管理（ドリフト対策）: CompletionPlanner がチェックリスト形式で 3 つの完了条件を管理し、AI の自己申告に依存しない
- ナレッジ改善提案 + ヒューマン・イン・ザ・ループ: 仕訳修正を検知し改善提案を生成、人間の承認を経てナレッジベースへ反映するフロー
- 3 層アーキテクチャの連携: ハーネス層（lifecycle hooks, checker, planner）、エージェント層（extractor）、決定論的コード層（rules）が協調動作

### プロトタイプの起動方法
```bash
cd 2026-04-05/prototype
npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API マルチモーダル統合: 実際の PDF/画像からの請求書の情報抽出を実装（現在は JSON 入力のモック）
2. 会計ソフト API 連携: freee、マネーフォワード等の主要会計ソフトへの仕訳データ自動連携
3. Web ダッシュボード: 承認フロー、ナレッジ管理、処理状況の可視化を提供する UI 構築

### 学んだこと / 気づき
- 「信頼しないアーキテクチャ」は AI マネージドサービスの設計原則として非常に強力。AI の出力を外部検証する仕組みがあることで、利用者の安心感が向上する
- 終了条件の外部管理は、ドリフト問題への最もシンプルかつ効果的な対策。チェックリスト形式で管理することで、AI が「もう十分」と途中完了宣言するリスクをゼロにできる
- 決定論的コードと AI の責務分離は、テスタビリティの観点でも大きなメリットがある。税計算やバランスチェックはユニットテストで 100%カバーでき、AI の不確実性が限定される
