# 新機能パッケージ製品アイデア レポート
日時: 2026-04-13
ターゲットドメイン: 経理・請求書処理

## 選定アイデア: InvoiceForge — 請求書自動仕訳サービス

### エレベーターピッチ
受領した請求書を自動で仕訳に変換し、貸借一致・税額検証をハーネスが保証した上で、人間の承認を経て会計データとして出力する AI マネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は「AI エージェント単体では品質保証できない」典型的な業務である。AI は請求書テキストの理解と勘定科目の推定に優れるが、1 円の誤差も許されない仕訳処理では、貸借一致や消費税計算の検証を決定論的コードで行うハーネス層が不可欠。InvoiceForge では、ハーネスがライフサイクルフック（before:parse、after:classify、before:approve）で各ステップを監視し、終了条件チェックリストを AI の自己申告に頼らず外部管理する。この「AI を信頼しない設計」こそがハーネスの本質的価値であり、AI エージェント単体との決定的な差別化ポイントとなる。さらに、ナレッジ自動改善ループにより、ユーザーの修正フィードバックがパターンとして蓄積され、使えば使うほど精度が向上する仕組みも、マネージドサービスならではの価値である。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before:parse / after:classify）が、AI の出力に対する外部品質ゲートとして機能すること
- 終了条件チェックリスト（6 項目）がハーネスにより外部管理され、「全条件クリアまで完了としない」ドリフト防止が実現できること
- 決定論的コード層（貸借一致チェック、消費税計算検証、科目マスタ照合）が AI の出力を 100%正確に検証できること
- ナレッジストア（JSON ファイルベース）に取引先パターンが蓄積され、自動改善ループの基盤が動作すること
- ヒューマン・イン・ザ・ループ（CLI 承認フロー）がパイプラインに自然に組み込まれること
- モック/実 API の切り替えにより、API キーなしでもフルパイプラインのデモが可能であること

### プロトタイプの起動方法
```bash
cd 2026-04-13/prototype
npm install
# モックモード（APIキー不要）
MOCK_AI=true npx tsx demo/run.ts
# 実APIモード（Claude APIキーが必要）
ANTHROPIC_API_KEY=your-key npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. OCR/PDF 入力対応: 画像・PDF の請求書を直接入力できるようにし、実際の業務フローに対応する
2. Web ダッシュボード開発: CLI 承認フローを Web ベースの UI に置き換え、複数ユーザーの同時利用に対応する
3. 会計ソフト連携 API: freee、マネーフォワード、弥生会計など主要会計ソフトとの API 連携を実装し、仕訳データの自動インポートを実現する

### 学んだこと / 気づき
- 「AI マネージドサービス」の三位一体（AI + ハーネス + 決定論的コード）は、請求書処理のようなゼロトレランス業務で特に価値が高い。AI の推論力と決定論的な検証の組み合わせが、どちらか単体では到達できない品質を実現する
- ドリフト対策としてのチェックリスト外部管理は、実装がシンプルながらも強力。AI に「完了したか？」と聞くのではなく、外部条件を1つずつ検証するアプローチは、長時間タスクにおける品質保証の基本パターンになりうる
- ナレッジ改善ループは「2 回以上同じ修正が発生したらルール提案」という単純な閾値でも、十分に価値のある自動改善が実現できる。初回は提案なしだが、データが蓄積されるにつれて自然に賢くなる設計は、マネージドサービスの差別化として説得力がある
