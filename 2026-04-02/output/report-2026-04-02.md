## 選定アイデア: InvoicePilot — 請求書受領→仕訳→承認 自動パイプライン

### エレベーターピッチ
受領した請求書を自動で読み取り・仕訳推定し、人間は承認ボタンを押すだけで記帳が完了する、AI マネージドな請求書処理パイプライン。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理パイプラインは「受領→抽出→仕訳推定→承認」の各ステップに自然なチェックポイントがあり、ハーネスのライフサイクルフックが最も活きる構造を持っています。特に「必須フィールドの充足確認」「仕訳コードのマスタ照合」「税額の算術的整合性」は、AI の自己申告に頼らず外部から決定論的に検証可能です。また、ユーザーの仕訳修正がそのままナレッジ改善のフィードバックとなる自己改善ループが自然に発生し、マネージドサービスの核心的価値「使えば使うほど賢くなる」を最も分かりやすく体現できます。コモディティ性も極めて高く、「請求書処理が上手いから売上が伸びた」という企業は存在しないため、内製よりマネージドサービスの経済合理性が明確です。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（afterExtraction / afterJournalEstimation / beforeApproval）による AI ドリフト防止
- 終了条件の外部管理（チェックリスト形式）により、AI の「自己申告による完了」を排除
- 決定論的コード層による税額検証・マスタ照合・重複検出・異常値チェック
- ナレッジストアによる「取引先×品目→勘定科目」マッピングの蓄積と改善提案
- ヒューマン・イン・ザ・ループの確信度ベース自動判定（閾値 0.8 未満で人間レビュー）
- AI 層と決定論的コード層の明確な責務分離（AI は推論、計算はコード）

### プロトタイプの起動方法
```bash
cd 2026-04-02/prototype
npm install
npm run demo
```

### 次のステップ（マネージドサービス化に向けて）
1. OCR 統合（画像請求書→テキスト変換）と PDF 対応の追加
2. 会計ソフト API 連携（freee, マネーフォワード等への自動記帳）
3. マルチテナント対応とナレッジの企業間での匿名共有基盤の構築

### 学んだこと / 気づき
- ハーネス設計は「AI に何を任せないか」を明確にすることから始まる。税額計算のような「正解が一意に決まる」処理を AI に任せないことで、信頼性とコスト効率を両立できる
- ナレッジの自動改善は「ユーザーの承認」をゲートとして組み込むことが重要。AI の推定結果をそのまま学習させるとハルシネーションがナレッジを汚染する
- ドリフト対策の本質は「AI に自分の出力品質を自己評価させない」こと。チェックリストの各項目を決定論的なルールで検証することが、長時間タスクの品質保証に不可欠
- oxlint の厳格なルール（max-statements: 10, max-params: 3 等）に従うことで、自然と関数が小さく分離され、テスト容易性の高い設計になった
