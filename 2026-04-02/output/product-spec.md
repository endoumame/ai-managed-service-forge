# InvoicePilot 設計書

## エレベーターピッチ
受領した請求書を自動で読み取り・仕訳推定し、人間は承認ボタンを押すだけで記帳が完了する、AI マネージドな請求書処理パイプライン。

## ターゲットユーザー
- ペルソナ — 中小企業の経理担当者（1〜3 名体制）
- ペインポイント:
  - 月に数十〜数百枚の請求書を手作業で仕訳入力している
  - 取引先ごとにフォーマットが異なり、読み取りに時間がかかる
  - 仕訳ミスが月次決算時に発覚し、手戻りが発生する
  - インボイス制度対応で確認項目が増え、負荷が倍増している
- 現在の解決方法:
  - Excel 台帳への手入力
  - OCR ツール（精度に不満）+ 手動修正
  - 会計ソフトの仕訳テンプレート（新規取引先に対応できない）
- 提供する価値:
  - 請求書受領から仕訳完了まで、例外以外はノータッチ
  - 使えば使うほど仕訳精度が上がる自己改善ループ
  - ドリフトしない品質保証（ハーネスによる外部バリデーション）

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック:
  - `beforeExtraction`: 入力データの形式チェック（空でないか、文字数上限内か）
  - `afterExtraction`: 必須フィールド充足チェック（発行元、金額、日付、品目が全て存在するか）
  - `afterJournalEstimation`: 仕訳コードのマスタ照合、税額の算術検証
  - `beforeApproval`: 全バリデーション結果のサマリー生成
- 終了条件の管理:
  - チェックリスト形式で外部管理（JSON ファイル）
  - [ ] 全必須フィールドが抽出済み
  - [ ] 仕訳コードが勘定科目マスタに存在
  - [ ] 税額計算が一致（許容誤差: ±1 円）
  - [ ] 重複請求書チェック完了
  - [ ] 異常値チェック完了（金額の桁数、日付の妥当性）
- 品質チェック機構:
  - 金額の桁数異常検知（過去の同一取引先の平均から 3σ以上乖離）
  - 日付の未来日チェック
  - 重複した請求書の検出（請求書番号 + 取引先 + 金額のハッシュ）
- サブエージェント構成:
  - ExtractorAgent: 請求書テキストからの情報抽出
  - ClassifierAgent: 仕訳の勘定科目推定
  - （プロトタイプでは単一エージェントに統合）

### AIエージェント層
- 担当タスク（推論アップサイドが大きい部分）:
  - 非定型フォーマットの請求書からのフィールド抽出（発行元名、金額、日付、品目、税率）
  - 過去の仕訳パターンに基づく勘定科目の推定
  - 異常請求書の検出理由の自然言語説明
- 使用するツール / API:
  - Anthropic Claude API（claude-sonnet-4-20250514）
  - 構造化出力（JSON mode）でフィールド抽出
- ヒューマン・イン・ザ・ループのトリガー条件:
  - 仕訳推定の確信度が 80%未満の場合
  - 新規取引先（ナレッジに存在しない）の初回処理
  - 異常値が検出された場合（金額の 3σ逸脱等）
  - AI が抽出できなかった必須フィールドがある場合

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）:
  - 税率計算（8% / 10% の適用、端数処理）
  - 仕訳コードバリデーション（勘定科目マスタとの突合）
  - 重複検出（ハッシュ比較）
  - 貸借バランスの検証（借方合計 = 貸方合計）
  - 会計期間の判定

### ナレッジ自動改善ループ
1. インプット（ユーザー行動 / フィードバック）:
   - ユーザーが仕訳推定を修正した場合、修正内容を記録
   - 承認/却下の判断を記録
2. 矛盾検知メカニズム:
   - 同一取引先に対して異なる勘定科目が使用された場合にフラグ
   - 過去のマッピングと新規推定の不一致を検出
3. 承認フロー:
   - 改善提案をユーザーに提示（「取引先 A の品目 X は、過去 3 回中 3 回『消耗品費』に修正された。デフォルトを変更してよいか確認する」）
   - ユーザーが承認した場合のみナレッジを更新
4. 反映タイミング:
   - 即時反映（次回の同一の取引先処理から適用）
   - ただしユーザー承認が前提

## MVP（プロトタイプ）スコープ

### 実装する機能（3つに絞る）
1. 請求書テキストから構造化データを抽出（AI エージェント + ハーネスの必須フィールドチェック）
2. 仕訳推定と決定論的バリデーション（AI の推定 + ルールベースの税額計算・マスタ照合）
3. 承認フローとナレッジ改善提案（ヒューマン・イン・ザ・ループ + 自動学習）

### 実装しない機能（将来版）
- OCR（画像からのテキスト抽出）— プロトタイプではテキスト入力
- 会計ソフト連携（freee, マネーフォワード等への API 連携）
- マルチテナント対応
- バッチ処理（複数請求書の一括処理）
- ダッシュボード（Web UI）
- 適格な請求書番号の国税庁 DB との照合
