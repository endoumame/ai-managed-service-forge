# アイデア発散: 経理・請求書処理ドメイン

日時: 2026-05-02。

## アイデア 1: InvoiceForge — 請求書の自動仕訳マネージドサービス

### ユーザーが本当に欲しいもの（業務の完成品）
受領した請求書（PDF/画像）をアップロードするだけで、正しい勘定科目で仕訳され、承認待ちの状態で会計ソフトに連携される状態。経理担当者は「確認して承認ボタンを押す」だけで月次処理が完了する。

### ハーネス設計のキモ
- **ライフサイクルフック** — 読取→抽出→分類→仕訳の各ステップ完了後に、前ステップの出力との整合性チェックを自動実行
- **終了条件** —「全項目が抽出済み」「仕訳の貸借が一致」「過去の同一取引先パターンとの乖離が閾値以内」の 3 条件をチェックリストで管理
- **品質チェック** — 金額の桁数異常検知、消費税率の妥当性検証、取引先マスタとの突合

### AIが担う部分（推論のアップサイドが大きく、ミスのダウンサイドが小さい部分）
- 請求書のレイアウト認識と項目抽出（OCR 後の構造化）
- 取引内容の自然言語理解による勘定科目の推定
- 過去パターンとの類似度判定による異常取引の検知

### 決定論的コードが担う部分
- 消費税計算（税率テーブル×金額の確定計算）
- 仕訳の貸借バランス検証
- 会計ソフト API へのデータフォーマット変換
- 承認ワークフローの状態遷移管理

### ナレッジ/データの自動改善ループ
- ユーザーが仕訳を修正するたびに「取引先×内容→勘定科目」マッピングを蓄積
- 修正頻度が高い取引先パターンを検知し、ルール化を提案
- 月次で未使用ルールを検出し、整理を提案

### 内製との差別化ポイント
- OCR モデルの精度維持・更新コストが不要（請求書フォーマットは多様で、内製だと追従が困難）
- 税制改正への自動対応（消費税率変更、インボイス制度改正等）
- 複数企業の仕訳パターンから学習した「業界標準」の仕訳提案

## アイデア 2: PaymentGuard — 支払い期日管理 & キャッシュフロー最適化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
全取引先への支払い期日が一覧化され、キャッシュフローを考慮した最適な支払いスケジュールが自動生成される状態。支払い漏れゼロと資金効率の最大化が両立する。

### ハーネス設計のキモ
- **ライフサイクルフック** — 請求書登録→期日抽出→スケジュール生成→実行確認の各ステップにバリデーション
- **終了条件** —「全請求書の期日が登録済み」「重複支払いチェック完了」「資金残高シミュレーション完了」
- **品質チェック** — 期日の妥当性検証（過去日付の検出、異常に長い支払いサイト）

### AIが担う部分
- 請求書からの支払い条件抽出（「月末締め翌月末払い」等の自然言語解析）
- 取引先ごとの支払いパターン分析と異常検知
- キャッシュフロー予測に基づくスケジュール最適化提案

### 決定論的コードが担う部分
- 支払い期日のカレンダー計算（営業日考慮）
- 銀行振込データ（全銀フォーマット）の生成
- 資金残高シミュレーションの数値計算

### ナレッジ/データの自動改善ループ
- 実際の支払い実績と予測の差異を蓄積し、予測精度を向上
- 取引先ごとの支払い条件変更を自動検知してマスタを更新
- 季節変動パターンの学習

### 内製との差別化ポイント
- 全銀フォーマット等の銀行連携仕様への追従コストが不要
- 複数企業のキャッシュフローパターンから学習した業界ベンチマーク提供

## アイデア 3: ExpenseAudit — 経費精算の自動監査サービス

### ユーザーが本当に欲しいもの（業務の完成品）
従業員の提出した経費精算が、社内規程に照らして自動的に監査され、問題のある申請だけ経理担当者にエスカレーションされる状態。不正経費の見逃しゼロと、正当な経費の即時承認が両立する。

### ハーネス設計のキモ
- **ライフサイクルフック** — 申請受理→領収書検証→規程照合→リスクスコアリング→判定の各ステップに品質ゲート
- **終了条件** —「全項目の規程照合完了」「リスクスコア算出完了」「判定理由の記録完了」
- **品質チェック** — 領収書の日付と申請日の整合性、金額と領収書画像の一致確認

### AIが担う部分
- 領収書画像の読み取りと構造化
- 経費内容と社内規程の自然言語マッチング
- 不自然な経費パターンの検知（同一店舗への高頻度利用、端数の不自然さ等）

### 決定論的コードが担う部分
- 社内規程のルールエンジン（上限金額、カテゴリ別制限）
- リスクスコアの閾値判定と承認フロー振り分け
- 税務上の経費計上の可否判定

### ナレッジ/データの自動改善ループ
- 監査結果のフィードバック（誤検知/見逃し）を蓄積してリスクスコアを調整
- 新しい経費パターン（リモートワーク費用等）の出現を検知してルール追加を提案
- 承認者の判断傾向を学習して推奨判定に反映

### 内製との差別化ポイント
- 経費規程の多様なバリエーションに対応済みのルールテンプレート提供
- 不正パターンのデータベースを複数企業横断で蓄積（匿名化）
- 税制改正に伴う経費計上ルールの自動更新

## アイデア 4: ReconcileBot — 入金消込の自動化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
銀行明細と売掛金台帳が自動的に突合され、入金消込が完了した状態。不一致（金額差異、未入金、過入金）だけが経理担当者にアラートされ、対応方針まで提案される。

### ハーネス設計のキモ
- **ライフサイクルフック** — 銀行明細取込→パターンマッチ→消込候補生成→差異分析→確定の各ステップにバリデーション
- **終了条件** —「全明細行が処理済み（消込/保留/エスカレーション）」「未処理ゼロ確認」「消込合計と入金合計の一致」
- **品質チェック** — 二重消込の防止、消込金額と請求金額の差異チェック、消込日の妥当性

### AIが担う部分
- 銀行明細の摘要欄から取引先名の推定（略称、カタカナ表記のゆれ吸収）
- 複数請求書に対する一括入金の分割推定
- 差異原因の推定（振込手数料、値引き、為替差損等）

### 決定論的コードが担う部分
- 金額完全一致の自動消込
- 振込手数料の許容差異計算
- 売掛金残高の更新と帳簿反映
- 督促対象の自動抽出（期日超過の未入金リスト）

### ナレッジ/データの自動改善ループ
- ユーザーの手動消込パターンを学習し、次回以降の自動消込率を向上
- 取引先ごとの入金パターン（振込名義のゆれ、典型的な差異理由）を蓄積
- 季節的な入金遅延パターンの学習

### 内製との差別化ポイント
- 銀行 API の接続・維持コストが不要（複数の銀行に対応済み）
- 振込名義のゆれパターンを複数企業横断で蓄積
- 消込率のベンチマーク提供（業界平均との比較）

## アイデア 5: TaxPrepAssist — 月次の税務申告準備サービス

### ユーザーが本当に欲しいもの（業務の完成品）
月次の消費税申告に必要なデータが、仕訳帳から自動集計・検証され、申告書の下書きが完成した状態。税理士への渡し資料が自動生成され、差戻しゼロで申告が完了する。

### ハーネス設計のキモ
- **ライフサイクルフック** — 仕訳データ取込→税区分検証→集計→申告書下書き生成→整合性チェックの各ステップにバリデーション
- **終了条件** —「全仕訳の税区分の確認完了」「課税売上/仕入の集計一致」「申告書フォーマット準拠確認」
- **品質チェック** — 仕入税額控除の要件充足確認（インボイス番号の存在、適格請求書の発行事業者の番号照合）

### AIが担う部分
- 仕訳内容からの税区分推定（課税/非課税/免税/不課税の判定が曖昧なケース）
- インボイス記載事項の充足判定
- 税務リスクの高い取引の検知

### 決定論的コードが担う部分
- 消費税の計算（税率別の集計、端数処理）
- 申告書フォーマットへのデータ変換
- インボイス番号の国税庁データベース照合

### ナレッジ/データの自動改善ループ
- 税理士からの修正指摘を蓄積し、税区分推定の精度を向上
- 税制改正情報の自動取り込みとルール更新提案
- 過去の申告実績との差異分析による異常検知の精度向上

### 内製との差別化ポイント
- 税制改正への追従コストが不要（年次の税制改正は複雑で、内製システムの改修コストが大きい）
- 国税庁のインボイス発行事業者の公表サイトとの自動連携
- 複数企業の申告パターンから学習した業界標準の税務処理提供
