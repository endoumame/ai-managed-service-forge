# 新機能パッケージ製品アイデア レポート
日時: 2026-05-02
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceForge（請求書の自動仕訳マネージドサービス）

### エレベーターピッチ
請求書 PDF をアップロードするだけで、AI が項目を抽出し、ハーネスが品質を保証し、決定論的コードが正確に仕訳を生成する。経理担当者は「確認して承認」するだけで月次処理が完了するマネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は「読取→抽出→分類→仕訳→承認」という明確なライフサイクルを持ち、各ステップに品質ゲートを設置する必要がある。AI に自己完結させると金額ミスや勘定科目の誤分類が発生するリスクは高く、ハーネスによる外部バリデーションなしでは商用品質に達しない。加えて、消費税計算や貸借バランス検証といった決定論的処理と、勘定科目推定や異常検知といった AI 推論の境界が明確で、三位一体アーキテクチャの価値を最も端的に実証できる。ナレッジの自動改善ループ（仕訳修正→ルール蓄積→次回精度向上）も、ユーザーが使うほどサービスが賢くなる構造として自然に設計できた。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフックにより、抽出・分類・仕訳の各ステップで外部バリデーションが強制され、品質ゲートとして機能する
- 終了条件チェックリストによるドリフト防止: AI の自己完了宣言に依存せず、全条件充足を外部から判定
- 決定論的コードによる消費税の計算検証で、税額不一致のある請求書（INV-002）を即座に検知・エスカレーション
- 金額異常検知により、前月比 434.9%増の請求書（INV-003）を自動でエスカレーション
- ナレッジ自動改善ループ: ユーザーの仕訳修正から新規ルール提案を生成し、承認後はナレッジベースへ反映

### プロトタイプの起動方法
```bash
cd 2026-05-02/prototype
npm install
npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. OCR/PDF 解析の統合: Claude Vision API または専用 OCR サービスとの連携により、実際の請求書画像からの項目抽出を実装
2. 会計ソフト連携: freee/マネーフォワード等の API との仕訳データ連携、およびインボイス番号の国税庁データベース自動照合
3. マルチテナント対応と Web UI: Cloudflare Workers 上での API 実装、承認フローの Web ダッシュボード構築、テナントごとのナレッジベース分離

### 学んだこと / 気づき
- 「AI に任せる部分」と「決定論的に処理する部分」の境界設計が、マネージドサービスの品質を決定づける。消費税計算のような 1 円たりともズレが許されない処理を AI に委ねることは、ハーネスがあっても不適切
- ドリフト防止の核心は「終了条件の外部化」。AI が「完了しました」と宣言しても、チェックリストの全条件が満たされなければ処理を止める仕組みが不可欠
- ナレッジの自動改善ループは「提案→承認→反映」のヒューマン・イン・ザ・ループが必須。自動適用すると、一時的な例外処理がルール化されるリスクもある
