# InvoiceForge 設計書

## エレベーターピッチ

請求書 PDF をアップロードするだけで、AI が項目を抽出し、ハーネスが品質を保証し、決定論的コードが正確に仕訳を生成する。経理担当者は「確認して承認」するだけで月次処理が完了するマネージドサービス。

## ターゲットユーザー

- **ペインポイント** — 毎月数十〜数百枚の請求書を手作業で仕訳入力しており、月末に残業が集中する。入力ミスによる差戻しや修正が頻繁に発生し、本来の分析業務に時間を割けない。
- **現在の解決方法** — Excel 台帳での手管理、または高額な会計ソフトの OCR 機能（精度不足で結局手修正が必要）。
- **提供する価値** — 仕訳入力作業の 90%自動化。人間は例外処理と最終承認のみに集中できる。使うほど精度が上がる自己改善ループにより、時間経過で手修正率が低下。

## システムアーキテクチャ

### ハーネス層

- **ライフサイクルフック** —
  - `beforeExtract`: 入力データの形式検証（JSON 構造チェック）
  - `afterExtract`: 抽出結果の必須フィールド充足チェック（取引先名、日付、金額、明細）
  - `afterClassify`: 勘定科目の妥当性チェック（存在する科目か、過去パターンとの乖離度）
  - `afterJournalize`: 仕訳の貸借バランス検証、消費税計算の整合性チェック
- **終了条件の管理** —
  - チェックリスト方式で外部管理。AI に「完了」を自己申告させない
  - 必須条件: (1) 全項目が抽出済み (2) 勘定科目の割当済み (3) 貸借一致 (4) 消費税の検証済み (5) 信頼度スコアが閾値以上
  - いずれか未達の場合、ヒューマン・イン・ザ・ループへエスカレーション
- **品質チェック機構** —
  - 金額の桁数異常検知（前回の同一取引先との比較で±50%超は警告）
  - 消費税率の妥当性検証（品目に対する税率の適切性）
  - 取引先マスタとの突合（未登録取引先の検出）
- **サブエージェント構成** —
  - 抽出エージェント: 請求書データから構造化情報を抽出
  - 分類エージェント: 抽出情報を勘定科目に分類
  - メインオーケストレーター: ハーネスがライフサイクルを管理

### AIエージェント層

- **担当タスク（推論アップサイドが大きい部分）** —
  - 請求書の非定型レイアウトからの項目抽出（取引先名、日付、金額、明細行）
  - 取引内容の自然言語理解による勘定科目推定（「AWS 利用料」→通信費、「コピー用紙」→消耗品費）
  - 過去パターンとの類似度比較による異常取引検知
- **使用するツール/API** —
  - Claude API（claude-sonnet-4-20250514）: 自然言語理解、分類推論
  - 勘定科目マスタ（JSON）: 科目一覧と説明
  - 取引履歴ナレッジベース（JSON）: 過去の仕訳パターン
- **ヒューマン・イン・ザ・ループのトリガー条件** —
  - AI の信頼度スコアが 80%未満の場合
  - 過去に同一取引先で使われた勘定科目と異なる科目が推定された場合
  - 新規取引先（ナレッジベースに未登録）の場合
  - 金額が過去の同一取引先の平均から±50%以上乖離している場合

### 決定論的コード層

- **担当処理（ルールベースで確実に実行する部分）** —
  - 消費税計算: 税率テーブル × 税抜金額の確定計算（端数処理含む）
  - 仕訳の貸借バランス検証: 借方合計 === 貸方合計の厳密チェック
  - 仕訳データのフォーマット変換: 内部形式→会計ソフト連携用 JSON
  - 承認ワークフロー状態遷移: pending → approved / rejected / escalated
  - 日付妥当性チェック: 会計期間内か、請求日≦支払期日か

### ナレッジ自動改善ループ

1. **インプット（ユーザー行動/フィードバック）** — ユーザーが仕訳を修正した場合、修正前後のペアを記録。承認/却下のアクションもフィードバックとして記録。
2. **矛盾検知メカニズム** — 同一取引先に対して異なる勘定科目が使われた場合、既存ルールとの矛盾を検知。修正頻度が閾値を超えたパターンを「要見直しルール」としてフラグ。
3. **承認フロー** — 新規ルール提案をユーザーに提示し、「承認」「却下」「保留」の三択で判断を求める。自動適用はしない（ヒューマン・イン・ザ・ループ）。
4. **反映タイミング** — 承認されたルールは即座にナレッジベースへ追加。次回の同一の取引先処理から適用。

## MVP（プロトタイプ）スコープ

実装する機能は以下の 3 つに絞る。

1. **請求書データ抽出 & 仕訳生成パイプライン** — 請求書 JSON 入力→AI 抽出→勘定科目分類→仕訳生成の一連フロー
2. **ハーネスによるライフサイクル管理 & 品質チェック** — 各ステップのバリデーション、終了条件チェックリスト、ドリフト防止
3. **ナレッジ自動改善ループ** — 仕訳修正→ルール蓄積→改善提案→承認フロー

実装しない機能は以下のとおり（将来版）。
- 実際の OCR/PDF 解析（プロトタイプでは JSON 入力で代替）
- 会計ソフト API 連携（出力は JSON ファイル）
- マルチテナント対応
- Web UI ダッシュボード（CLI で代替）
- バッチ処理（1 件ずつ処理）
