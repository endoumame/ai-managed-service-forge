# InvoiceForge（インボイスフォージ）設計書

## エレベーターピッチ
受領した請求書を AI が読み取り、ハーネスが品質を保証しながら正確な仕訳候補を生成し、経理担当者の修正を学習して日々賢くなるインボイス自動仕訳マネージドサービス。

## ターゲットユーザー
- ペインポイント: 月に数十〜数百枚の請求書を手作業で仕訳しており、月末月初に経理担当者が残業を強いられる。インボイス制度対応で適格な請求書番号の確認作業も増加。
- 現在の解決方法: Excel 管理、会計ソフトへの手入力、一部 OCR ツールの利用（精度不足で結局手修正）
- 提供する価値: 仕訳作業時間を 90%削減し、経理担当者は「判断が必要なケース」のみに集中できる状態を実現

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック:
  - `beforeExtract`: 入力データの形式検証（PDF/画像/JSON）
  - `afterExtract`: 抽出結果の完全性チェック（必須フィールドが全て埋まっているか）
  - `beforeClassify`: 抽出データの型バリデーション
  - `afterClassify`: 仕訳候補の信頼度スコア確認
  - `beforeCommit`: 貸借一致・消費税整合性の最終チェック
- 終了条件管理:
  - 全必須フィールド抽出済み（取引先名、金額、日付、品目、インボイス番号）
  - 仕訳候補の信頼度が閾値（80%）以上
  - 貸借バランスが一致
  - インボイス番号の形式が正規表現で検証済み
- 品質チェック機構:
  - 同一取引先の過去仕訳との乖離度チェック（勘定科目が変わった場合アラート）
  - 金額の統計的な異常検知（過去平均の 3σ逸脱でフラグ）
  - 消費税率の妥当性検証（品目と税率の組み合わせチェック）
- サブエージェント構成:
  - ExtractorAgent: 請求書データの抽出特化
  - ClassifierAgent: 勘定科目の分類特化

### AIエージェント層
- 担当タスク（推論アップサイドが大きい部分）:
  - 非定形フォーマットの請求書からの情報抽出
  - 取引先名の名寄せ（「(株)ABC」「株式会社 ABC」「ABC Co.,Ltd.」の同一視）
  - 品目説明文からの勘定科目推定
  - 過去パターンに基づく仕訳候補の生成
- 使用するツール/API:
  - Claude API（テキスト理解・分類）
  - 将来: OCR API（画像→テキスト変換）
- ヒューマン・イン・ザ・ループのトリガー条件:
  - 信頼度スコアが 80%未満の仕訳候補
  - 新規取引先（過去パターンなし）の初回仕訳
  - 金額が過去平均の 3 倍を超える請求書
  - AI が複数の勘定科目で迷っている場合（上位 2 候補の差が 10%未満）

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）:
  - 消費税計算（税率 10%/8%/非課税の判定と計算）
  - インボイス番号の形式バリデーション（T+13 桁数字）
  - 仕訳の貸借バランスチェック（借方合計 = 貸方合計）
  - 支払期日のカレンダー計算（営業日考慮）
  - 重複請求書の検出（請求書番号×取引先×金額の一致）

### ナレッジ自動改善ループ
1. インプット（ユーザー行動/フィードバック）: 経理担当者が仕訳候補を修正・承認する行為そのもの
2. 矛盾検知メカニズム: 同一取引先×同一品目で異なる勘定科目が使われた場合に矛盾フラグを立てる
3. 承認フロー: 新ルール候補を経理担当者に提示し、明示的に「このルールを採用する」を確認
4. 反映タイミング: 承認後、仕訳ルール DB へ即座に追加。次回以降の同パターンに自動適用

## MVP（プロトタイプ）スコープ
以下の機能を実装します（3 つ以内に絞ること）。
1. 請求書データ抽出→仕訳候補生成パイプライン（ハーネスによるライフサイクル管理付き）
2. ヒューマン・イン・ザ・ループ承認フロー（信頼度ベースのエスカレーション）
3. ナレッジ自動改善ループ（修正→ルール提案→承認→反映）

以下の機能は将来版で実装します。
- OCR による画像/PDF 読み取り（プロトタイプでは JSON 入力）
- 会計ソフトとの API 連携（プロトタイプではファイル出力）
- マルチテナント対応
- バッチ処理（大量請求書の一括処理）
- ダッシュボード UI
