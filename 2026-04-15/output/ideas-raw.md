## アイデア 1: InvoiceForge — AI請求書仕訳オートパイロット

### ユーザーが本当に欲しいもの（業務の完成品）
「受領した請求書の画像/PDF を投げたら、正しい勘定科目で仕訳され、承認待ちキューに入り、承認後に会計ソフトへ自動連携される」という完成された業務フロー。経理担当者が仕訳作業から解放され、承認判断のみに集中できる状態。

### ハーネス設計のキモ
- **before-classify フック**: AI 仕訳分類の前に、過去の仕訳パターン DB を参照し、類似請求書の仕訳履歴をコンテキストとして注入
- **after-classify フック**: AI 分類結果を決定論的ルール（金額上限チェック、存在しない勘定科目の検出、前回と大幅に異なる仕訳の警告）でバリデーション
- **終了条件**: 全請求書が「分類済み」「承認済み」「連携済み」のいずれかのステータスになるまで完了としない（AI の自己申告不可）
- **品質チェック**: 仕訳金額の合計と請求書金額の一致確認、消費税計算の整合性チェック

### AIが担う部分
- 請求書からの情報抽出（取引先名、金額、日付、品目の自然言語理解）
- 勘定科目の推論（過去パターン＋品目内容からの分類）
- 異常請求書の検知（通常と大きく異なる金額、未知の取引先）

### 決定論的コードが担う部分
- 消費税の計算（税率 × 税抜金額）
- 仕訳データのフォーマット変換（CSV/API 形式への変換）
- 金額の整合性チェック（小計 + 税 = 合計）
- 重複請求書の検出（請求番号の照合）

### ナレッジ/データの自動改善ループ
- ユーザーが仕訳を修正した場合、「取引先×品目→勘定科目」のマッピングが自動で学習候補に追加
- 一定回数の同一修正パターンが蓄積されたら、自動でルール化を提案
- 承認率/修正率のメトリクスで仕訳精度を継続的に監視

### 内製との差別化ポイント
- 勘定科目の推論モデルは業界横断で学習データが蓄積されるため、単一企業の内製では得られない精度向上
- 税制改正（インボイス制度等）への対応をサービス側で一括アップデート
- AI モデルのバージョンアップに伴う再チューニングコストをサービス側で吸収

## アイデア 2: PayWatch — 支払期限アラート＆キャッシュフロー予測エンジン

### ユーザーが本当に欲しいもの（業務の完成品）
「今月・来月の支払予定が一覧化され、キャッシュフローへの影響が可視化され、支払い漏れが絶対に起きない」という安心感のある資金管理体制。

### ハーネス設計のキモ
- **daily-scan フック**: 毎日定時に未処理請求書をスキャンし、支払期限 7 日前/3 日前/当日のアラートを生成
- **終了条件**: 全請求書に支払予定日が設定され、かつ銀行残高シミュレーションが完了するまで
- **品質チェック**: 支払予定総額と銀行残高の比較、マイナス残高予測時の警告

### AIが担う部分
- 請求書からの支払条件読取（「月末締め翌月末払い」等の自然言語解析）
- キャッシュフロー異常パターンの検知（季節性を考慮した異常値検出）
- 支払優先順位の提案（取引関係の重要度判断）

### 決定論的コードが担う部分
- 支払期限の日付計算（営業日カレンダー考慮）
- キャッシュフローシミュレーション（入金予定 - 出金予定の時系列計算）
- アラート生成ルール（期限 N 日前の通知）

### ナレッジ/データの自動改善ループ
- 取引先ごとの支払条件パターンを蓄積し、新規請求書の支払条件を自動推測
- 実績データからキャッシュフロー予測の精度を継続改善
- 支払遅延リスクのスコアリングモデルを蓄積データで改善

### 内製との差別化ポイント
- 複数企業のキャッシュフローパターンから業界別の季節変動モデルを提供
- 銀行 API 連携の保守・セキュリティ管理をサービス側で担当
- 税理士/会計士との連携フォーマット標準化

## アイデア 3: ReceiptBridge — 経費精算レシート自動処理パイプライン

### ユーザーが本当に欲しいもの（業務の完成品）
「従業員がレシートの写真を撮るだけで、経費精算申請が自動作成され、上長承認後に会計処理まで完了する」というエンドツーエンドの経費精算体験。

### ハーネス設計のキモ
- **before-extract フック**: レシート画像の品質チェック（ぼやけ、切れ、反射の検出）→ 再撮影依頼
- **after-extract フック**: 抽出情報の妥当性チェック（日付が未来でないか、金額が経費規定の上限以内か）
- **終了条件**: 全レシートが「抽出完了」「規定チェック済み」「申請書生成済み」を全て満たすまで
- **品質チェック**: 経費規定との照合、同日同店舗の重複チェック

### AIが担う部分
- レシート OCR 結果の構造化（店名、日付、金額、品目の抽出）
- 経費カテゴリの推論（「タクシー代」→交通費、「懇親会」→交際費）
- 不正経費の疑い検知（パターン異常検出）

### 決定論的コードが担う部分
- 経費規定との照合（上限金額、対象カテゴリのルールチェック）
- 申請書フォーマット生成
- 承認フローのルーティング（金額帯による承認者の決定）

### ナレッジ/データの自動改善ループ
- ユーザーがカテゴリを修正するたびに、店名→カテゴリのマッピング精度が向上
- 経費規定の変更を検知し、チェックルールを自動更新提案
- 部門別の経費パターンを学習し、異常検知の閾値を自動調整

### 内製との差別化ポイント
- 多様なレシートフォーマット（コンビニ、飲食店、交通機関等）の読取精度を業界横断データで向上
- 経費規定テンプレートのライブラリ提供
- インボイス制度対応（適格請求書の要件チェック）をサービス側で最新化

## アイデア 4: VendorLedger — 取引先マスタ自動整備＆名寄せエンジン

### ユーザーが本当に欲しいもの（業務の完成品）
「請求書に記載された取引先情報が自動的にマスタと照合・更新され、表記揺れや重複のない正確な取引先データベースが維持される」という、データ品質が保証されたマスタ管理。

### ハーネス設計のキモ
- **on-new-vendor フック**: 新規取引先検出時に、既存マスタとの類似度チェックを実行し、名寄せ候補を提示
- **終了条件**: 全新規取引先が「既存マスタに紐付け済み」または「新規登録承認済み」になるまで
- **品質チェック**: 登記情報との照合、法人番号の有効性チェック

### AIが担う部分
- 取引先名の表記揺れ検出（「(株)ABC」と「株式会社エービーシー」の同定）
- 住所の正規化と照合
- 取引先カテゴリの推論（業種、取引内容の分類）

### 決定論的コードが担う部分
- 法人番号 API との照合
- 完全一致・部分一致のマッチングアルゴリズム
- マスタデータの CRUD 操作

### ナレッジ/データの自動改善ループ
- ユーザーが名寄せを承認/却下するたびに、類似度判定の閾値が改善
- 業界共通の表記揺れパターン辞書が蓄積
- 新規取引先の自動分類精度が使用量に比例して向上

### 内製との差別化ポイント
- 複数企業の名寄せ実績から構築された表記揺れ辞書
- 法人番号 API 連携の保守をサービス側で担当
- M&A・社名変更の追跡を自動化

## アイデア 5: AuditTrail — 月次決算チェックリスト自動実行エンジン

### ユーザーが本当に欲しいもの（業務の完成品）
「月次決算の締め作業で必要なチェック項目が自動実行され、異常があれば原因特定まで含めてレポートされ、経理マネージャーは最終確認のみで決算を締められる」という効率的な月次決算プロセス。

### ハーネス設計のキモ
- **checklist-runner フック**: 定義済みチェック項目を順次実行し、各項目の結果を記録
- **終了条件**: 全チェック項目が「合格」「要確認（人間判断待ち）」「是正済み」のいずれかになるまで
- **品質チェック**: 前月比の大幅変動検知、勘定科目残高の整合性確認

### AIが担う部分
- 異常値の原因推論（「売上が前月比 30%減 → 大口顧客 X の入金遅延が原因」）
- チェック結果の自然言語レポート生成
- 過去の決算パターンからの逸脱検知

### 決定論的コードが担う部分
- 勘定科目残高の集計・照合
- 前月比・前年同月比の計算
- チェックリストの進捗管理（完了率、未処理項目数）

### ナレッジ/データの自動改善ループ
- 毎月の異常原因と対処法の蓄積 → 同種の異常に対する自動対処提案
- チェック項目の追加・削除をユーザーの実績から提案
- 業界特有の決算パターン知識の蓄積

### 内製との差別化ポイント
- 業界別の決算チェックリストテンプレート提供
- 会計基準の変更への自動対応
- 監査法人が求めるエビデンス形式への自動整形
