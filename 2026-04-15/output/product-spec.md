# InvoiceForge — AI請求書仕訳オートパイロット 設計書

## エレベーターピッチ

請求書データを投入するだけで、AI が勘定科目を推論し、ハーネスが金額整合性と仕訳妥当性を検証し、人間の承認を経て会計データとして確定する――経理担当者を「仕訳作業者」から「承認判断者」に変える AI マネージドサービス。

## ターゲットユーザー

- **ペルソナ**: 中小企業（従業員 50〜300 名）の経理担当者。1〜3 名で経理業務全般を担当。
- **ペインポイント**:
  - 月に数十〜数百枚の請求書を手作業で仕訳している
  - 勘定科目の判断に迷う場面があり、過去の仕訳を都度検索している
  - 繁忙期（月末・四半期末）に業務が集中し、残業が常態化
  - 仕訳ミスが決算修正につながるリスクを常に抱えている
- **現在の解決方法**:
  - Excel や会計ソフトへの手入力
  - 簿記知識と経験に基づく勘定科目の判断
  - 上長や税理士への相談
- **提供する価値**:
  - 仕訳作業時間を 80%削減（手入力 → 承認のみ）
  - 過去パターンに基づく一貫した仕訳品質
  - ヒューマンエラーの大幅削減（金額整合性チェックの自動化）

## システムアーキテクチャ

### ハーネス層

AI エージェントを包み込み、品質と進捗を外部から制御する層。

- **ライフサイクルフック**:
  - `before-classify`: 過去の仕訳パターン DB からコンテキストを注入。同一取引先の過去仕訳、類似品目の仕訳履歴を AI に渡す
  - `after-classify`: 決定論的バリデーション実行。金額整合性、勘定科目存在チェック、前回仕訳との大幅乖離警告
  - `on-complete`: 全請求書の処理ステータスを集計し、未処理があれば再実行を指示
  - `on-approval`: 人間の承認/修正結果をナレッジストアにフィードバック

- **終了条件管理**:
  - チェックリスト方式で管理（AI に完了を自己申告させない）
  - 条件 1: 全請求書が `classified` ステータスになっている
  - 条件 2: 全仕訳が `validated` ステータスを通過している
  - 条件 3: 全仕訳が `approved` または `pending_approval` ステータスである
  - 条件 4: 金額合計の整合性チェックが通過している

- **品質チェック機構**:
  - 税込金額 = 税抜金額 + 消費税額の整合性
  - 勘定科目コードが科目マスタに存在するか
  - 仕訳金額が取引先の過去平均から 3σ以上乖離していないか
  - 同一請求書番号の重複処理チェック

- **サブエージェント構成**:
  - メインエージェント: 請求書解析＆仕訳分類
  - バリデータ: 分類結果の独立検証（メインエージェントとは別のプロンプトで検証）

### AIエージェント層

推論のアップサイドが大きく、ミスのダウンサイドが小さい（ハーネスが検知可能な）タスクを担当。

- **担当タスク**:
  - 請求書テキストからの構造化情報抽出（取引先名、金額、日付、品目）
  - 品目内容と過去パターンに基づく勘定科目の推論
  - 信頼度スコアの算出（低信頼度 → 人間確認へエスカレーション）
  - 異常請求書の検知と理由説明

- **使用するツール/API**:
  - Anthropic Claude API（claude-sonnet-4-20250514）: 自然言語理解＆分類
  - ナレッジストア API: 過去仕訳パターンの参照

- **ヒューマン・イン・ザ・ループのトリガー条件**:
  - AI 信頼度スコアが 80%未満の仕訳
  - 新規取引先からの初回請求書
  - 金額が過去平均から大幅に乖離している請求書
  - ナレッジストアに改善提案が蓄積された場合の承認依頼

### 決定論的コード層

ルールベースで確実に実行する処理。AI に任せない。

- **担当処理**:
  - 消費税計算（税率テーブル × 税抜金額、軽減税率対応）
  - 仕訳データのフォーマット変換（内部 JSON → CSV/会計ソフト形式）
  - 金額整合性チェック（小計 + 消費税 = 合計の検算）
  - 重複請求書検出（請求書番号の完全一致チェック）
  - 勘定科目コードの存在検証（マスタとの照合）
  - チェックリストの進捗管理

### ナレッジ自動改善ループ

1. **インプット（ユーザー行動/フィードバック）**:
   - ユーザーが仕訳の勘定科目を修正した場合、修正前後のデータを記録
   - 承認/却下の判断データ
   - 異常検知に対する「正常」判定のフィードバック

2. **矛盾検知メカニズム**:
   - 同一取引先×品目に対して異なる勘定科目が使われているケースを検出
   - 修正頻度が閾値を超えた分類パターンを検出
   - 新規パターン（既存ルールに該当しない分類）を検出

3. **承認フロー**:
   - 改善提案をキューに蓄積
   - 一定数の同一修正パターンが蓄積された時点で人間に提示
   - 承認された提案のみがルールとしてナレッジストアに反映

4. **反映タイミング**:
   - 即座反映: 個別の仕訳修正は次回の同一取引先処理から参照
   - バッチ反映: ルール化された改善提案は承認後に全体に適用

## MVP（プロトタイプ）スコープ

実装する機能（3 つに絞ること）:
1. **請求書データ → AI仕訳分類パイプライン**: JSON 請求書を AI で分類し、ハーネスがバリデーションする一連のフロー
2. **ヒューマン・イン・ザ・ループ承認フロー**: CLI での対話的な承認/修正インターフェース
3. **ナレッジ自動改善提案**: 修正データの蓄積と改善ルール提案の生成

実装しない機能（将来版）:
- OCR/画像からの請求書読取（プロトタイプでは JSON 入力）
- 会計ソフトとの API 連携
- Web ダッシュボード UI
- マルチテナント対応
- バッチ処理の並列化
- 監査ログの長期保存
