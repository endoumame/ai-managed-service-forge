# 新機能パッケージ製品アイデア レポート
日時: 2026-04-15
ターゲットドメイン: 経理・請求書処理

## 選定アイデア: InvoiceForge — AI請求書仕訳オートパイロット

### エレベーターピッチ
請求書データを投入するだけで、AI が勘定科目を推論し、ハーネスが金額整合性と仕訳妥当性を検証し、人間の承認を経て会計データとして確定する――経理担当者を「仕訳作業者」から「承認判断者」に変える AI マネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書仕訳は「AI の推論力が活きる部分」と「決定論的に検証すべき部分」が明確に分離できる理想的なドメインである。勘定科目の推論は品目内容の自然言語理解が必要で AI の得意領域だが、金額の整合性チェックや消費税計算は正解が一意に定まるためルールベースで確実に処理すべきである。この分離がハーネスの存在意義を最も明確に示す。さらに、仕訳処理は「途中で止めると帳簿が不整合になる」という特性があり、AI に自己完結させるとドリフト問題（途中完了宣言や品質の自己過信）のリスクが高い。ハーネスのチェックリスト方式による終了条件管理が不可欠であることを、プロトタイプで実証できた。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before-classify でのナレッジ注入、after-classify でのバリデーション）が、AI の分類精度向上と品質保証を両立できること
- 終了条件の外部管理（チェックリスト方式）により、AI が「完了」と自己申告できない設計が実現可能であること
- 重複請求書検知（同一請求書番号の 2 重処理警告）が決定論的コードで確実に動作すること
- ナレッジの自動改善ループ（ユーザー修正 → 蓄積 → 提案生成）の仕組みが、シンプルなデータフローで成立すること
- 信頼度スコアに基づくヒューマン・イン・ザ・ループ（高信頼度は自動承認、低信頼度は人間確認）が自然な UX として機能すること

### プロトタイプの起動方法
```bash
cd 2026-04-15/prototype
npm install
npm run demo          # 対話モード
npm run demo:auto     # 自動承認モード
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API 統合: 現在のキーワードルールベース分類を Claude API による自然言語分類に置き換え、ロングテールの品目にも対応
2. OCR/PDF 請求書対応: 画像・PDF の請求書を AI で構造化データに変換するパイプラインを追加
3. 会計ソフト連携: freee・マネーフォワード等の API と接続し、承認済み仕訳の自動連携を実装
4. Web ダッシュボード: Vue.js（既存の apps/web）を拡張し、承認フローとナレッジ管理の GUI を構築
5. マルチテナント化: 企業ごとのナレッジ分離とアクセス制御を実装

### 学んだこと / 気づき
- ハーネスの「門番」機能は、AI の出力品質が不安定な現段階でこそ価値が高い。モデルが進化しても、決定論的検証の安心感は経理業務では不可欠
- ナレッジの自動改善ループは「修正行動」という自然なフィードバック源があるため、ユーザーに追加の労力を求めずに実現できる
- 消費税計算や重複検知のような「正解が一意の処理」を AI に任せないことで、ハーネス層の検証ロジックがシンプルに保たれる
- 信頼度ベースの自動承認/人間確認の切り分けは、ユーザー体験と安全性のバランスとして有効
- プロトタイプの段階でも、三層分離アーキテクチャにより各層の責務が明確で、テストやデバッグがしやすかった
