# 新機能パッケージ製品アイデア レポート
日時: 2026-06-01
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceForge — AI請求書マッチング＆仕訳エンジン

### エレベーターピッチ
受領した請求書を自動で読み取り・発注照合・仕訳生成まで完了させ、経理担当者を「例外処理と最終承認だけ」に解放する AI マネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は「読み取り→照合→仕訳→承認」という明確なパイプラインを持っています。各ステップにハーネスのライフサイクルフックを自然に設置できます。AI が「読み取れたつもり」で誤データを後続処理に流すドリフト問題に対し、ハーネスの出力バリデーションで防止できます。終了条件を AI の自己申告ではなくチェックリストで外部管理し、処理の確実性を担保します。経理担当者の修正フィードバックが仕訳パターンとして蓄積され、自然に精度が向上するナレッジループも成立します。これらの仕組みはハーネスなしでの実現が困難であり、AI マネージドサービスのコンセプトを最も明確に体現できるアイデアです。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフックが各処理ステップの前後でバリデーションを実行し、異常を検知できること
- CompletionPlanner によるチェックリスト方式で、AI の自己完了宣言に頼らず処理進捗を外部管理できること
- 決定論的コード（税計算・仕訳ルール）と AI 推論（データ抽出・曖昧マッチング）の責務分離が機能すること
- フィードバック蓄積→改善提案生成のナレッジ自動改善ループの基本構造が動作すること
- 信頼度に基づくヒューマン・イン・ザ・ループの判定メカニズムが動作すること

### プロトタイプの起動方法
```bash
cd 2026-06-01/prototype
npm install
MOCK_AI=true npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API を使った実請求書データの抽出精度検証（PDF/画像 OCR 連携含む）
2. 発注書マスタとの照合ロジック改善（取引先名の表記ゆれ辞書の自動学習）
3. マルチテナント対応と Web ダッシュボード開発（承認フローの UI 化）

### 学んだこと / 気づき
- ハーネスの価値は「AI の出力を信頼しない」という設計思想に直結する。バリデーションフックがなければ、AI の誤抽出は後続処理へサイレントに伝播する
- 決定論的コード層の重要性は税計算で特に明確。消費税率の適用ミスは法的問題に直結するため、AI の推論に任せてはならない
- ナレッジ自動改善ループでは「改善提案→人間の承認→反映」のフローを設けて、AI 単独の暴走を防ぎつつ継続的な改善を実現できる
- モック抽出でも正規表現ベースの処理でかなりの精度が出るが、請求書フォーマットの多様性（「合計」vs「請求金額」等の表記ゆれ）に対応するには AI の自然言語理解が不可欠
