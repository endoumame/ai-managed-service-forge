# アイデア発散: 経理・請求書処理ドメイン

実行日: 2026-06-01。

## アイデア 1: InvoiceForge — AI請求書マッチング＆仕訳エンジン

### ユーザーが本当に欲しいもの（業務の完成品）
受領した請求書が自動的に発注データと照合され、勘定科目が割り当てられ、承認待ちの仕訳伝票として会計システムに投入される状態。経理担当者は例外処理と最終承認だけに集中できる。

### ハーネス設計のキモ
- ライフサイクルフック — 請求書読み取り後に「金額・日付・取引先」の構造化データバリデーション。仕訳生成後に「勘定科目の妥当性チェック」（過去の同一取引先の仕訳パターンとの一致率）
- 終了条件 —「全フィールド抽出完了」「照合率 95%以上」「仕訳候補の信頼度スコア 0.8 以上」を外部チェックリストで管理
- 品質チェック — 金額の桁数チェック、消費税率の整合性、発注書との金額差異アラート

### AIが担う部分
- 多様なフォーマットの請求書からのデータ抽出（OCR + NLP）
- 発注書との曖昧マッチング（品目名の表記ゆれ対応）
- 過去の仕訳パターンからの勘定科目推定

### 決定論的コードが担う部分
- 消費税計算（税率テーブルに基づく確定計算）
- 仕訳ルールの適用（勘定科目マスタとの照合）
- 電子帳簿・保存法の要件チェック（タイムスタンプ、原本保存）
- 金額照合（発注額との差異計算）

### ナレッジ/データの自動改善ループ
- 経理担当者が修正した仕訳パターンを蓄積 → 同一取引先の次回以降の仕訳精度が向上
- 表記ゆれの辞書が自動拡張（「㈱ABC」「(株)ABC」「ABC 株式会社」の同一化）
- 照合失敗パターンの学習 → マッチングルールの自動改善提案

### 内製との差別化ポイント
- 請求書フォーマットの多様性への対応は継続的な学習が必要で、内製では運用コストが膨大
- インボイス制度・電子帳簿・保存法の法改正追従をサービス側で吸収
- 複数企業のデータから学習したマッチングモデルの精度は単一企業では実現不可能

## アイデア 2: ExpenseGuard — 経費精算の異常検知＆自動承認サービス

### ユーザーが本当に欲しいもの（業務の完成品）
経費精算の申請内容が自動的にチェックされ、正常な申請は自動承認、疑わしい申請のみ管理者にエスカレーションされる状態。承認者の負担が 90%削減される。

### ハーネス設計のキモ
- ライフサイクルフック — 各申請チェック後に「異常スコア」と「該当ルール」を構造化ログに記録。バッチ完了後にサマリーレポート自動生成
- 終了条件 —「全申請のスコアリング完了」「エスカレーション対象の人間通知完了」「日次レポート出力完了」
- 品質チェック — 処理漏れチェック（受付数 = 処理数）、スコア分布の偏り検知

### AIが担う部分
- 領収書画像からの情報抽出
- 申請パターンの異常検知（時間・場所・金額の組み合わせ）
- 自然言語での申請理由の妥当性評価

### 決定論的コードが担う部分
- 社内規程に基づく金額上限チェック
- 重複申請検知（日付・金額・店舗の完全一致）
- 承認フローのルーティング（金額帯別の承認者マッピング）

### ナレッジ/データの自動改善ループ
- 管理者が「問題なし」と判断した申請パターンを学習 → 誤検知率の低下
- 新しい不正パターンの検出 → ルールベースへの変換提案
- 季節性のある経費パターン（忘年会シーズン等）の自動認識

### 内製との差別化ポイント
- 不正検知モデルの精度は多企業のデータがあるほど向上（ネットワーク効果）
- 社内規程の変更への追従をサービスとして吸収
- 承認フロー自体のベストプラクティスを提供

## アイデア 3: ReconcileBot — 銀行入出金の自動消込サービス

### ユーザーが本当に欲しいもの（業務の完成品）
銀行口座の入出金明細と売掛金/買掛金が自動的に消し込まれ、未消込の残高一覧が日次で経理担当者に提示される状態。月次決算の消込作業が数日から数時間に短縮される。

### ハーネス設計のキモ
- ライフサイクルフック — 各消込候補のペアリング後に「一致度スコア」と「消込根拠」を記録。バッチ完了後に未消込一覧の自動生成
- 終了条件 —「全入出金明細の処理完了」「消込率の目標値達成」「未消込アイテムの分類完了」
- 品質チェック — 消込後の残高整合性チェック、二重消込の検知

### AIが担う部分
- 振込名義と取引先名の曖昧マッチング
- 分割入金・合算入金の推定
- 入金遅延パターンの認識と予測

### 決定論的コードが担う部分
- 金額完全一致の自動消込
- 為替差損益の計算
- 残高検証（消込前後の整合性）
- 消込仕訳の自動生成

### ナレッジ/データの自動改善ループ
- 経理担当者の手動消込パターンを学習 → 同一取引先の次回・自動消込の率向上
- 振込名義の変換辞書を自動拡張
- 入金パターン（月末集中、分割払い等）の企業別プロファイル構築

### 内製との差別化ポイント
- 銀行 API との接続・維持をサービスで吸収
- 複数銀行のフォーマット差異への対応
- マッチングモデルの継続的改善（多企業データからの学習）

## アイデア 4: TaxDocPilot — 税務書類の自動生成＆整合性チェックサービス

### ユーザーが本当に欲しいもの（業務の完成品）
月次・四半期・年次の税務申告に必要な書類が、会計データから自動生成され、整合性チェック済みの状態で税理士または担当者に提示される。手動転記のミスがゼロになる。

### ハーネス設計のキモ
- ライフサイクルフック — 各書類生成後にクロスリファレンスチェック（別表間の数値整合性）。全書類生成後にパッケージ全体の整合性検証
- 終了条件 —「必要書類一覧の全生成完了」「クロスリファレンス差異ゼロ」「前期比較の異常値・確認完了」
- 品質チェック — 科目残高の前期比較、税率適用の正確性、申告期限との整合性

### AIが担う部分
- 勘定科目から税務区分への分類推定
- 前期比較での異常値の原因推定
- 税制改正の影響範囲の自然言語サマリー

### 決定論的コードが担う部分
- 税額計算（法定税率テーブルに基づく確定計算）
- 書類フォーマットへのデータマッピング
- クロスリファレンスの数値整合性チェック
- 申告期限のカレンダー管理

### ナレッジ/データの自動改善ループ
- 税理士の修正パターンを蓄積 → 分類精度の向上
- 税制改正情報の自動取り込みとルール更新提案
- 業種別の税務処理パターンのベストプラクティス蓄積

### 内製との差別化ポイント
- 税制改正への追従コストをサービスで吸収（毎年の法改正対応）
- 複数の申告書様式への対応
- 税務調査対応のためのエビデンス自動整理

## アイデア 5: PayableFlow — 支払サイクル最適化＆キャッシュフロー予測サービス

### ユーザーが本当に欲しいもの（業務の完成品）
未払い請求書の支払スケジュールが、キャッシュフロー予測に基づいて自動最適化され、「いつ・いくら・どの口座から支払うか」の計画が提示される状態。資金ショートのリスクが可視化され、早期警告が出る。

### ハーネス設計のキモ
- ライフサイクルフック — 支払計画・生成後に「資金残高シミュレーション」を自動実行。アラート条件への抵触チェック
- 終了条件 —「全未払い請求書の計画割当完了」「資金ショートリスク評価完了」「支払バッチファイル生成完了」
- 品質チェック — 支払予定額と口座残高の整合性、支払期限の遵守チェック、二重支払の検知

### AIが担う部分
- 入金予測（過去の入金パターンからの予測）
- 支払優先度の推定（取引先との関係性、遅延ペナルティの有無）
- キャッシュフロー異常の早期検知と原因分析

### 決定論的コードが担う部分
- 支払期限のカレンダー計算
- 銀行振込バッチファイルの生成（全銀フォーマット）
- 口座残高のシミュレーション計算
- 支払条件（月末締め翌月末払い等）の適用

### ナレッジ/データの自動改善ループ
- 実際の入金日と予測の差異を蓄積 → 予測モデルの精度向上
- 取引先別の支払パターンプロファイルの自動構築
- 季節性・業界トレンドの反映

### 内製との差別化ポイント
- キャッシュフロー予測モデルの精度は多企業データで向上
- 全銀フォーマット等の銀行接続仕様の維持
- 資金調達オプション（ファクタリング等）の自動提案
