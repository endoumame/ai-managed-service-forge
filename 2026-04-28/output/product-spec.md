# InvoiceForge 設計書

## エレベーターピッチ
InvoiceForge は、請求書を受け取るだけで正確な仕訳が切られ承認待ちキューに入る「経理業務の完成品」を提供する AI マネージドサービスです。

## ターゲットユーザー
- ペインポイント — 毎月数十〜数百枚の請求書を手作業で仕訳に起こしており、月末に残業が集中する。勘定科目の判断ミスで修正仕訳が発生し、二度手間になる。
- 現在の解決方法 — 会計ソフト（freee, マネーフォワード等）の OCR 機能を使っているが、勘定科目の推定精度が低く、結局手動修正が多い。あるいは、すべて手作業で処理している。
- 提供する価値 — 請求書投入 → 仕訳完了 → 承認待ちの全自動パイプライン。経理担当者は「確認・承認」だけのワークフローに移行できる。

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック
  - `before:extract` — 請求書解析前に仕入先マスタと過去仕訳履歴をコンテキストに注入
  - `after:extract` — 抽出結果のスキーマバリデーション（必須フィールドの存在確認）
  - `before:classify` — 勘定科目マスタと分類ルールを注入
  - `after:classify` — 推定された勘定科目が有効なコード体系内かチェック
  - `after:journalize` — 貸借一致の算術検証、税額の再計算検証
- 終了条件の管理
  - チェックリスト方式で管理（AI に完了判断させない）
  - [ ] 請求書情報の抽出完了（全必須フィールドが非 null）
  - [ ] 勘定科目の割当完了（全明細行に有効な科目コード）
  - [ ] 仕訳の貸借が一致し検証を通過
  - [ ] 税額の整合性の検証を通過
  - [ ] 承認ルーティング完了
- 品質チェックの機構
  - 貸借バランスの算術検証（借方合計 === 貸方合計）
  - 消費税額の再計算（税抜金額 × 税率と請求書に記載された税額の比較）
  - 信頼度スコアが閾値未満の場合はヒューマンレビューへ強制ルーティング
- サブエージェントの構成
  - 情報抽出エージェント — 請求書からの構造化データ抽出
  - 分類エージェント — 勘定科目推定
  - メインオーケストレーター — ハーネスが制御するパイプライン全体管理

### AI エージェント層
- 担当タスク（推論アップサイドが大きい部分）
  - 請求書の構造理解と情報抽出（多様なフォーマットへの対応）
  - 取引内容から勘定科目を推定（過去パターン + コンテキスト理解）
  - 異常検知（通常と異なる金額、新規取引先、重複請求の疑い）
  - 不明点の自然言語による質問生成（ヒューマン・イン・ザ・ループ用）
- 使用するツールと API
  - Claude API（claude-sonnet-4-20250514）— 情報抽出・分類・異常検知
  - JSON ファイルストレージ — 仕入先マスタ、勘定科目マスタ、過去仕訳履歴
- ヒューマン・イン・ザ・ループのトリガー条件
  - 信頼度スコアが 80%未満の勘定科目推定
  - 金額が 100 万円以上の請求書（高額閾値）
  - 新規取引先からの初回請求書
  - 異常検知フラグが立った場合

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）
  - 消費税額の計算（税率 × 税抜金額、端数処理ルール適用）
  - 貸借バランスの検証（借方合計 === 貸方合計の厳密一致）
  - 支払期日の算出（契約条件マスタの支払サイト日数を加算）
  - 仕訳データのフォーマット変換（内部 JSON → 会計ソフト取込形式）
  - 承認ルーティング（金額閾値に基づく承認者の決定論的割当）

### ナレッジ自動改善ループ
1. インプット（ユーザー行動やフィードバック）
   - 勘定科目の手動修正（AI 推定 → ユーザー修正の差分）
   - 承認/差戻しのアクションとその理由
   - 新規取引先の初回確定仕訳
2. 矛盾検知メカニズム
   - 同一取引先で異なる勘定科目が使われた場合にアラート
   - 過去 3 ヶ月の修正率が上昇傾向の場合にアラート
   - 新規ルールが既存ルールと矛盾する場合に検出
3. 承認フロー
   - 改善提案は「ドラフト」状態でキューに蓄積
   - 経理責任者が週次で確認し承認または却下
   - 承認後ルールベースへ反映
4. 反映タイミング
   - 即座反映 — 仕入先マスタの表記揺れ登録
   - 承認後反映 — 勘定科目の分類ルール変更
   - 月次反映 — 信頼度閾値の調整

## MVP（プロトタイプ）スコープ
実装する機能は以下の 3 つです。
1. 請求書→仕訳変換パイプライン — 請求書 JSON を入力し、ハーネス制御下で AI が情報抽出・勘定科目を推定し、決定論的コードが税額計算・貸借検証を行って仕訳 JSON を出力する
2. ナレッジ自動改善提案 — ユーザーが勘定科目を修正した際に、修正パターンを蓄積し「このルールを追加しますか」と改善提案を生成する
3. ヒューマン・イン・ザ・ループ承認フロー — 信頼度が低い仕訳や高額請求書を CLI で確認・承認・修正できるインタラクティブフロー

将来版で実装する機能は以下のとおりです。
- PDF/画像からの OCR（プロトタイプでは構造化 JSON を入力とする）
- 会計ソフトとの API 連携（CSV/JSON エクスポートまで）
- マルチテナント対応
- Web ダッシュボード（CLI のみ）
- 銀行明細との自動消込（ReconcileBot として将来統合予定）
