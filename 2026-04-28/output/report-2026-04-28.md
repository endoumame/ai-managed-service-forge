# 新機能パッケージ製品アイデア レポート
日時: 2026-04-28
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceForge — AI請求書仕訳オートパイロット

### エレベーターピッチ
InvoiceForge は、請求書を受け取るだけで正確な仕訳が切られ承認待ちキューに入る「経理業務の完成品」を提供する AI マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書の仕訳処理は「ハーネスなしでは成立しない」典型的なドメインです。AI に税額計算を任せると浮動小数点の誤差やハルシネーションで 1 円の不一致が生じえますが、経理業務では 1 円の誤差も許されません。この「AI の推論力は情報抽出に活かし、計算・検証は決定論的コードに任せる」という分離がハーネスの本質的価値を最も明確に示します。

さらに、金額閾値や信頼度スコアに基づくヒューマン・イン・ザ・ループの接点が自然に設計でき、「いつ人間が介入すべきか」をハーネスが決定論的に判断する構造が構築できる。ナレッジ改善ループも、ユーザーの勘定科目修正がそのまま学習データになるため、使えば使うほど賢くなるサービスモデルが成立する。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before/after）によるパイプライン制御
- 決定論的コードによる貸借一致検証・税額整合性チェック（AI の自己申告に頼らない品質保証）
- 信頼度スコアと金額閾値に基づくヒューマンレビューへの自動ルーティング
- 終了条件チェックリストによる外部管理（5 項目中 4 項目 PASS で「承認ルーティング未完了」を正しく検知）
- ナレッジ自動改善ループ: 2 回の修正操作から改善提案が自動生成され、承認待ちキューに入る

### プロトタイプの起動方法
```bash
cd 2026-04-28/prototype
pnpm install
pnpm demo
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API を使った実際の PDF/画像からの請求書の情報抽出エージェントの実装
2. Web ダッシュボード（承認フロー・改善提案レビュー画面）の構築
3. 会計ソフト（freee, マネーフォワード）へのエクスポート連携

### 学んだこと / 気づき
- ハーネスの価値は「AI が正しく動いている時」ではなく「AI が間違えた時」に発揮される。新規取引先の低信頼度仕訳が自動的にレビューキューに入る設計は、AI の失敗を前提としたアーキテクチャの好例
- 決定論的コードと AI の境界線は「数値の正確性が必要かどうか」で明確に引ける。税額計算は 1 円の誤差も許されないため決定論的、勘定科目の推定は「だいたい正しい」で十分なため AI 向き
- ナレッジ改善ループは「自動適用しない」ことが重要。提案を draft 状態で人間の承認を待つ設計にしないと、誤った修正パターンが汚染源になるリスクがある
