# InvoiceForge - AI請求書仕訳オートパイロット プロトタイプ

請求書を受け取るだけで正確な仕訳が切られ承認待ちキューに入る「経理業務の完成品」を提供する AI マネージドサービスのプロトタイプ。

## アーキテクチャ

```
harness/          ← ハーネス層（ライフサイクル管理・品質チェック・終了条件）
  lifecycle.ts       Before/Afterフックでパイプライン全体を制御
  checker.ts         貸借一致・税額整合性・勘定科目有効性を決定論的に検証
  planner.ts         終了条件チェックリスト（AIに自己申告させない）

agent/            ← AIエージェント層（情報抽出・分類・異常検知）
  index.ts           仕入先マスタと過去履歴から勘定科目を推定

deterministic/    ← 決定論的コード層（ルールベース処理）
  rules.ts           税額計算・貸借バランス検証・承認ルーティング

knowledge/        ← ナレッジ管理層
  store.ts           インメモリストア（仕入先・勘定科目・修正履歴）
  improver.ts        修正パターンから改善提案を自動生成

demo/             ← デモ
  run.ts             エントリポイント
  sample-data.ts     3種類のサンプル請求書
```

## セットアップ

```bash
cd 2026-04-28/prototype
pnpm install
```

## デモ実行

```bash
pnpm demo
```

デモでは以下の 3 シナリオを処理します。

1. **既知取引先の請求書** - 仕入先マスタから高信頼度で自動仕訳
2. **新規取引先の請求書** - 低信頼度でヒューマンレビューにルーティング
3. **高額請求書** - 金額閾値超過で自動的にレビュー対象化

最後にナレッジ自動改善ループのデモとして、ユーザーの修正操作から改善提案が生成される流れを実演します。

## 設計上の重要ポイント

### AIに任せないもの（決定論的コードが担保）
- 税額計算（`roundYen(amount * taxRate)`）
- 貸借バランス検証（`totalDebit === totalCredit`）
- 承認ルーティング（金額閾値・信頼度閾値による判定）

### AIに任せるもの（推論のアップサイドが大きい部分）
- 請求書からの情報抽出・構造理解
- 仕入先名の表記揺れマッチング
- 勘定科目の推定（過去パターン + コンテキスト理解）
- 異常検知（新規取引先・通常と異なるパターン）

### ドリフト対策
- 終了条件をハーネスのチェックリストで外部から管理
- 各ステップ完了後にフックで外部バリデーション
- AI の信頼度が閾値未満なら自動的にヒューマンレビューへ
