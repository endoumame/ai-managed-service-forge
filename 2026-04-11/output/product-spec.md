# InvoiceForge 設計書

## エレベーターピッチ

受領した請求書を投入するだけで、AI が情報を抽出し、ハーネスが決定論的に検算・仕訳ルールを適用し、人間は例外確認だけで仕訳データを完成させるマネージドサービス。

## ターゲットユーザー

- ペインポイント — 毎月数十〜数百枚の請求書を手作業で仕訳入力。フォーマットがバラバラで自動化できず、繁忙期には残業が常態化。AI ツールを試しても読取ミスの確認作業が結局手間。
- 現在の解決方法 — 経理担当者が 1 枚ずつ目視で確認→手入力。または市販 OCR ツール＋手動修正。
- 提供する価値 — 仕訳作業の 80%以上を自動化し、人間は例外ケース（新規取引先・異常金額）の確認に集中できる。使うほどルールの蓄積で精度が向上する自己改善型サービス。

## システムアーキテクチャ

### ハーネス層

- ライフサイクルフック
  - `beforeExtract`: 請求書入力の形式バリデーション（必須フィールドの存在確認）
  - `afterExtract`: AI 抽出結果の整合チェック（小計＋消費税＝合計の検算）
  - `beforeClassify`: 仕訳ルールテーブルの参照・適用
  - `afterClassify`: 過去パターンとの乖離チェック（前月比±30%超で警告フラグ）
  - `beforeFinalize`: 全仕訳の最終バリデーション
- 終了条件管理
  - チェックリスト方式（AI の自己申告ではなく外部ファイルで管理）
    1. [ ] 全請求書の情報抽出が完了している
    2. [ ] 金額整合チェックがすべてパスしている
    3. [ ] 全仕訳に勘定科目が割り当てられている
    4. [ ] 警告フラグ付き仕訳がすべて人間確認済みである
    5. [ ] 出力フォーマットのバリデーションがパスしている
- 品質チェック機構
  - 金額検算（決定論的: 税率×税抜金額 vs AI 読取の税額）
  - 取引先名の正規化チェック（マスタとのファジーマッチ→不一致で人間確認）
  - 重複請求検知（同一取引先×同一金額×近接日付）
- サブエージェント構成
  - ExtractorAgent: 請求書からの情報抽出（AI）
  - ClassifierAgent: 勘定科目の推定（AI＋ルール併用）
  - Orchestrator: ハーネス本体（決定論的コード）

### AIエージェント層

- 担当タスク（推論アップサイドが大きい部分）
  - 非定型フォーマット請求書からの構造化データ抽出
  - 取引先名の表記ゆれ解決（「(株)ABC」「ABC 株式会社」→同一取引先と推定）
  - 新規取引先の勘定科目推定（過去の類似パターンから提案）
  - 異常検知（請求金額の急変、重複請求の可能性）
- 使用するツール/API
  - Claude API（claude-sonnet-4-20250514）: テキスト解析・分類
  - 構造化出力（JSON mode）: 抽出結果の型安全な取得
- ヒューマン・イン・ザ・ループのトリガー条件
  - AI 信頼度が閾値（80%）未満の場合
  - 新規取引先の初回仕訳
  - 金額整合チェックが不一致の場合
  - 過去パターンとの乖離が閾値超えの場合

### 決定論的コード層

- 担当処理（ルールベースで確実に実行する部分）
  - 消費税の検算（税率マスタ × 税抜金額）
  - 仕訳ルールテーブルの参照・適用（取引先 ID × 品目 → 勘定科目）
  - 支払期日の算出（取引先別の支払条件マスタ参照）
  - 出力フォーマット変換（仕訳データ → CSV/JSON）
  - 重複チェック（完全一致キーによる高速照合）

### ナレッジ自動改善ループ

1. **インプット（ユーザー行動/フィードバック）**:
   - 人間が仕訳を修正した内容（勘定科目の変更、金額の修正）
   - 承認/却下のアクション
   - 新規取引先の初回確定仕訳

2. **矛盾検知メカニズム**:
   - 同一取引先に対して異なる勘定科目が 3 回以上使われた場合に「ルール曖昧」フラグ
   - 修正率が一定閾値を超えた取引先パターンに対するアラート

3. **承認フロー**:
   - 自動改善提案をナレッジ更新候補としてキューイング
   - 経理責任者が承認した候補のみルールテーブルに反映
   - 「3 回連続で同じ修正」→自動ルール昇格提案

4. **反映タイミング**:
   - 承認済み改善はルールテーブルへ即座に反映
   - 月次で「改善レポート」を生成（ルール追加数、精度向上率）

## MVP（プロトタイプ）スコープ

以下の 3 つの機能を実装します。
1. 請求書の情報抽出パイプライン — JSON 形式の請求書データを AI が解析し、構造化データに変換。ハーネスが金額整合チェックを実行。
2. 仕訳ルール適用エンジン — 取引先×品目→勘定科目のルールテーブルを持ち、決定論的にマッチング。未知パターンは AI が推定し、人間確認を要求。
3. ナレッジ自動改善ループ — 人間による仕訳修正を蓄積し、一定条件でルールテーブル更新を提案。承認フロー付き。

以下の機能は将来版で対応します。
- OCR/画像からの請求書読取（プロトタイプでは JSON 入力）
- 会計システムとの API 連携
- マルチテナント対応
- Web ダッシュボード（プロトタイプは CLI）
- 銀行口座との消込連携
