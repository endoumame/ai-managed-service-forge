# 新機能パッケージ製品アイデア レポート
日時: 2026-04-11
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceForge — 受領請求書の自動仕訳マネージドサービス

### エレベーターピッチ
受領した請求書を投入するだけで、AI が情報を抽出し、ハーネスが決定論的に検算・仕訳ルールを適用し、人間は例外確認だけで仕訳データを完成させるマネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理では「1 円の誤差も許されない」という厳格な正確性が求められる。AI エージェント単体では金額の読み間違いや勘定科目の誤分類が避けられないが、ハーネスが各ステップの前後に決定論的な検算（小計＋税＝合計）を挟むことで、AI のドリフトをステップ単位で捕捉できる。また、終了条件を AI の自己申告ではなくチェックリスト方式で外部管理することで、「途中完了宣言」というドリフトの典型パターンを構造的に防止できる。さらに、仕訳修正のフィードバックが自然にルールテーブル更新に繋がるため、「使うほど賢くなる」自己改善ループが最も明確に成立するドメインです。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック 4 種（beforeExtract、afterExtract、afterClassify、beforeFinalize）で各ステップの品質をゲートとして保証する仕組み
- 終了条件チェックリストにより、flagged 仕訳が残っている限り「未完了」と判定される外部管理の動作
- 3 回の同一修正パターンからルール昇格提案が自動生成されるナレッジ改善ループ
- 未知の取引先（INV-2026-004）が flagged ステータスとなり、人間の承認を経て approved に遷移するヒューマン・イン・ザ・ループの動作
- 金額整合チェック（決定論的検算）による、AI の品質自己過信を防ぐドリフト対策

### プロトタイプの起動方法
```bash
cd 2026-04-11/prototype
npm install
npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API 連携の実装（現在はモックモード）。非定型フォーマット請求書の PDF/画像からの情報抽出を AI で実行し、ハーネスの検算と組み合わせる
2. Web ダッシュボードの構築。flagged 仕訳の承認/却下 UI、ナレッジ改善提案の承認 UI、仕訳結果の一覧表示を提供する
3. 会計システム連携（freee / マネーフォワード等）。仕訳データの CSV/API 出力とインポート機能を実装し、エンドツーエンドの自動化を実現する

### 学んだこと / 気づき
- ハーネスの価値は「AI の出力を信用しない」という設計姿勢に集約される。経理ドメインでは特にこの姿勢が重要
- 終了条件の外部管理は実装コストが低いにもかかわらず、ドリフト防止効果が高い。チェックリスト 1 つで「AI の途中完了宣言」を構造的に防止できる
- 自己改善ループの設計では「提案→承認→反映」の 3 ステップが必須。自動反映はリスクが高く、ヒューマン・イン・ザ・ループとの整合が取れない
- 厳格なリントルール（max-statements: 10, no-magic-numbers, func-style: expression）環境での開発は、結果的にコードの品質を高めた。関数の責務分離が強制されることで、テスタビリティも向上する
