# アイデア発散: 経理・請求書処理ドメイン

日時: 2026-04-11。

## アイデア 1: InvoiceForge — 受領請求書の自動仕訳マネージドサービス

### ユーザーが本当に欲しいもの（業務の完成品）
「受け取った請求書を渡すだけで、正しい勘定科目・部門・税区分の割り当て済み仕訳データが会計システムに連携される」状態。経理担当者は例外ケースの確認だけに集中できる。

### ハーネス設計のキモ
- ライフサイクルフック — 請求書読取後に「金額整合チェック」（小計＋税＝合計の検算）を決定論的に実行
- 終了条件 — 全仕訳が「確認済み」ステータスになるまで完了としない（AI 自己申告禁止）
- 品質チェック — 過去の同一取引先の仕訳との乖離検知（前月比±30%超で警告）

### AIが担う部分（推論のアップサイドが大きく、ミスのダウンサイドが小さい部分）
- 非定型フォーマット請求書からの情報抽出（取引先名、品目、金額、日付）
- 過去パターンからの勘定科目推定（提案として提示、最終決定は人間）
- 請求書の異常検知（重複請求、金額の急変）

### 決定論的コードが担う部分
- 消費税計算（税率×税抜金額の検算）
- 仕訳ルールの適用（取引先×品目→勘定科目のマッピングテーブル）
- 支払期日の算出（取引先ごとの支払条件マスタ参照）
- 会計システムへの CSV/API 出力フォーマット変換

### ナレッジ/データの自動改善ループ
- ユーザーが仕訳を修正するたびに、取引先×品目→勘定科目マッピングが更新される
- 新規取引先パターンの自動学習（3 回同じ仕訳が確認されたらルールに昇格）
- 月次で「ルール適用率」「例外率」を可視化し、改善傾向を確認可能

### 内製との差別化ポイント
- OCR エンジン＋AI モデルの継続的アップデートが不要（モデル進化に自動追従）
- 業界横断で蓄積された仕訳パターンナレッジを共有基盤として活用
- 初期セットアップ時に既存仕訳データから自動でルール生成（コールドスタート問題の解消）

## アイデア 2: PaymentGuard — 支払承認ワークフロー自動化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「請求書に基づく支払が、金額帯別の承認フローを経て、正確な金額で正しい口座に実行される」状態。二重支払・過払い・不正支払を防ぎつつ、支払遅延を最小化する。

### ハーネス設計のキモ
- ライフサイクルフック — 支払実行前に「発注書照合」「予算残高チェック」をゲートとして挿入
- 終了条件 —「承認完了」「口座情報の照合完了」「予算枠の確認完了」の 3 条件すべてが OK になるまで支払実行をブロック
- 品質チェック — 口座番号の変更検知（取引先マスタとの差異アラート）

### AIが担う部分
- 請求書と発注書の突合（非定型フォーマット間のマッチング）
- 支払優先度の推定（キャッシュフロー予測に基づく支払スケジューリング提案）
- 不正パターンの検知（取引先口座の急な変更、通常と異なる金額パターン）

### 決定論的コードが担う部分
- 承認ワークフローのルーティング（金額帯別の承認者決定）
- 予算残高の計算と比較
- 支払実行のバッチ処理（銀行 API 連携のフォーマット変換）

### ナレッジ/データの自動改善ループ
- 承認却下理由の蓄積→同パターンの事前警告
- 支払遅延ケースの分析→早期アラート条件の自動調整
- 不正検知パターンの継続更新

### 内製との差別化ポイント
- 不正検知パターンの DB 構築・維持コストを複数社で按分
- 銀行 API 連携のメンテナンスをサービス側で吸収
- 規制変更（インボイス制度等）への対応を自動配信

## アイデア 3: ExpenseAI — 経費精算の完全自動化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「従業員がレシートを撮影するだけで、経費精算書が自動作成され、規程チェック済みの状態で承認者に回付される」状態。経理部門は月末の突合作業から解放される。

### ハーネス設計のキモ
- ライフサイクルフック — レシート読取後に「社内規程チェック」（上限金額、対象費目、必要添付書類）を自動実行
- 終了条件 —「規程準拠チェック完了」「領収書の原本照合完了」「仕訳連携完了」の全条件充足
- 品質チェック — レシート画像の鮮明度チェック、日付整合性（申請日 vs 利用日）

### AIが担う部分
- レシートからの情報抽出（店名、金額、日付、品目の推定）
- 費目の自動分類（飲食→交際費 or 会議費の判定）
- 不正申請パターンの検知（同日同店舗の重複、上限ギリギリの分割申請）

### 決定論的コードが担う部分
- 社内経費規程のルールチェック（金額上限、事前申請要否）
- 承認フローのルーティング
- 仕訳データの生成と会計システム連携

### ナレッジ/データの自動改善ループ
- 差し戻し理由の蓄積→申請時の事前警告
- 費目分類の修正履歴→分類精度の向上
- 季節・イベント別の経費パターン学習

### 内製との差別化ポイント
- 多様なレシートフォーマットの読取精度を継続改善
- 経費規程テンプレートのベストプラクティス提供
- インボイス制度・電帳法対応の自動アップデート

## アイデア 4: ReconcileBot — 銀行口座の自動消込サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「銀行口座の入出金明細と帳簿上の債権・債務が自動的に照合され、未消込の差異だけが経理担当者にエスカレーションされる」状態。月次決算の消込作業が数日→数分に短縮される。

### ハーネス設計のキモ
- ライフサイクルフック — 消込処理後に「残高整合チェック」（帳簿残高と銀行残高の一致確認）
- 終了条件 —「全明細が消込済み or エスカレーション済み」「残高差異ゼロ or 差異の理由を記録済み」
- 品質チェック — 消込率（前月比で急低下していないか）、大口取引の個別確認フラグ

### AIが担う部分
- 銀行明細の摘要テキストと売掛先・買掛先のファジーマッチング
- 分割入金・合算入金の推定（1 請求に対する複数入金の対応付け）
- 異常パターンの検知（未入金の長期化、二重入金）

### 決定論的コードが担う部分
- 金額完全一致による自動消込
- 残高計算と差異集計
- 消込結果の仕訳生成

### ナレッジ/データの自動改善ループ
- 手動消込パターンの学習（同一取引先の入金パターン蓄積）
- 消込ルールの自動生成（3 回連続で同じ手動消込→ルール提案）
- 取引先別の入金傾向分析（遅延予測）

### 内製との差別化ポイント
- 複数銀行 API/CSV フォーマットの差異吸収を一元化
- マルチテナントでの消込パターンナレッジの蓄積
- 決算期の負荷ピークに対するスケーラブルな処理能力

## アイデア 5: InvoiceAudit — 請求書発行の自動品質保証サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「売上データから請求書が自動生成され、法的要件・取引先ごとの固有要件を満たした品質保証済みの状態で送付される」状態。請求漏れ・金額ミス・送付遅延ゼロを実現する。

### ハーネス設計のキモ
- ライフサイクルフック — 請求書生成後に「法的要件チェック」（インボイス制度準拠、適格請求書の番号記載）を必ず実行
- 終了条件 —「全請求書が品質チェック通過」「送付確認完了」「売上帳簿との整合確認完了」
- 品質チェック — 前月比の請求総額チェック、宛名・住所の変更検知、単価マスタとの乖離検知

### AIが担う部分
- 契約書からの請求条件の自動抽出（自然言語理解）
- 請求書テンプレートの取引先別の最適化提案
- 請求漏れの検知（契約一覧 vs 請求実績の突合で未請求を発見）

### 決定論的コードが担う部分
- 売上データからの請求金額算出
- 消費税・源泉税の計算
- インボイス制度の法的要件チェック（登録番号、税率別記載）
- PDF 生成と送付処理

### ナレッジ/データの自動改善ループ
- 取引先からの問い合わせ・修正依頼の蓄積→同パターンの事前防止
- 請求条件の変更履歴管理→契約更新時の自動反映
- 業界別の請求書ベストプラクティス更新

### 内製との差別化ポイント
- インボイス制度・電帳法の法改正に自動追従
- 多様な送付方法（メール・郵送・EDI）の一元管理
- 取引先別のフォーマット要件対応をサービス側で吸収
