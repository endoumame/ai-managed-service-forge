# セキュリティ監査ドメイン — アイデア発散

日時: 2026-04-16。

## アイデア 1: CloudConfig Guardian — クラウド設定ドリフト検知＆自動修復サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「自社のクラウド環境（AWS/GCP/Azure）が、セキュリティベストプラクティスおよび社内ポリシーから逸脱していないことを継続的に保証された状態」。月次のセキュリティレポートではなく、リアルタイムに設定ドリフトを検知し、修復提案まで含めた"安心の完成品"が欲しい。

### ハーネス設計のキモ
- ライフサイクルフック — 各クラウド API コール前にレートリミットチェック、コール後に結果の正規化＆異常値フラグ付与
- 終了条件 —「全リソースタイプをスキャン完了」「重大度 High 以上の検出項目すべてにトリアージ結果が付与」をチェックリストで管理
- 品質チェック — 検出結果の偽陽性率を過去データと比較し、異常に高い/低い場合はアラート

### AIが担う部分
- 設定値の「文脈依存リスク評価」（同じ設定でも用途によってリスクが変わる）
- 修復提案の自然言語生成（技術者以外にも理解可能なレポート）
- 新しい脅威パターンの類推（既知パターンからの外挿）

### 決定論的コードが担う部分
- クラウド API 呼び出しとレスポンスのパース
- CIS Benchmark など既知ルールセットとの照合
- レポートのフォーマット変換（JSON→PDF/HTML）
- スケジューリングと通知ディスパッチ

### ナレッジ/データの自動改善ループ
- ユーザーが「誤検知」とマークした項目をナレッジベースに蓄積 → 同類パターンの検知精度向上
- 修復提案の採用/却下率を追跡 → 提案の質を改善
- 新たに公開された CVE と自社設定の自動マッチング

### 内製との差別化ポイント
- CIS Benchmark 等のルールセット更新を常に最新に維持するのは高コスト
- マルチクラウド対応の抽象化レイヤーの構築・維持は共通業務
- 誤検知データの集合知（複数顧客のフィードバックで精度向上）

## アイデア 2: AuditTrail Sentinel — アクセスログ異常検知＆インシデント初動サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「社内システムのアクセスログから異常なアクセスパターンを自動検知し、インシデントの初動対応（影響範囲特定、関係者通知、一次遮断判断の提案）まで完了した状態」。SOC チームの 24/7 体制を内製するのは中小企業にとって非現実的。

### ハーネス設計のキモ
- ライフサイクルフック — ログ取り込みバッチ完了後に必ず統計的ベースラインと比較し、AI 分析後に誤検知フィルターを適用
- 終了条件 —「未処理アラート数がゼロ」「各アラートに重大度ラベルと対応ステータスが付与済み」
- 品質チェック — アラート疲れ防止のため、直近 1 週間のアラート数が閾値を超えた場合にチューニング提案

### AIが担う部分
- 正常/異常パターンの文脈判断（深夜アクセスでも海外出張中なら正常、等）
- 複数ログソースの相関分析（VPN ログ＋アプリログ＋メールログの横断分析）
- インシデントレポートの自然言語生成

### 決定論的コードが担う部分
- ログの正規化・パース（各種フォーマット→統一スキーマ）
- 統計的ベースライン計算（移動平均、標準偏差）
- ルールベースの既知攻撃パターンマッチング（Sigma Rules など）
- 通知ディスパッチ（Slack/Email/PagerDuty）

### ナレッジ/データの自動改善ループ
- 「誤検知」「見逃し」のフィードバックを蓄積 → 異常検知モデルの閾値調整
- インシデント対応のプレイブック化 → 類似インシデント発生時の初動における自動化率の向上
- 業界固有の攻撃パターンを匿名化した上で横展開

### 内製との差別化ポイント
- SOC の 24/7 体制は人件費が最も高いセキュリティコスト
- Sigma Rules 等の検知ルールの継続的メンテナンスはコモディティ業務
- 複数顧客の匿名化パターンデータによる検知精度の向上

## アイデア 3: PolicyForge — セキュリティポリシー自動生成＆コンプライアンス追跡サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「ISMS/SOC2/PCI DSS 等の規格に準拠したセキュリティポリシー文書一式が、自社の実態に合わせてカスタマイズされ、技術的対策の実装状況と紐付けて追跡可能な状態」。コンサル費用を払って作った文書が棚の上で埃をかぶる問題を解消したい。

### ハーネス設計のキモ
- ライフサイクルフック — ポリシー文書生成後に必ず規格要件との突合チェック（カバレッジ検証）、技術実装とのギャップ分析
- 終了条件 —「規格の全要件項目にポリシー条項がマッピング済み」「ギャップ項目に対応計画が記載済み」
- 品質チェック — 生成されたポリシー文書の読みやすさスコア（Flesch-Kincaid 相当）チェック

### AIが担う部分
- 規格要件の自然言語理解と自社コンテキストへの適用
- ポリシー文書の自然言語生成（法務レビューに耐える品質）
- 技術実装との自然言語ベースのギャップ分析

### 決定論的コードが担う部分
- 規格要件マスターデータの管理（ISO 27001 Annex A 等の項目リスト）
- カバレッジマトリクスの計算と可視化
- 文書バージョン管理と diff 表示
- 定期レビュースケジュール管理

### ナレッジ/データの自動改善ループ
- 監査指摘事項のフィードバック → ポリシー文言の改善
- 規格改訂への自動追従と差分通知
- 業界別テンプレートの充実（類似企業のパターン蓄積）

### 内製との差別化ポイント
- セキュリティコンサルタントの費用（1 プロジェクト数百万円〜）を削減可能
- 規格改訂への追従は専門知識が必要なコモディティ業務
- 文書と実態の乖離を継続的に監視する仕組みは内製では優先度が下がりがち

## アイデア 4: DepShield — 依存パッケージ脆弱性トリアージ＆修復PRサービス

### ユーザーが本当に欲しいもの（業務の完成品）
「依存パッケージの脆弱性アラートに対して、自社コードベースへの実際の影響度を評価し、安全なアップデート PR が自動生成され、破壊的変更がある場合はマイグレーションガイド付きで提示された状態」。Dependabot のアラート地獄から解放されたい。

### ハーネス設計のキモ
- ライフサイクルフック — 脆弱性スキャン後に「到達の可能性」を必ず分析し（脆弱なコードパスが実際に呼ばれるか）、PR 生成後にテストスイートを実行
- 終了条件 —「全 Critical/High 脆弱性にトリアージ結果が付与」「生成 PR のテストが全パス」
- 品質チェック — 生成された PR の diff サイズが閾値を超えた場合は分割提案、テストカバレッジ低下検知

### AIが担う部分
- 脆弱性の自社コードベースへの影響度分析（コードパス分析＋コンテキスト判断）
- 破壊的変更時のマイグレーションコード生成
- トリアージレポートの自然言語生成

### 決定論的コードが担う部分
- 依存関係ツリーの解析（lockfile パース）
- CVE データベースとの照合
- SemVer に基づく互換性チェック
- テスト実行とカバレッジ計算
- PR 生成の Git 操作

### ナレッジ/データの自動改善ループ
- ユーザーの PR 承認/却下データから、許容されるアップデート範囲を学習
- 「影響なし」判定の精度向上（実際にインシデントにつながったかの追跡）
- パッケージ別の信頼性スコア蓄積

### 内製との差別化ポイント
- Dependabot の「脆弱性アラート数百件放置」問題は極めて一般的
- 到達の可能性を分析するには高度な静的解析能力が必要であり、内製ハードルが高い
- マルチ言語・マルチフレームワーク対応の維持はコモディティ

## アイデア 5: SecretSweep — シークレット漏洩検知＆ローテーション支援サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「コードリポジトリ、設定ファイル、CI/CD パイプライン、チャットログに含まれるシークレット（API キー、パスワード等）の漏洩を検知し、影響範囲を特定し、ローテーション手順が提示された状態」。
GitGuardian のアラートを受けてからの対応ではなく、先回り型のシークレット管理を実現する。

### ハーネス設計のキモ
- ライフサイクルフック — スキャン後に「正規表現マッチ→エントロピー分析→コンテキスト判定」の 3 段階フィルタリング、検知後に自動で関連サービスの影響範囲調査
- 終了条件 —「全スキャン対象をカバー」「検知項目すべてに真陽性/偽陽性ラベルが付与」「真陽性項目にローテーション状態が記録」
- 品質チェック — 偽陽性率の監視、スキャンカバレッジの完全性チェック

### AIが担う部分
- コンテキスト依存の真陽性/偽陽性判定（テストデータ vs 本番キー、コメント内のサンプル vs ハードコード）
- シークレットの種類推定（どのサービスの API キーか）
- ローテーション手順の自然言語生成（サービス固有の手順）

### 決定論的コードが担う部分
- 正規表現による高速パターンマッチ
- エントロピー計算によるランダム文字列検出
- Git ヒストリー走査（過去コミットの洗い出し）
- シークレットマネージャー（Vault/AWS Secrets Manager 等）との連携

### ナレッジ/データの自動改善ループ
- 偽陽性パターンの学習 → 検知精度向上
- 新しいシークレット形式のパターン追加（新サービスの API キー形式等）
- ローテーション手順テンプレートの充実

### 内製との差別化ポイント
- シークレットパターンの継続的な追加・更新はコモディティ
- マルチソース（Git/Slack/Confluence 等）横断スキャンの構築・維持は高コスト
- シークレット漏洩の発生頻度は低いものの影響が甚大 → 専門サービスの経済合理性が高い
