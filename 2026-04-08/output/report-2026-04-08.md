# 新機能パッケージ製品アイデア レポート
日時: 2026-04-08
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoicePilot

### エレベーターピッチ
InvoicePilot は、請求書の受領から仕訳起票・承認までを AI ハーネスが自動制御し、経理担当者を「手入力作業者」から「承認者」に変える AI マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
5 つの候補アイデアの中で、InvoicePilot が全評価軸で満点（25/25 点）を獲得しました。特にハーネスの価値が最も明確に発揮される点が決め手です。請求書処理では「AI が抽出した金額が本当に正しいか」を決定論的に検証する仕組みが不可欠であり、ハーネスなしでは成立しません。ライフサイクルフック、終了条件の外部管理、品質チェック機構のすべてが自然に設計できます。「エージェントハーネスとは何か」を具体的なコードで示す最良の題材です。

### プロトタイプで実証できたこと
- ハーネスによるドリフト対策: プランナーが 6 段階の終了条件をチェックリストとして外部管理し、AI エージェントが「完了」を自己申告することを防止
- 決定論的バリデーション: 金額の桁数チェック、借方貸方一致、勘定科目コードの有効性など、AI の出力を客観的に検証するゲートの実装
- ナレッジ自動改善ループ: ユーザーの仕訳修正を蓄積し、修正頻度が閾値（3 回）を超えたら改善提案を自動生成する仕組み
- ヒューマン・イン・ザ・ループ: 信頼度スコアに基づくエスカレーション判定と、改善提案の承認フロー
- 3 層アーキテクチャの分離: AI 層（テキスト→構造化データ抽出）、決定論的コード層（税計算・仕訳生成）、ハーネス層（統制・品質管理）が明確に分離

### プロトタイプの起動方法
```bash
cd 2026-04-08/prototype
pnpm install
MOCK_AI=true pnpm run demo
```

### 次のステップ（マネージドサービス化に向けて）
1. 実際の PDF/画像からの OCR 連携（現在はテキスト入力のみ）と、複数フォーマットの請求書に対応するテンプレートエンジンの構築
2. WebUI ダッシュボード（承認フロー・改善提案レビュー・処理状況のリアルタイム可視化）の実装
3. マルチテナント対応とナレッジベースの企業間の匿名共有メカニズム（業界ベストプラクティスの蓄積）

### 学んだこと / 気づき
- ハーネスの「終了条件の外部管理」は、単純なチェックリストでも強力なドリフト対策になる。AI に判断させず、決定論的コードが判定することの重要性が実装を通じて明確になった
- 自己改善ループは「修正の蓄積→閾値超え→提案生成→人間承認」の 4 段階で設計すると、最小限のコードで実現できる
- 請求書処理の 80%は決定論的コードで処理でき、AI が担うのは「テキストからの構造化データ抽出」と「勘定科目の推定」という限定された領域。この切り分けが「AI マネージドサービス」の設計パターンとして汎用的に適用可能
