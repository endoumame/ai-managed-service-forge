# InvoicePilot 設計書

## エレベーターピッチ
InvoicePilot は、請求書の受領から仕訳起票・承認までを AI ハーネスが自動制御し、経理担当者を「手入力作業者」から「承認者」に変える AI マネージドサービスです。

## ターゲットユーザー
- ペルソナ: 中小企業（従業員 50〜500 名）の経理担当者・経理マネージャー
- ペインポイント:
  - 月間 100〜1000 枚の請求書を手動で仕訳入力している
  - 取引先ごとにフォーマットが異なり、目視確認に時間がかかる
  - 入力ミスが発生し、月次決算時に修正作業が発生する
  - 承認フローが属人的で、担当者の不在時にボトルネックとなる
- 現在の解決方法:
  - OCR 付き会計ソフト（freee, マネーフォワード等）を使うが、仕訳の精度が低く結局手動修正
  - Excel で管理している企業も多い
- 提供する価値:
  - 請求書の受領から仕訳起票までの工数を 90%削減
  - 入力ミス率をゼロに近づける（決定論的バリデーション）
  - 承認フローの自動化と監査証跡の確保

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック:
  - `beforeExtraction`: 請求書データの前処理（フォーマット正規化、必須フィールドの存在チェック）
  - `afterExtraction`: AI 抽出結果のバリデーション（金額の桁数チェック、日付フォーマット検証）
  - `beforeJournalEntry`: 仕訳ルールとの整合性チェック（借方貸方一致、勘定科目の有効性）
  - `afterJournalEntry`: 過去データとの差異検出（同一取引先の金額急変警告）
- 終了条件管理:
  - チェックリスト方式で管理（AI の自己申告を許可しない）
  - 必須条件: 全フィールド抽出済み / 金額整合性 OK / 仕訳ルール適合 / 承認者アサイン済み
  - 各条件の判定は決定論的コードが行う
- 品質チェック機構:
  - 抽出精度スコアリング（信頼度が閾値以下なら人間エスカレーション）
  - 仕訳パターンの統計的・異常検知
  - 処理完了後の最終サマリーレビュー
- サブエージェント構成:
  - `ExtractorAgent`: 請求書からの情報抽出に特化
  - `ClassifierAgent`: 勘定科目の分類に特化（将来版）
  - `AnomalyAgent`: 異常検知に特化（将来版）

### AIエージェント層
- 担当タスク（推論アップサイドが大きい部分）:
  - 請求書テキストからの構造化データ抽出（取引先名、日付、金額、品目、税率）
  - 勘定科目の推定（過去の仕訳パターンとナレッジベースに基づく）
  - 異常な請求書のフラグ立て（金額が過去平均の 3 倍以上、未知の取引先等）
- 使用するツール/API:
  - Anthropic Claude API（claude-sonnet-4-20250514）— 構造化データ抽出・分類
  - ナレッジストア参照ツール — 過去の仕訳パターン検索
- ヒューマン・イン・ザ・ループのトリガー条件:
  - AI 信頼度スコアが 80%未満の項目
  - 新規取引先からの初回請求書
  - 金額が過去平均から 20%以上乖離している場合
  - ナレッジベースに該当パターンがない場合

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）:
  - 消費税計算（税率 10%/8%の判定、端数処理）
  - 仕訳フォーマット変換（勘定科目コード、部門コード、摘要の組立）
  - 借方貸方の一致検証
  - 承認ワークフロー制御（金額閾値に応じた承認者ルーティング）
  - 日付・金額のフォーマットバリデーション
  - 重複・請求書検出（請求書番号の完全一致チェック）

### ナレッジ自動改善ループ
1. インプット（ユーザー行動/フィードバック）:
   - 仕訳の手動修正（勘定科目の変更、金額の訂正）
   - 承認/却下のアクション
   - ヒューマン・イン・ザ・ループでの判断結果
2. 矛盾検知メカニズム:
   - 同一取引先×品目で異なる勘定科目が適用された場合にフラグ
   - 修正頻度が閾値（5 回/月）を超えたルールを改善候補に
   - 新しい修正パターンが既存ナレッジと矛盾する場合に警告
3. 承認フロー:
   - 改善提案をキューに蓄積
   - 経理マネージャーが週次で提案をレビュー・承認/却下
   - 承認された提案のみがナレッジベースに反映
4. 反映タイミング:
   - 承認直後にナレッジベースを更新
   - 次回の同一パターン請求書から新ルールを適用

## MVP（プロトタイプ）スコープ
実装する機能は以下の 3 つです。
1. **請求書テキストからの構造化データ抽出 + ハーネスによるバリデーション**
   - AI が請求書テキストから情報抽出 → ハーネスが終了条件チェック → バリデーション
2. **勘定科目推定 + ナレッジベースからの自動改善ループ**
   - 過去パターンに基づく仕訳提案 → ユーザー修正 → ナレッジ蓄積 → 改善提案生成
3. **承認ワークフロー（ヒューマン・イン・ザ・ループ）**
   - 信頼度に基づくエスカレーション → CLI での承認/却下/修正 → 結果のフィードバック

以下の機能は将来版として実装しません。
- 実際の OCR/PDF 解析（テキスト入力で代替）
- 会計ソフトへの連携
- マルチテナント対応
- WebUI/ダッシュボード
- サブエージェント構成（単一エージェントで実装）
