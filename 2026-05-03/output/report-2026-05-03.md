# 新機能パッケージ製品アイデア レポート
日時: 2026-05-03。
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: InvoiceGuard

### エレベーターピッチ
InvoiceGuard は、受領した請求書 PDF を自動で読み取り・仕訳・突合し、ハーネスが品質を保証しながら承認フローまで完結させる AI マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は金額を扱う業務であり、AI の自己過信（「正しく読み取れました」という誤報告）が直接的な金銭損失につながる。このため、ハーネスによる外部バリデーション（借貸バランスチェック、金額突合、異常値検知）の価値が最も明確に訴求できるドメインです。

さらに、処理パイプラインが「抽出→仕訳生成→品質チェック→承認」と段階的であるため、各ステップにライフサイクルフック（before/after）を挟むハーネス設計が自然に成立する。AI の終了条件を AI 自身に判断させず、外部チェックリストで管理するドリフト防止パターンの有効性を強く実証できる。

加えて、人間の仕訳修正がそのまま学習データとなるため、ナレッジの自己改善ループが最もシンプルかつ自然に設計でき、「使うほど賢くなるマネージドサービス」のコンセプトを体現しやすい。

### プロトタイプで実証できたこと
- ハーネスの外部チェックリストによる完了判定（AI の自己申告に依存しない 6 段階チェック）
- ライフサイクルフック（beforeExtraction / afterExtraction / afterJournalEntry）による各ステップの品質保証
- 決定論的コードによる借貸バランスチェック・金額突合（差額 0 円を保証）
- ヒューマン・イン・ザ・ループの自動トリガー（信頼度不足、高額請求、異常値）
- 重複請求書の決定論的検知（同一取引先・金額・請求番号の完全一致）
- ナレッジ改善ループ（人間の修正→改善提案生成→承認待ちステータス）
- AI 層と決定論的コード層の責務分離（AI：テキスト理解・分類、決定論：計算・検証）

### プロトタイプの起動方法
```bash
cd 2026-05-03/prototype
pnpm install
INVOICE_GUARD_MOCK=true npx tsx demo/run.ts
```

### 次のステップ（マネージドサービス化に向けて）
1. 実際の PDF OCR 統合（Claude Vision API または専用 OCR エンジン）と、抽出精度のベンチマーク構築
2. Web UI ダッシュボード（承認フロー画面、改善提案レビュー画面）の実装と Playwright 等による視覚的品質チェック
3. マルチテナント対応・会計ソフト連携 API（freee、マネーフォワード等）の実装と、課金モデルの設計

### 学んだこと / 気づき
- ハーネスの「チェックリストベース完了判定」は請求書処理のような段階的パイプラインと非常に相性が良い。各ステップの通過/失敗がそのまま処理品質の可視化になる
- AI に任せる範囲を「テキスト理解・分類」に限定し、金額計算を一切任せない設計にすることで、ドリフトの影響範囲を効果的に縮小できる
- ナレッジ改善ループの「提案→承認」フローは、マネージドサービスの継続的な価値提供（使うほど精度が上がる）の核心的な仕組みとなる
- 重複検知のような決定論的チェックは、AI が見落としやすい問題を確実にキャッチでき、ハーネスの存在意義を明確に示す
