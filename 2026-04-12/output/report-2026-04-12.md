# 新機能パッケージ製品アイデア レポート
日時: 2026-04-12
ターゲットドメイン: 法務レビュー（契約書）

## 選定アイデア: ContractShield - 契約書リスク自動スクリーニングサービス

### エレベーターピッチ
ContractShield は、契約書をアップロードするだけでリスク条項の自動検出・修正案生成・レビュー進捗管理を一気通貫で提供します。法務レビューの品質と速度を劇的に向上させる AI マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
契約書レビューは「見落とし=法的リスク」という高ダウンサイドの業務です。AI エージェント単体では品質を担保できません。ハーネスによる終了条件の管理、品質チェック、ヒューマン・イン・ザ・ループが不可欠です。ハーネスの価値を最も明確に示せるドメインといえます。さらに、ユーザーのリスク判定修正が自然にナレッジ改善ループに接続されます。「使うほど賢くなる」AI マネージドサービスの本質的価値を体現できます。全 5 評価軸で満点を獲得し、プロトタイプ実現可能性も高いことから選定しました。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（before/after）による全フェーズの品質ゲートの動作
- 終了条件チェックリストによるドリフト防止（高リスク条項の人間レビューが未完了の場合、進捗が 91%で停止）
- AI と決定論的コードの明確な分離（パース・分類・計算は決定論的、リスク判定は AI）
- ナレッジ改善ループの基本フロー（ユーザー修正 → 改善提案 → 承認待ち）
- 8 条項の契約書を正しくパースし、損害賠償条項のリスクを検出、修正案を生成

### プロトタイプの起動方法
```bash
cd 2026-04-12/prototype
pnpm install
DEMO_MODE=mock pnpm demo
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API 統合の本格実装（現在はモックレスポンス）とプロンプトチューニング
2. Web ダッシュボード（Vue.js）の構築 — 契約書アップロード、レビュー結果表示、承認フロー
3. ナレッジ DB の永続化（PostgreSQL）とマルチテナント対応

### 学んだこと / 気づき
- ハーネスの「終了条件の外部管理」は、AI の自己過信によるドリフトを防ぐ上で有効である。チェックリストの 91%停止が、ヒューマン・イン・ザ・ループの設計意図を可視化した
- 決定論的コードと AI の分離は、コードの信頼性だけでなく、デバッグ容易性にも大きく寄与する。パースのバグとリスク判定のバグを独立して追跡できる
- 厳格なリンタールールが、AI 生成コードの品質を決定論的に担保するハーネスとして機能した。これ自体が「コード品質のハーネス」である
- 漢数字→アラビア数字の変換など、日本語の契約書に特有の処理は決定論的コードで十分にカバーできる。AI に任せる必要はない
