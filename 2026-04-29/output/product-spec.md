# InvoiceForge 設計書

## エレベーターピッチ
請求書 PDF を投入するだけで、AI が構造化データを抽出し、ハーネスが数値整合性と仕訳ルールを検証し、承認待ちの仕訳データとして会計ソフトにインポート可能な状態で出力する請求書の自動仕訳マネージドサービスである。

## ターゲットユーザー
- 月に数十から数百枚の請求書を手作業で仕訳しているのがペインポイントである。転記ミス、仕訳科目の迷い、二重計上のリスクが常にある。経理担当者が属人的に知識を持っており、退職時にナレッジが失われる
- 現在の解決方法は Excel 管理と手入力、または高価な OCR ソフトと手動仕訳である。いずれも「確認作業」の工数が大きい
- 提供する価値は請求書処理を「確認・承認だけ」に変えることである。仕訳ナレッジをシステムに蓄積し、属人化を解消する

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフックは以下の通りである
  - `beforeExtraction` は請求書データのフォーマット検証（必須フィールドの存在確認）を行う
  - `afterExtraction` は抽出値の数値整合性チェック（小計 + 消費税 = 合計の検証）を行う
  - `beforeJournalEntry` は仕訳候補の勘定科目マスタ存在チェックを行う
  - `afterJournalEntry` は貸借バランスチェック（借方合計 = 貸方合計）を行う
- 終了条件の管理方法は以下の通りである
  - チェックリスト方式で管理する。AI の自己申告に依存しない
  - 条件は次の 5 つである。全請求書に抽出結果あり、数値不整合ゼロ、全仕訳に科目割当済、貸借差額ゼロ、高リスク案件に承認フラグ付与済
- 品質チェック機構は以下の通りである
  - 抽出の信頼度スコアの計測（閾値以下はヒューマンレビュー送り）を行う
  - 過去の同一取引先の仕訳パターンとの整合性チェックを行う
  - 金額の外れ値検知（同一取引先の過去平均 ±3 シグマ）を行う
- サブエージェント構成は以下の通りである
  - 抽出エージェントは請求書テキストからの構造化データ抽出を担う
  - 仕訳エージェントは抽出データに基づく仕訳候補提案を担う

### AI エージェント層
- 担当タスク（推論アップサイドが大きい部分）は以下の通りである
  - 請求書テキストの構造化データ抽出（取引先名、品目、金額、日付、請求書番号）を行う
  - 取引先名の名寄せ（表記揺れの解決）を行う
  - 仕訳科目の候補提案（過去パターンとコンテキスト理解）を行う
  - 異常パターンの検知と説明生成を行う
- 使用するツールと API は以下の通りである
  - Claude API（claude-sonnet-4-20250514）でテキスト理解・構造化を行う
  - 取引先マスタ検索（内部ツール）を利用する
  - 仕訳パターン DB 参照（内部ツール）を利用する
- ヒューマン・イン・ザ・ループのトリガー条件は以下の通りである
  - 抽出の信頼度スコアが 0.8 未満の場合
  - 新規取引先（マスタに存在しない）の場合
  - 金額が過去平均の 2 倍超の場合
  - 仕訳科目の候補が複数あり確信度が分散している場合

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）は以下の通りである
  - 消費税の計算・検証（税率テーブル参照、端数処理ルール適用）を行う
  - 請求書番号の重複チェック（完全一致検索）を行う
  - 仕訳データのフォーマット変換（CSV/JSON から会計ソフト形式）を行う
  - 勘定科目コードの変換（科目名からコードへのマッピング）を行う
  - 日付のバリデーション・正規化（和暦から西暦への変換含む）を行う
  - 貸借バランスの厳密検証を行う

### ナレッジの自動改善ループ
1. インプット（ユーザー行動やフィードバック）は以下の通りである
   - 仕訳の承認（そのまま採用）、修正承認（科目変更等）、差し戻し
   - 新規取引先の登録情報
   - 手動修正の内容（どの値をどう直したか）
2. 矛盾検知メカニズムは以下の通りである
   - 同一取引先に対する仕訳科目の不一致検出を行う
   - 過去の承認パターンと新しい提案の乖離検出を行う
   - ルールベース判定と AI 提案の矛盾検出を行う
3. 承認フローは以下の通りである
   - 改善提案をバッチで生成する（週次）
   - 提案内容の例として「取引先 X の品目 Y は、過去 10 回中 8 回が科目 Z で承認されています。デフォルトルールとして追加しますか」がある
   - 人間が承認するとルールベースに追加する（次回から AI 推論不要になる）
4. 反映タイミングは以下の通りである
   - 即座反映として取引先マスタの更新がある
   - 週次反映として仕訳ルールの更新提案がある
   - 月次反映として異常検知の閾値の再計算がある

## MVP（プロトタイプ）スコープ
実装する機能は以下の 3 つに絞る。
1. 請求書データ抽出と数値整合性バリデーションである。モック請求書 JSON を入力し、AI が構造化データを抽出し、ハーネスが数値チェックを行う
2. 仕訳候補提案とヒューマン承認フローである。抽出データに基づき AI が仕訳を提案し、信頼度が低いものは人間にレビューを求める（CLI 上の対話）
3. ナレッジの自動改善提案である。承認された仕訳パターンを蓄積し、新規ルール提案を生成する

実装しない機能（将来版）は以下の通りである。
- PDF/画像の OCR 処理（プロトタイプでは JSON 入力）
- 会計ソフトとの API 連携
- マルチテナント対応
- Web UI ダッシュボード
- 銀行明細との消込処理
