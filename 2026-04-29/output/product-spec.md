# InvoiceForge 設計書

## エレベーターピッチ
請求書 PDF を投入するだけで、AI が構造化データを抽出し、ハーネスが数値整合性と仕訳ルールを検証し、承認待ちの仕訳データとして会計ソフトにインポート可能な状態で出力する、請求書自動仕訳マネージドサービス。

## ターゲットユーザー
- **ペインポイント**: 月に数十〜数百枚の請求書を手作業で仕訳している。転記ミス、仕訳科目の迷い、二重計上のリスクが常にある。経理担当者が属人的に知識を持っており、退職時にナレッジが失われる。
- **現在の解決方法**: Excel 管理 + 手入力、または高価な OCR ソフト + 手動仕訳。いずれも「確認作業」の工数が大きい。
- **提供する価値**: 請求書処理を「確認・承認だけ」に変える。仕訳ナレッジをシステムに蓄積し、属人化を解消する。

## システムアーキテクチャ

### ハーネス層
- **ライフサイクルフック**:
  - `beforeExtraction`: 請求書データのフォーマット検証（必須フィールドの存在確認）
  - `afterExtraction`: 抽出値の数値整合性チェック（小計 + 消費税 = 合計の検証）
  - `beforeJournalEntry`: 仕訳候補の勘定科目マスタ存在チェック
  - `afterJournalEntry`: 貸借バランスチェック（借方合計 = 貸方合計）
- **終了条件管理**:
  - チェックリスト方式で管理。AI の自己申告に依存しない
  - 条件: ①全請求書に抽出結果あり ②数値不整合ゼロ ③全仕訳に科目割当済 ④貸借差額ゼロ ⑤高リスク案件に承認フラグ付与済
- **品質チェック機構**:
  - 抽出信頼度スコアの計測（閾値以下はヒューマンレビュー送り）
  - 過去同一取引先の仕訳パターンとの整合性チェック
  - 金額の外れ値検知（同一取引先の過去平均±3σ）
- **サブエージェント構成**:
  - 抽出エージェント: 請求書テキストからの構造化データ抽出
  - 仕訳エージェント: 抽出データに基づく仕訳候補提案

### AIエージェント層
- **担当タスク（推論アップサイドが大きい部分）**:
  - 請求書テキストの構造化データ抽出（取引先名、品目、金額、日付、請求書番号）
  - 取引先名の名寄せ（表記揺れの解決）
  - 仕訳科目の候補提案（過去パターン + コンテキスト理解）
  - 異常パターンの検知と説明生成
- **使用するツール/API**:
  - Claude API（claude-sonnet-4-20250514）: テキスト理解・構造化
  - 取引先マスタ検索（内部ツール）
  - 仕訳パターン DB 参照（内部ツール）
- **ヒューマン・イン・ザ・ループのトリガー条件**:
  - 抽出信頼度スコア < 0.8
  - 新規取引先（マスタに存在しない）
  - 金額が過去平均の 2 倍超
  - 仕訳科目の候補が複数あり確信度が分散

### 決定論的コード層
- **担当処理（ルールベースで確実に実行する部分）**:
  - 消費税の計算・検証（税率テーブル参照、端数処理ルール適用）
  - 請求書番号の重複チェック（完全一致検索）
  - 仕訳データのフォーマット変換（CSV/JSON → 会計ソフト形式）
  - 勘定科目コードの変換（科目名→コードのマッピング）
  - 日付のバリデーション・正規化（和暦→西暦変換含む）
  - 貸借バランスの厳密検証

### ナレッジ自動改善ループ
1. **インプット（ユーザー行動/フィードバック）**:
   - 仕訳の承認（そのまま採用）/ 修正承認（科目変更等）/ 差し戻し
   - 新規取引先の登録情報
   - 手動修正の内容（どの値をどう直したか）
2. **矛盾検知メカニズム**:
   - 同一取引先に対する仕訳科目の不一致検出
   - 過去の承認パターンと新しい提案の乖離検出
   - ルールベース判定と AI 提案の矛盾検出
3. **承認フロー**:
   - 改善提案をバッチで生成（週次）
   - 提案内容:「取引先 X の品目 Y は、過去 10 回中 8 回が科目 Z で承認されています。デフォルトルールとして追加しますか？」
   - 人間が承認→ルールベースに追加（次回から AI 推論不要に）
4. **反映タイミング**:
   - 即座反映: 取引先マスタの更新
   - 週次反映: 仕訳ルールの更新提案
   - 月次反映: 異常検知閾値の再計算

## MVP（プロトタイプ）スコープ
実装する機能（3 つに絞る）:
1. **請求書データ抽出 + 数値整合性バリデーション**: モック請求書 JSON を入力し、AI が構造化データを抽出し、ハーネスが数値チェックを行う
2. **仕訳候補提案 + ヒューマン承認フロー**: 抽出データに基づき AI が仕訳を提案し、信頼度が低いものは人間にレビューを求める（CLI 上の対話）
3. **ナレッジ自動改善提案**: 承認された仕訳パターンを蓄積し、新規ルール提案を生成する

実装しない機能（将来版）:
- PDF/画像の OCR 処理（プロトタイプでは JSON 入力）
- 会計ソフトとの API 連携
- マルチテナント対応
- Web UI ダッシュボード
- 銀行明細との消込処理
