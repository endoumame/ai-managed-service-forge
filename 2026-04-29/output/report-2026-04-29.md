# 新機能パッケージ製品アイデア レポート
日時は 2026-04-29 です。
ターゲットドメインは経理・請求書処理です。

## 選定アイデア: InvoiceForge — 請求書の自動仕訳マネージドサービス

### エレベーターピッチ
請求書を投入するだけで、AI が構造化データを抽出し、ハーネスが数値整合性と仕訳ルールを検証し、承認待ちの仕訳データとして出力する請求書の自動仕訳マネージドサービスです。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は AI 単体では「抽出しました」で終わりますが、金額の 1 円のズレが経理ミスに直結するため、決定論的バリデーションが不可欠です。ハーネスが数値整合性チェック（小計+消費税=合計）、重複した請求書の検出、貸借バランス検証を強制実行することで初めて業務品質が担保されます。さらに、終了条件をチェックリスト方式で外部管理することで、AI の「完了」自己申告によるドリフト問題を防止します。承認された仕訳パターンをナレッジとして蓄積し、次回以降の推定精度を自動改善するループも自然に組み込めます。このように「AI エージェント＋ハーネス＋決定論的コード」の三位一体がもっとも明確に発揮されるドメインとして選定しました。

### プロトタイプで実証できたこと
- ハーネスによる品質ゲートとして、5 件の請求書に対して数値整合性チェック（7 項目/件）を全自動で実行し、全件 PASS を確認しました
- 重複した請求書の検出として、5 件目に意図的に含めた再送請求書（INV-2026-0401）を決定論的チェックで即座にブロックしました
- 三層分離の動作として、AI 層（品目から科目推定）、決定論的層（税計算・重複チェック・貸借検証）、ハーネス層（進捗管理・品質ゲート・ヒューマン承認）が独立して動作しました
- ヒューマン・イン・ザ・ループとして、新規取引先・金額異常時に自動でレビュー要求を発行しました（4 件でフラグが立った）
- 終了条件の外部管理として、チェックリスト方式で「全請求書の抽出完了/数値不整合ゼロ/全仕訳割当済/貸借差額ゼロ/高リスクフラグ済」を管理しました
- ナレッジ蓄積として、承認された仕訳パターンを JSON ファイルに自動保存しました（knowledge/data.json）

### プロトタイプの起動方法
```bash
cd 2026-04-29/prototype
pnpm install
npx tsx demo/run.ts --auto-approve
```

### 次のステップ（マネージドサービス化に向けて）
1. PDF/画像からの OCR 統合として、現在の JSON 入力を PDF アップロードに拡張し、実際の請求書画像を処理可能にします
2. 会計ソフト API 連携として、freee/マネーフォワード等の仕訳インポート API と接続し、エンドツーエンドの自動化を実現します
3. マルチテナント対応とナレッジ共有として、複数企業の匿名化された仕訳パターンを集約し、新規顧客でも高精度な科目推定を可能にします

### 学んだこと / 気づき
- ハーネスの価値は「AI の出力を信頼しない」という設計原則から自然に導出されます。特に金額を扱う経理領域ではこの原則が強く効きます
- 重複検出のような単純なルールベースチェックでも、ハーネスとして組み込むことで大きな価値を生みます（AI 推論は不要）
- 取引先名の名寄せ（「(株)ABC」から「ABC 株式会社」）は AI の推論アップサイドが大きい典型例です。間違えても致命的ではなく、正解すれば大幅な効率化になります
- ナレッジの自動改善ループは「承認/差し戻し」のフィードバックを構造化するだけで自然に成立します。特別な学習基盤は不要です
