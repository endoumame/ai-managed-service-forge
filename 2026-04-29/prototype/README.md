# InvoiceForge — 請求書の自動仕訳マネージドサービス（プロトタイプ）

請求書データを投入すると、AI が構造化データを抽出し、ハーネスが数値整合性と仕訳ルールを検証し、承認待ちの仕訳データとして出力します。

## アーキテクチャ

```
harness/          ← ハーネス層: ライフサイクル管理・品質ゲート・終了条件
  lifecycle.ts       フック定義（before/after extraction, journal entry）
  checker.ts         品質チェック（信頼度・異常検知）
  planner.ts         終了条件のチェックリスト・進捗管理

agent/            ← AI エージェント層: 推論（抽出・仕訳候補提案）
  index.ts           請求書抽出・仕訳生成・異常検知

deterministic/    ← 決定論的コード層: ルールベース処理
  rules.ts           税計算・重複チェック・勘定科目マッピング・貸借検証

knowledge/        ← ナレッジ管理: 学習・改善提案
  store.ts           承認パターンの永続化
  improver.ts        自動改善提案の生成

demo/             ← デモ用エントリポイント
  run.ts             CLI デモ実行
  mock-invoices.json モックデータ（5 件、うち 1 件重複）
```

## セットアップ

```bash
cd 2026-04-29/prototype
pnpm install
```

## デモ実行

### 自動承認モード（非対話）

```bash
npx tsx demo/run.ts --auto-approve
```

### 対話モード（ヒューマン・イン・ザ・ループ）

```bash
npx tsx demo/run.ts
```

各仕訳候補に対して `y/n` で承認/却下を入力します。

## デモで確認できること

1. ハーネスによる品質ゲートとして、数値整合性（小計+税=合計）の自動検証を行う
2. 重複した請求書の検出として、請求書番号ベースの決定論的チェックを行う
3. 仕訳候補の自動提案として、キーワードマッチによる勘定科目推定を行う
4. 貸借バランス検証として、借方合計と貸方合計の厳密チェックを行う
5. ヒューマン・イン・ザ・ループとして、信頼度が低い場合・新規取引先の場合に人間レビューを要求する
6. 終了条件の外部管理として、AI の自己申告ではなくチェックリストで進捗管理を行う
7. ナレッジ蓄積として、承認された仕訳パターンを JSON に永続化する
