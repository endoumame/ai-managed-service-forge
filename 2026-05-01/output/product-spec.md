# InvoiceForge 設計書

## エレベーターピッチ
請求書が届いたら正しい勘定科目で自動仕訳され、人間は承認ボタンを押すだけ——InvoiceForge は「請求書処理の完成品」を AI マネージドサービスとして提供する。

## ターゲットユーザー
- ペインポイント — 経理担当者は毎月大量の請求書を手作業で仕訳しており、単純作業に時間を奪われている。仕訳ミスは決算修正に直結し、心理的な負荷も高い。
- 現在の解決方法 — 会計ソフトの自動仕訳機能（精度が低い）、派遣・パート社員の増員、税理士への外注
- 提供する価値 — 仕訳精度 95% 以上の自動化により、経理担当者は「確認・承認」のみに集中できる。使えば使うほど精度が上がる自己改善ループ付き。

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック
  - `beforeExtract`: 請求書データの入力バリデーション（必須フィールドの存在確認、データ型チェック）
  - `afterExtract`: 抽出結果の完全性チェック（日付・金額・取引先・品目が全て抽出されたか）
  - `beforeClassify`: 過去の同一取引先の仕訳履歴をコンテキストとして注入
  - `afterClassify`: 仕訳の貸借バランスチェック、税率整合性チェック、金額上限チェック
  - `beforeApprove`: 承認前の最終バリデーション（全チェック項目のパス確認）
- 終了条件の管理
  - チェックリスト方式で外部管理（AI に自己申告させない）
  - 条件は次の 5 つ。① 必須項目をすべて抽出済み ② 勘定科目を割当済み ③ 貸借一致 ④ 税率整合 ⑤ 承認キュー投入完了
  - 各条件はハーネスが決定論的に検証
- 品質チェック機構
  - 過去の同一の取引先の仕訳との乖離度チェック（標準偏差を超える場合に警告）
  - 金額の異常値検知（過去 3 ヶ月の平均 ± 2σ）
  - 必須フィールドの欠損検知
- サブエージェント構成
  - ExtractorAgent — 請求書からの情報抽出を担当
  - ClassifierAgent — 勘定科目の分類を担当
  - AnomalyAgent — 異常検知を担当

### AI エージェント層
- 担当タスク（推論のアップサイドが大きい部分）
  - 請求書テキストからの情報抽出（非構造化データ → 構造化データ）
  - 勘定科目の推論（品目名・取引先名・金額レンジからの推定）
  - 異常パターンの検知（重複請求、金額急変、不自然な頻度変更）
- 使用するツール / API
  - Claude API（claude-sonnet-4-20250514）— テキスト理解・分類
  - 構造化出力（JSON mode）— 抽出結果のスキーマ準拠を保証
- ヒューマン・イン・ザ・ループのトリガー条件
  - AI 信頼度が 80% 未満の勘定科目分類
  - 新規取引先からの初回請求書
  - 異常検知アラートが発火した場合
  - 金額が設定された閾値を超える場合

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）
  - 消費税計算（税率 × 税抜金額、端数処理ルール適用）
  - 仕訳テンプレート適用（勘定科目コード → 借方/貸方の仕訳パターン）
  - 貸借バランス検証（借方合計 === 貸方合計）
  - CSV/会計ソフトフォーマット変換
  - 重複チェック（請求書番号 × 取引先 × 金額のユニーク制約）

### ナレッジの自動改善ループ
1. インプット（ユーザー行動 / フィードバック）
   - 人間が仕訳を修正した場合の修正前後のペア
   - 承認/差し戻しの判断
   - 手動で追加された勘定科目マッピング
2. 矛盾検知のメカニズム
   - 同一取引先 × 同一品目に対して異なる勘定科目が割り当てられた場合の検知
   - ルールベースの判定結果と AI 推論の不一致検知
3. 承認フロー
   - 改善提案はキューに蓄積され、経理責任者が一括承認/却下
   - 承認された改善のみがナレッジベースに反映
4. 反映タイミング
   - マッピングテーブルへ即座に反映（次回処理から適用）
   - 信頼度が一定以上のマッピングは「ルールベース昇格」（AI の推論から決定論的コードへ移行）

## MVP（プロトタイプ）スコープ
実装する機能は以下の 3 つに絞る。
1. 請求書テキストからの情報抽出 + 勘定科目推論 — AI が請求書テキストを解析し、構造化データに変換して勘定科目を推論する
2. ハーネスによる外部バリデーション + 承認フロー — 仕訳結果を決定論的にチェックし、人間の承認を待つフローを実装する
3. ナレッジの自動改善ループ — 人間の修正フィードバックからマッピングテーブルを更新し、次回以降の精度を向上させる

以下の機能は将来版とし、今回は実装しない。
- OCR / 画像からの請求書読み取り（プロトタイプではテキスト入力を前提とする）
- 会計ソフト連携（freee、マネーフォワード等の API 連携）
- マルチテナント対応
- ダッシュボード UI（プロトタイプは CLI のみ）
- バッチ処理（プロトタイプは 1 件ずつ処理）
