# アイデア発散: 経理・請求書処理ドメイン

日時: 2026-05-01。

## アイデア 1: InvoiceForge — AI 請求書の自動仕訳マネージドサービス

### ユーザーが本当に欲しいもの（業務の完成品）
「請求書が届いたら、正しい勘定科目で仕訳され、承認待ちキューに入っている状態」。経理担当者は確認・承認するだけで仕訳が完了する。手入力ゼロ、ミスゼロの請求書処理。

### ハーネス設計のキモ
- Before Tool フック — AI が仕訳を生成する前に、請求書の必須項目（日付・金額・取引先・品目）がすべて抽出済みかチェックする
- After Tool フック — 仕訳の生成後に、貸借バランスチェック・税率の整合性チェック・金額の上限チェックを決定論的に実行する
- 終了条件 —「必須項目をすべて抽出済み」「仕訳の貸借一致」「承認キューへの投入完了」の 3 条件をハーネスが外部管理する
- 品質チェック — 過去の同一取引先の仕訳パターンとの乖離検知

### AIが担う部分（推論のアップサイドが大きく、ミスのダウンサイドが小さい部分）
- 請求書テキスト / 画像からの情報抽出（OCR 結果の構造化）
- 勘定科目の推論（過去パターン + 品目名からの推定）
- 異常検知（通常と異なる金額・頻度の請求の検出）

### 決定論的コードが担う部分
- 消費税計算（税率 × 金額の算術演算）
- 仕訳ルール適用（勘定科目コード → 仕訳テンプレートのマッピング）
- 貸借バランスチェック（借方合計 = 貸方合計の検証）
- CSV/会計ソフト向けフォーマット変換

### ナレッジ/データの自動改善ループ
1. 人間が仕訳を修正した場合、修正前後のペアを「学習データ」として蓄積
2. 取引先 × 品目 → 勘定科目のマッピングテーブルが自動更新
3. 一定の件数を蓄積後に、ルールベース判定へ「昇格」（AI の推論から決定論的コードへ移行）

### 内製との差別化ポイント
- 勘定科目推論モデルの精度向上を個社で行うと高コスト（学習データが少ない）
- マネージドサービスなら匿名化された業界横断データで精度が向上し続ける
- 税制改正への対応もサービス側で一括更新

## アイデア 2: ExpenseGuard — AI経費精算コンプライアンスチェッカー

### ユーザーが本当に欲しいもの（業務の完成品）
「経費精算申請が社内規定に準拠しているか自動チェックされ、違反があれば具体的な理由とともに差し戻されている状態」。経理部門はチェック済みの申請だけを最終承認すればよい。

### ハーネス設計のキモ
- Before Tool フック — 経費データの必須フィールド（日付・金額・用途・領収書添付）の存在確認
- After Tool フック — コンプライアンスチェック結果に対して、ルールカバレッジ 100% かを検証（全ルールが評価済みか）
- 終了条件 —「全ルール評価完了」「判定結果の根拠明示」「差し戻し理由を自然言語で生成完了」の 3 条件
- 品質チェック — ルール適用漏れの検知（新しい経費カテゴリに対応するルールが存在するか）

### AIが担う部分
- 領収書画像からの情報抽出
- 用途の自然言語分類（「接待」「交通費」「備品」等）
- 不自然なパターンの検知（金額の端数操作、連続する上限ギリギリ申請）

### 決定論的コードが担う部分
- 社内規定ルールとの照合（上限金額、事前申請要否、承認権限）
- 日当計算・交通費計算
- 重複申請チェック（同一日・同一金額）

### ナレッジ/データの自動改善ループ
1. 人間が「問題なし」と判断した申請のうち、AI が「要注意」と判定したものを偽陽性として記録
2. 逆に見逃した違反を偽陰性として記録
3. しきい値の自動調整とルールの追加提案

### 内製との差別化ポイント
- 社内規定は各社異なるが、チェックロジックの「型」は共通
- 規定変更への追従をマネージドサービスとして提供（規定テンプレートの更新配信）
- 不正パターンのデータベースを業界横断で蓄積

## アイデア 3: ReconcileBot — AI 銀行口座の自動照合サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「銀行口座の入出金明細と社内の売掛金 / 買掛金台帳が自動照合され、一致・不一致・要確認の 3 分類に仕分けられている状態」。月次決算の照合作業が数時間から数分に短縮される。

### ハーネス設計のキモ
- Before Tool フック — 入力データの形式バリデーション（日付フォーマット、金額の数値型確認）
- After Tool フック — 照合結果の網羅性チェック（すべての明細が分類済みか）、金額合計の整合性チェック
- 終了条件 —「全明細の分類完了」「未照合金額の合計表示」「要確認リストの生成完了」
- 品質チェック — 照合率の異常検知（前月比で 10% 以上低下していないか）

### AIが担う部分
- 取引先名の名寄せ（銀行明細の摘要と台帳の取引先名のファジーマッチング）
- 分割支払い・合算支払いの推定
- 不明入金の取引先推定

### 決定論的コードが担う部分
- 金額完全一致の照合
- 日付範囲内の照合（支払期日 ± N 日）
- 差額計算・残高検証

### ナレッジ/データの自動改善ループ
1. 人間が手動照合した結果を「正解データ」として蓄積
2. 取引先の名寄せ辞書が自動拡張（「(株)ABC」=「ABC 株式会社」等）
3. 照合パターンの自動学習（特定取引先は常に月末に 3 分割で支払う等）

### 内製との差別化ポイント
- 銀行フォーマットの多様性への対応を個社で維持するのは非効率
- 名寄せ辞書は業界横断の共有により精度が向上し続ける
- 新規取引先への対応速度がマネージドサービスのほうが速い

## アイデア 4: TaxPrepAI — AI 税務申告の書類準備サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「月次/四半期の税務申告に必要なデータが自動集計・分類され、申告書のドラフトが生成されている状態」。税理士は最終確認と提出だけを行えばよい。

### ハーネス設計のキモ
- Before Tool フック — 入力データの期間の整合性チェック（対象期間のデータがすべて揃っているか）
- After Tool フック — 税額計算の再検証（決定論的コードで独立に計算し、AI の出力と突合する）
- 終了条件 —「全勘定科目の集計完了」「税額の二重計算一致」「申告書フォーマット準拠」
- 品質チェック — 前期との比較による異常値検知

### AIが担う部分
- 取引の税務分類（課税/非課税/免税/不課税の判定が曖昧なケース）
- 税務上の注記事項の自然言語生成
- 税制改正の影響分析

### 決定論的コードが担う部分
- 税額計算（税率 × 課税標準額）
- 各種控除の計算
- 申告書フォーマットへのマッピング

### ナレッジ/データの自動改善ループ
1. 税理士の修正を「税務判断事例」として蓄積
2. 業種別の典型的な税務分類パターンの学習
3. 税制改正情報の自動取り込みとルール更新提案

### 内製との差別化ポイント
- 税制は毎年改正され、追従コストが高い
- 税務判断の事例データベースは個社では蓄積が困難
- 税理士の工数削減効果が大きく、ROI が明確

## アイデア 5: PaymentFlow — AI 支払予定・キャッシュフロー最適化サービス

### ユーザーが本当に欲しいもの（業務の完成品）
「今月の支払予定が自動作成され、キャッシュフローへの影響が可視化され、支払の優先順位の提案がされている状態」。CFO は最適化された支払計画を承認するだけでよい。

### ハーネス設計のキモ
- Before Tool フック — 未処理の請求書の取り込み漏れチェック（受領済み請求書がすべて支払予定に含まれているか）
- After Tool フック — 支払計画の整合性チェック（支払合計が口座残高を超えていないか）
- 終了条件 —「全請求書の支払日の割当完了」「キャッシュフロー予測の生成完了」「承認待ち状態への遷移完了」
- 品質チェック — 支払遅延リスクの検知（支払期日を超過する可能性があるものの警告）

### AIが担う部分
- 支払優先度の判定（取引関係の重要度、遅延ペナルティの有無）
- キャッシュフローのトレンド分析・予測
- 異常な支払パターンの検知

### 決定論的コードが担う部分
- 支払期日の計算（月末締め翌月末払い等のルール適用）
- キャッシュフロー計算（日別の入出金シミュレーション）
- 早期支払割引の計算

### ナレッジ/データの自動改善ループ
1. 実際のキャッシュフローと予測の乖離を記録・分析
2. 季節変動パターンの学習
3. 取引先ごとの支払行動パターン（実際の入金タイミング）の蓄積

### 内製との差別化ポイント
- キャッシュフロー予測は業界横断データがあると精度が約 30% 向上する
- 支払条件の最適化ノウハウを個社で蓄積するのは困難
- 金融市場の変動を考慮した高度な予測は専門性が必要
