# 新機能パッケージ製品アイデア レポート
日時: 2026-04-01
ターゲットドメイン: 経理・請求書処理

## 選定アイデア: InvoiceForge — 請求書自動仕訳・転記サービス

### エレベーターピッチ
受領した請求書を投入するだけで、ハーネスが品質保証した仕訳データが自動生成され、経理担当者は例外承認だけで月次決算を完了できるAIマネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
請求書処理は「AIだけでは不十分だが、ハーネスと組み合わせれば完成品になる」典型例である。AIが仕訳科目を推定しても、金額の算術整合性（税込 = 税抜 + 消費税）は決定論的コードで検証すべきであり、過去パターンとの乖離はハーネスが検知すべきである。このプロトタイプでは、AIの推定信頼度が80%未満の場合や新規取引先の初回処理時に自動的にヒューマン・イン・ザ・ループが発動する設計を実装した。また、チェックリスト形式の終了条件管理により、AIが「もう十分」と自己申告するドリフト問題を構造的に防止している。ナレッジの自動改善ループ（修正フィードバック→パターン蓄積→改善提案）も組み込み、「使うほど賢くなる」マネージドサービスの核心を体現した。

### プロトタイプで実証できたこと
- ハーネスのライフサイクルフック（beforeExtract/afterExtract/afterClassify/beforeOutput）が各処理ステップで品質ゲートとして機能すること
- チェックリスト方式の終了条件管理（7項目すべてがパスしないと処理完了にならない）によるドリフト防止
- AIの推定信頼度に基づくヒューマン・イン・ザ・ループの自動トリガー（信頼度70% < 閾値80%で発動）
- 新規取引先の初回処理時に人間承認を必須とする設計
- ナレッジストアによる仕訳パターンの蓄積と、修正記録からの自動改善提案生成
- 決定論的コードによる金額整合性チェック（消費税計算・明細合計検証）
- 過去パターンとの乖離検知（同一取引先×品目で異なる仕訳科目が推定された場合の警告）

### プロトタイプの起動方法
```bash
cd 2026-04-01/prototype
pnpm install
pnpm run demo
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude APIによる実際のOCR・請求書解析の実装（現在のルールベース模擬を置き換え）
2. Webダッシュボードの構築（承認フロー・ナレッジ管理のUI化）
3. 会計ソフト連携API（freee、マネーフォワード等へのCSV/API出力）
4. マルチテナント対応とナレッジの企業横断学習基盤

### 学んだこと / 気づき
- ハーネスの品質チェックは「AIが間違えたときに気づく」だけでなく「AIの信頼度が低いときに事前にエスカレーションする」予防的な役割も持つ
- 終了条件のチェックリスト方式は実装がシンプルだが、ドリフト防止効果は大きい。7項目のうち1つでも欠けると完了にならない
- ナレッジの自動改善提案は「同じ修正が2回以上発生したら提案」というシンプルなルールでも、運用上の価値は高い
- 決定論的コード（消費税計算・金額検証）とAI推論（仕訳科目推定）の分離は、責務の明確化だけでなくテスタビリティの向上にも寄与する
