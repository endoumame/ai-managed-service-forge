# 新機能パッケージ製品アイデア レポート
日時: 2026-04-30
ターゲットドメイン: 経理・請求書処理。

## 選定アイデア: JournalCraft — AI仕訳起票アシスタント

### エレベーターピッチ
あらゆる取引データから正確な複式簿記の仕訳を自動起票し、経理担当者を「入力作業者」から「判断者」へ変革する AI マネージドサービス。

### なぜこのアイデアを選んだか（ハーネスの価値観点）
仕訳処理は「借方合計 = 貸方合計」という数学的な不変条件を持つため、AI の推論結果を決定論的に検証するハーネスの価値が一目で伝わる。AI が勘定科目を推論し、ハーネスがバランスチェック・マスタ照合・税区分検証を行い、決定論的コードが税計算・採番・承認ルーティングを担当するという三位一体モデルの教科書的な実装が可能です。さらに、承認済み仕訳がナレッジパターンとして蓄積され、次回以降の推論精度が向上するという自己改善ループが自然に組み込める。ドリフト対策としても、終了条件チェックリスト（6 項目のフラグ管理）をハーネスが外部管理することで、AI の「もう十分」という自己申告に依存しない設計を実現した。

### プロトタイプで実証できたこと
- ナレッジ DB に登録済みの取引先（家賃）は 95%確信度で自動承認候補になることを確認
- ナレッジ未登録の取引（タクシー、消耗品、会議費）は AI 推論（キーワードマッチ）で 70%確信度となり、閾値 80%未満のため人間承認フローに回ることを確認
- 全取引で借貸バランスチェックが PASS し、決定論的コード層の正常動作を実証
- ナレッジ自動改善提案（新規パターン：グルメケータリング→会議費）が生成されることを確認
- ハーネスの 6 段階チェックリスト（抽出→仕訳生成→バランス→科目→税→承認）が全取引で完了状態になることを確認

### プロトタイプの起動方法
```bash
cd 2026-04-30/prototype
npm install
npm run demo
```

### 次のステップ（マネージドサービス化に向けて）
1. Claude API との統合（モックからリアル AI 推論への移行）で、未知の取引パターンへの対応力を強化
2. Web ダッシュボード構築による承認 UI とナレッジ管理画面の提供
3. 会計ソフト（freee, マネーフォワード等）との API 連携による仕訳データの自動投入

### 学んだこと / 気づき
- ハーネスのライフサイクルフック設計は、before/after の対称構造よりも「after の検証」に集中する方が MVP として有効
- ナレッジ DB のシードデータ（1 件の登録パターン）だけで、該当取引の確信度が 95%に跳ね上がる効果は、ユーザーへの価値提案として非常に分かりやすい
- 確信度閾値による自動承認/人間承認の振り分けは、ヒューマン・イン・ザ・ループの最もシンプルかつ効果的な実装パターン
- `no-magic-numbers`等の厳格なリンタールールは、ビジネスルール（承認閾値、税率等）を定数化する副次効果があり、マネージドサービスの設定変更の容易性に寄与する
