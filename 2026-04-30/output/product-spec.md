# JournalCraft 設計書

## エレベーターピッチ
あらゆる取引データ（請求書テキスト、銀行明細、レシート情報）から正確な複式簿記の仕訳を自動起票し、経理担当者を「入力作業者」から「判断者」へ変革する AI マネージドサービス。

## ターゲットユーザー
- ペインポイント
  - 月末の仕訳入力作業に膨大な時間を費やしている
  - 新人経理は勘定科目の判断に自信が持てず、ベテランへの確認が頻発
  - 仕訳ミス（科目誤り、税区分ミス、借貸不一致）が月次決算の遅延原因
  - 税制改正のたびに仕訳ルールの見直しが必要
- 現在の解決方法
  - Excel + 手入力で仕訳作成
  - 会計ソフトの仕訳テンプレート（柔軟性が低い）
  - ベテラン経理への属人的な知識依存
- 提供する価値
  - 取引テキストを入力するだけで、正確な仕訳候補が生成される
  - 承認した仕訳がナレッジとして蓄積され、精度が継続的に向上する
  - ベテランの「暗黙知」がシステムに組み込まれ、属人化を解消

## システムアーキテクチャ

### ハーネス層
- ライフサイクルフック
  - `beforeExtract`: 取引データのフォーマット正規化
  - `afterExtract`: 抽出結果の必須フィールド存在チェック
  - `beforeJournalGenerate`: 過去パターンとの類似度チェック（ナレッジ参照）
  - `afterJournalGenerate`: 借方・貸方バランス検証、勘定科目マスタ照合
  - `beforeApproval`: 最終整合性チェック（税区分、期間帰属）
- 終了条件管理
  - チェックリスト方式。各取引に対して以下のフラグ管理
    - [ ] 取引データ抽出完了
    - [ ] 仕訳候補の生成完了
    - [ ] バランスチェックパス
    - [ ] 勘定科目マスタ照合パス
    - [ ] 税区分検証パス
    - [ ] 承認待ちキュー投入 or 承認完了
  - AI に「完了」を自己申告させず、全フラグの充足をハーネスが判定
- 品質チェック機構
  - 借方合計 = 貸方合計の数学的検証（決定論的）
  - 勘定科目コードのマスタ存在チェック（決定論的）
  - 金額の桁数異常検知（統計的閾値）
  - 過去の類似取引との仕訳パターン一致度（AI + ルール）
- サブエージェント構成
  - Extractor エージェント -- 取引テキストから構造化データを抽出
  - ClassifierAgent -- 勘定科目・税区分を推論
  - メインオーケストレーター -- 全体のライフサイクル管理（ハーネス）

### AIエージェント層
- 担当タスク（推論アップサイドが大きい部分）
  - 非構造化テキストからの取引情報抽出（日付、金額、取引先、内容）
  - 勘定科目の推論（摘要テキストの意味理解が必要）
  - 新規パターンの分類（過去に例がない取引の判断）
  - 仕訳根拠の自然言語での説明生成
- 使用するツール/API
  - Anthropic Claude API（claude-sonnet-4-20250514）
  - 構造化出力（JSON mode）
- ヒューマン・イン・ザ・ループのトリガー条件
  - AI の確信度が閾値（80%）未満の場合
  - 新規取引先との初回取引
  - 金額が通常の 3 倍を超える異常値
  - 過去に類似パターンがない取引

### 決定論的コード層
- 担当処理（ルールベースで確実に実行する部分）
  - 借方・貸方バランスの強制（合計不一致なら仕訳を拒否）
  - 消費税計算（税率テーブルによる一意決定）
  - 勘定科目マスタとの照合（存在しないコードの検知）
  - 仕訳番号の採番（連番管理）
  - 承認フロー制御（金額閾値による承認者決定ルール）
  - 会計期間の判定（取引日から会計期間への変換）

### ナレッジ自動改善ループ
1. インプット（ユーザー行動/フィードバック）
   - 承認された仕訳（正例としてパターン DB 登録）
   - 修正された仕訳（AI の推論誤りとして学習データ化）
   - 却下された仕訳（ネガティブフィードバック）
2. 矛盾検知メカニズム
   - 同一取引先・同一内容で異なる勘定科目が使われている場合に検知
   - 過去の修正パターンと新規推論の矛盾検知
3. 承認フロー
   - 新規パターンの追加 → 自動提案 → 経理責任者の承認で確定
   - 矛盾検知時 → 両方のパターンを提示し、正しい方を選択
4. 反映タイミング
   - 承認済みパターンは即時反映
   - 統計的な改善（確信度閾値の調整等）は月次バッチで反映

## MVP（プロトタイプ）スコープ
実装する機能は以下の 3 つです。
1. 取引テキスト → 仕訳候補の生成 -- テキスト入力から借方・貸方の仕訳候補を AI で生成し、決定論的にバランス検証
2. ナレッジベースの学習ループ -- 承認済み仕訳のパターン蓄積と、次回推論時の類似パターン参照
3. ヒューマン・イン・ザ・ループ承認フロー -- CLI 上での仕訳確認・修正・承認インターフェース

将来版で実装する機能は以下のとおりです。
- 会計ソフトとの API 連携
- PDF/画像からの OCR 取り込み
- 複数通貨対応
- 部門・プロジェクトコードの自動付与
- Web ダッシュボード
- 複数ユーザー・権限管理
- バッチ処理（大量請求書の一括処理）
